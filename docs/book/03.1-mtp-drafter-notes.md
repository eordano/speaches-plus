# The gemma-4-E4B assistant drafter contract

`google/gemma-4-E4B-it-qat-q4_0-unquantized-assistant` (apache-2.0) is the
official Google MTP drafter for E4B speculative decoding, implemented by
`nv-specdecode::gemma4_assistant` and `nv-models::gemma4_assistant_wgpu`. This
page is the upstream contract those must match, recovered from the safetensors
header and the transformers reference (`modeling_gemma4_assistant.py`,
`modeling_gemma4.py`, `Gemma4SharedKVAssistedCandidateGenerator`) — none of it
is recoverable from our tree, and the distribution ships the generic Gemma 4
model card, which is why it is written down here.

**The checkpoint is optional and its absence is silent.**
`default_assistant_dir` (`chat_engine_wgpu/learned.rs`) returns `None` when the
HF cache holds no assistant snapshot, and the serving path falls through to the
checkpoint-free **suffix automaton**, which drafts rarely on free-form prose. A
box showing near-1.0 acceptance and almost no drafted rounds is usually a box
with no drafter, not a broken drafter. **Check for the snapshot before reading
an acceptance number as a property of the code.**

## config.json

Top level: architectures `["Gemma4AssistantForCausalLM"]`, model_type
`gemma4_assistant`, backbone_hidden_size 2560 (= E4B hidden), num_centroids
2048, centroid_intermediate_top_k 32, use_ordered_embeddings true,
tie_word_embeddings true, dtype bfloat16, eos_token_id [1, 106]
(generation_config adds 50).

`text_config` (the inner `gemma4_text` 4-layer trunk): hidden_size 256,
intermediate_size 2048, num_hidden_layers 4, num_attention_heads 4,
num_key_value_heads 2, num_global_key_value_heads null, head_dim 256 (sliding),
global_head_dim 512 (full attention), **num_kv_shared_layers 4** (==
num_hidden_layers, so *every* layer is KV-shared and Q-only), attention_k_eq_v
false (irrelevant — the drafter never computes K/V), layer_types
`[sliding, sliding, sliding, full]`, sliding_window 512, hidden_activation
gelu_pytorch_tanh, rms_norm_eps 1e-6, vocab_size 262144,
max_position_embeddings 131072, hidden_size_per_layer_input 0 (no PLE),
enable_moe_block false. Rope: sliding is default with theta 10000; full is
proportional with theta 1e6, partial_rotary_factor 0.25 and
head_dim_key=global_head_dim.

`backbone_hidden_size` is the compatibility check: `AssistantSpecDrafter::load`
asserts it equals the target's `hidden_size`, so this drafter serves E4B (2560)
and no larger Gemma-4.

## Tensor inventory

All BF16 unless noted; 78,779,908 params. This is the `qat-q4_0-unquantized`
extraction — plain bf16, no quant tensors, nothing to dequantize.

| tensor | shape |
|---|---|
| `masked_embedding.centroids.weight` | [2048, 256] |
| `masked_embedding.token_ordering` | [262144] (I64) |
| `model.embed_tokens.weight` | [262144, 256] (tied; used **only** as lm_head) |
| `model.norm.weight` | [256] |
| `pre_projection.weight` | [256, 5120] |
| `post_projection.weight` | [2560, 256] |

Per layer `i`, with `H` = 256 for the sliding layers 0-2 and 512 for the
full-attention layer 3:

| tensor | shape |
|---|---|
| `model.layers.i.self_attn.q_proj.weight` | [4*H, 256] (4 heads x H) |
| `model.layers.i.self_attn.q_norm.weight` | [H] (per-head RMS over head_dim) |
| `model.layers.i.self_attn.o_proj.weight` | [256, 4*H] |
| `model.layers.i.{input,post_attention,pre_feedforward,post_feedforward}_layernorm.weight` | [256] |
| `model.layers.i.mlp.{gate,up}_proj.weight` | [2048, 256] |
| `model.layers.i.mlp.down_proj.weight` | [256, 2048] |
| `model.layers.i.layer_scalar` | [1] |

There are **no** `k_proj` / `v_proj` / `k_norm` / `v_norm` tensors anywhere:
with `num_kv_shared_layers == num_hidden_layers`, every drafter layer reuses the
backbone's `shared_kv_states[layer_type]` verbatim.

## What the backbone must export, per draft step (q_len = 1)

1. `last_hidden_state` of the **final decoder layer** — HF records decoder layer
   outputs, i.e. **pre-final-norm**, shape `[B, seq, 2560]`; only the row of the
   last committed token is used, and the E4B side must export exactly that row,
   not the post-norm hidden.
2. `shared_kv_states: {layer_type -> (K, V)}` — the **full-length** K/V of the
   *last non-KV-shared layer of each layer type* in the backbone
   (`store_full_length_kv` in `Gemma4TextAttention`; K already k_norm-ed and
   roped, V already v_norm-ed, shape `[B, n_kv, kv_len, head_dim]`). For E4B,
   sliding K/V have head_dim 256 with 2 kv heads and full-attention K/V head_dim
   512; E4B's own `num_kv_shared_layers` is 18.
3. `position_ids = current_length - 1`, **held constant** for all k drafted
   steps — set once before the drafting loop and never incremented.

On token-level rollback after partial acceptance, truncate `shared_kv_states`
along kv_len to the committed length and pick `last_hidden_state` at the
matching row.

## Forward pass

```
x = pre_projection(inputs_embeds)            # [B,1,5120] -> [B,1,256], no embed scaling
h = gemma4_text_trunk(x, shared_kv_states)   # 4 layers + final norm
last_hidden_out = post_projection(h)         # [B,1,256] -> [B,1,2560], fed back as step input
logits = masked_embedding(h, lm_head.weight) # ordered-embedding head
next_token = argmax(logits)
```

`inputs_embeds = concat(target_embed_tokens(last_token), last_hidden)`, shape
`[B, 1, 5120]`. The token embedding comes from the **backbone's** scaled
embedding table (`Gemma4TextScaledWordEmbedding`: raw row x sqrt(2560)); the
drafter checkpoint contains no 2560-dim table.

Trunk layer (sandwich norms):

```
resid = x
h = input_layernorm(x)                       # plain-weight RMSNorm (weight init 1.0, NOT 1+w)
attn = o_proj( attention(h) )
h = post_attention_layernorm(attn)
x = resid + h
resid = x
h = pre_feedforward_layernorm(x)
h = down_proj( gelu_tanh(gate_proj(h)) * up_proj(h) )
h = post_feedforward_layernorm(h)
x = resid + h
x = x * layer_scalar                         # learned scalar, multiplies the WHOLE hidden state
```

Attention is Q-only:

```
q = q_proj(h).view(1, n_heads, head_dim)     # head_dim 256 (sliding) / 512 (full)
q = q_norm(q)                                # RMSNorm over head_dim, per head
q = rope(q, position)
K, V = shared_kv_states[layer_type]          # straight from the backbone; no projection
attn = softmax(q @ K^T * 1.0) @ V            # scaling == 1.0 (NOT 1/sqrt(d)); GQA 4q:2kv
out = o_proj(attn.reshape(1, n_heads*head_dim))
```

- **The softmax scale is literally `1.0`** (`self.scaling = 1.0`); q_norm takes
  the role of scale control. Substituting `1/sqrt(d)` is the easy way to get a
  drafter that runs and never accepts.
- Masks: `q_len == 1` makes causality moot and the wrapper builds bidirectional
  masks, so the effective rule for a single query at the sequence end is that
  the full-attention layer attends to **all** kv_len positions and sliding
  layers attend to the **last min(512, kv_len)** positions.
- RoPE sliding: default rope, theta 10000, full 256-dim rotation (128 freqs,
  `inv_freq = theta^(-2i/256)`). RoPE full attention: "proportional" rope, theta
  1e6, `partial_rotary_factor 0.25` over `global_head_dim` 512, so
  `rope_angles = 0.25*512/2 = 64` real frequencies
  `inv_freq[i] = 1e6^(-2i/512), i<64`, then **192 zero frequencies** (identity
  on those dims); cos/sin are `cat(freqs, freqs)` (length 512), applied
  rotate-half style over the full 512 head dim, `attention_scaling = 1.0`.

## Output head (`use_ordered_embeddings`)

The vocab (262144) is partitioned into 2048 clusters x 128 tokens.

```
centroid_logits = centroids(h)                       # [.., 2048] = h @ centroids.weight^T
top32 = topk(centroid_logits, k=32).indices
ids_per_cluster = token_ordering.view(2048, 128)     # token_ordering[c*128+j] = vocab id of
                                                     # member j of cluster c
cand_ids = ids_per_cluster[top32].flatten()          # 32*128 = 4096 token ids
cand_logits = h @ lm_head.weight[cand_ids]^T         # [.., 4096]
logits = full(fill) scattered with cand_logits at cand_ids
```

Greedy drafting therefore needs only an argmax over the 4096 candidate dot
products and a map back through `cand_ids`. `lm_head.weight` is
`model.embed_tokens.weight`, tied. HF's fill value is `min(cand_logits) - 1.0`,
not `-inf`; that only matters for sampling.

## Drafting loop

```
last_hidden = backbone_hidden_states[-1][:, n_last_matches : n_last_matches+1]  # 2560
last_token  = committed_ids[:, -1:]
pos         = len(committed_ids) - 1          # constant across the loop
for _ in range(k):
    e = backbone_embed(last_token)            # scaled, 2560
    tok_logits, h2560 = drafter(concat([e, last_hidden]), pos, shared_kv_states)
    last_token  = argmax(tok_logits)
    last_hidden = h2560
    stop early on eos {1, 106, 50}
```

Verification is one batched backbone forward over `committed + drafted` — the
standard Leviathan greedy accept, which the chain verifiers already implement.

## Three properties to preserve, and why they look wrong

- **Constant `position_ids` during drafting** is faithful to HF: every drafted
  query claims the same rope position. It smells like an upstream
  simplification; mirror it. Incrementing per step is a one-line change in
  `propose` and is the first thing to try if acceptance is poor — but it is a
  deviation from the reference, not a fix.
- **Shared KV is frozen during the k-step draft loop.** Drafted tokens append KV
  nowhere, because the drafter has no K/V projections at all; it sees drafted
  history only through the recurrent `post_projection` hidden state.
- **The sliding shared KV must be full length.** The backbone's own sliding
  cache may be window-truncated; HF keeps a separate full-length copy at the
  `store_full_length_kv` layer. A cache holding only the trailing 512 sliding
  positions is still sufficient (the drafter's window is also 512) *provided*
  kv-position alignment is preserved for the trailing-window mask.
