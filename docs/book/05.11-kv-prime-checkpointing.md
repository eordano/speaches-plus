# KV-prime checkpointing: deep-context primes are one-time and kill-resumable (cuda)

Deep-depth measurement on the cuda qwen3.8 dense arm pays a full prefill (or
synthetic fill) to reach its depth. This layer writes the primed cache state to
disk and restores it on the next run at the same key, so a kill loses minutes of
priming exactly once. It is a test-harness facility
(`rust/crates/nv-models/tests/prime_ckpt_common/mod.rs` plus
`Qwen3MoeKvCache::dump_primed_state_for_reuse` / `restore_primed_state_checked`
in `nv-models/src/qwen3_5_moe.rs`), not a serving feature; the wgpu serving analog
is `05.10-kv-disk-persistence.md`.

## What a checkpoint holds, and how it refuses

Everything a primed `Qwen3MoeKvCache` needs to decode as if the prefill had just
run: per-full-attention-slot fp8 KV rows and their f32 scales up to `current_len`,
every GDN `LinAttnState` (BF16 conv state + F32 recurrent state), and
`current_len` itself. The file is magic `NVPRIMEK`, the layout version
(`PRIME_CKPT_CACHE_LAYOUT_VERSION_1_BUMP_WHEN_FP8_ROW_SCALE_OR_LIN_STATE_LAYOUT_CHANGES`),
the fingerprint string, geometry, then raw little-endian payload.

**The file name is the fingerprint:**
`q38-cfg<fnv1a64-of-config.json>-L<layers>-kv<n_kv>x<head_dim>-d<depth>-<fillmode>-layout<N>.bin`.
Fill mode distinguishes real chunked prefill (`realchunk512v1`) from the synthetic
depth-timing fill (`synthfill512v1`); **the two are never interchangeable.** Any
mismatch — magic, layout version, fingerprint, geometry, depth beyond the cache —
refuses with a named constant (`PRIME_CKPT_BAD_HEADER`,
`PRIME_CKPT_FINGERPRINT_MISMATCH`, `PRIME_CKPT_GEOMETRY_MISMATCH`); there is no
migration path. The restore-or-prime helper treats a refused restore as a cache
miss: it reprimes and rewrites.

## Knob, location, concurrency, disk

- `NV_KV_CKPT_DIR` — checkpoint directory; unset (the default) disables the
  subsystem, so ladder defaults never change. Point it at a directory on real
  disk (e.g. `$HOME/tmp/kv-ckpt`), never `/tmp` (tmpfs) and never the
  source tree.
- Writes go through a per-fingerprint blocking `flock` and a pid-named `.tmp`
  renamed into place, so concurrent lanes serialize and a kill never leaves a torn
  file.
- Before writing, the dump checks `statvfs` free space against the expected file
  size plus a 2 GiB margin and refuses with `PrimeCkptDiskTight` if short; the
  restore-or-prime helper downgrades that refusal to "prime kept, checkpoint
  skipped" **so a tight disk costs the cache, not the run.**

## Expected sizes (qwen3.8-27B: 16 full-attention slots, 4 kv heads, hd 256)

KV + scales cost `full_attn_slots * 2 * (n_kv*head_dim + 4*n_kv)` bytes per token
— 33,280 B/token here — plus a depth-independent ~154 MiB for the 48 GDN states on
a real prime (synthetic fills carry none): 8k depth is 0.25 GiB synthetic /
0.40 GiB real, 32k is 1.02 / 1.16, 196k is 6.22 / 6.37. The size model in
`expected_ckpt_file_bytes_fp8_kv_rows_scales_plus_lin_state_slack` bounds the real
file from above (256 MiB slack covers GDN states and header); the gate asserts
that bound so the headroom refusal stays honest.

## Gates

The suite covering restore parity and kill-resume is
`qwen38_prime_ckpt.rs::qwen38_prime_ckpt_restore_matches_fresh_prime_argmax_32_tokens_and_beats_repriming`
(`#[ignore]`, `NV_QWEN38_SERVING_TEST=1`): real chunked prefill to depth, dump (or
adopt a prior process's file under the same fingerprint — **that is the
cross-process kill-resume proof**), then a 32-token greedy ladder from the
restored cache must match the fresh-prime ladder argmax-exact, step-0 logits
inside the corruption bar, decode ms/tok inside the 2x band, and restore faster
than re-priming. The depth-timing ladder (`qwen38_serving_ctx.rs`, eager arm)
consumes the same store through `restore_or_prime_then_dump_holding_the_flock` and
labels each depth's `prime_source`.
