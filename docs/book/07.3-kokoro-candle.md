# 7.3 Kokoro in candle -- the speaches-native path to adapted voices

Status: in progress, started 2026-09-10. Goal: run Kokoro-82M inside the Rust
engine on candle instead of ONNX, so the decoder-adaptation tier of
[7.2](07.2-voices.md) trains with candle autograd (`nv-train` style) against the
candle speaker encoders, with no torch anywhere in the fleet.

## What Kokoro is (v1.0, `hexgrad/Kokoro-82M`)

StyleTTS2 decoder-only plus iSTFTNet, 82 M parameters, conditioned on a 256-d
style vector `ref_s` = [decoder style (128) | prosody style (128)]:

| part | torch module | shape notes |
|---|---|---|
| `bert` | ALBERT (PLBERT): emb 128, hidden 768, 12 heads, ffn 2048, 12 shared layers, 178 tokens, 512 positions | one layer's weights reused 12 times |
| `bert_encoder` | Linear 768 -> 512 | |
| `predictor.text_encoder` | DurationEncoder: 3 x [BiLSTM(640 -> 2x256), AdaLayerNorm(128 -> 512)] with the style concatenated at every layer | |
| `predictor.lstm`, `duration_proj` | BiLSTM(640 -> 2x256), Linear 512 -> 50; duration = sum(sigmoid) / speed, rounded, min 1 | alignment matrix from durations (non-differentiable) |
| `predictor.shared`, `F0`, `N`, `F0_proj`, `N_proj` | BiLSTM(640 -> 2x256); 3 AdainResBlk1d each (512, 512 -> 256 upsample x2, 256), Conv1d 256 -> 1 | F0/N at 2x the text frame rate |
| `text_encoder` | Embedding 178 x 512, 3 x [Conv1d k5 (weight_norm), LayerNorm, LeakyReLU 0.2], BiLSTM(512 -> 2x256) | |
| `decoder` | AdainResBlk1d encode (514 -> 1024), decode x4 (1090 -> 1024, 1024, 1024, 512 upsample), F0/N Conv1d k3 s2, asr_res Conv1d 512 -> 64 | AdaIN = InstanceNorm1d(affine) modulated by `fc(style)`; these `fc` layers are the adaptation tier's parameters (116 tensors, 4.8 M) |
| `decoder.generator` | iSTFTNet: harmonic source (SineGen, 8 harmonics, upsample 300, Linear 9 -> 1, tanh), noise convs + AdaINResBlock1 per stage, ConvTranspose1d ups [10, 6] k [20, 12], 3 AdaINResBlock1 (Snake activation) per stage with k [3, 7, 11], conv_post -> 22 channels, iSTFT n_fft 20 hop 5 | iSTFT as DFT-matrix conv_transpose (the `CustomSTFT` variant the ONNX export uses) |

Randomness: SineGen adds a random initial phase and Gaussian noise; the
generator adds noise to the source. Parity against torch or ONNX is therefore
exact up to the decoder's input (`dec_pre_gen`) and statistical after it.

## Plan and gates

Weights: `kokoro-v1_0.pth` -> `kokoro-v1_0.safetensors` with torch names and
`weight_norm` folded (`weight = g * v / ||v||`), 327 MB f32, converted once by
`python/tts/kokoro/convert_checkpoint.py`; with `--ref` the same script dumps every
intermediate of one sentence (the fitted reference style) to a safetensors file the
`cargo test -p nv-tts kokoro` gates read via `KOKORO_SAFETENSORS` / `KOKORO_REF`.

## Serving and fitting in the engine

`nv_tts::kokoro::KokoroCandle` is the engine's handle: the candle front end
behind a mutex, the base AdaIN weights kept aside, and the two encoders loaded
lazily for fits. The engine builds it when `KOKORO_CANDLE_WEIGHTS` names the
converted safetensors; `NV_QWEN_VOICE_ENCODER_DIR` (the standalone Qwen ECAPA
encoder) and `NV_WESPEAKER_CANDLE_DIR` (`graph.json` + `weights.safetensors`
from `onnx_export_graph.py`) are needed only for the adapter tier of
`/v1/voices/fit`. The device is CUDA 0 when the build has it, else CPU.

- A `kokoro-adapter` store voice is read as a map of AdaIN tensors
  (`adapter.safetensors`, else `adapter.npz` with the ONNX initializer names)
  and synthesized by swapping those tensors in for the request and restoring the
  base afterwards, so one model serves every adapted voice with no per-voice
  memory. Without `KOKORO_CANDLE_WEIGHTS` the engine falls back to the per-voice
  ORT session of chapter 7.2; both paths read the same voice directory.
- `POST /v1/voices/fit` with `tier: "adapter"` runs the style-tier evolution
  first, then `KokoroCandle::fit_adapter` on that style: `epochs` (default 12),
  `patience` and `min_delta` bound the training, the request's sentences are the
  validation set, and `tts::fit::TRAIN_SENTENCES` supply disjoint training
  sentences for every request. The job writes `pack.npy`, `adapter.safetensors`,
  `adapter.npz` and candle-rendered samples, and stores the epoch history in
  `voice.json` under `eval`. The SSE stream reports `train` events per epoch and
  a `stop` event with the early-stopping reason.
- Test: `serve_handle_swaps_adapters_and_restores_base` (base vs restored
  waveform identical, base vs adapted differing) beside the parity gates.

Stage 5b gate (2 epochs, one training sentence, CPU, 52 s): held-out WeSpeaker
0.6985 -> 0.7122 with the L2 anchor at 1.0; a fresh model with the stored
weights applied scores 0.7120, so the served form is the trained form. Two
candle facts the trainer works around: `Var::set` refuses a tensor sharing its
storage (checkpoints are `copy()`d), and `conv2d`'s backward hands the input
gradient back through `conv_transpose2d`, whose extent falls short of the input
by the rows a strided forward discards; the executor zero-pads the input up to
the next stride multiple, runs the strided conv, and narrows the output to the
ONNX size (`A_STRIDED_CONV_BACKPROPAGATES_ONLY_WHEN_THE_TRANSPOSE_REPRODUCES_THE_INPUT_EXTENT`;
`strided_tests` holds bit parity with the plain route and the gradient shape at
49, 50 and 63 frames).

Memory under autograd is governed by four rules, each named at its site and
none changing a score: `OnnxGraph::run` drops an activation after its last
consumer and reads weights in place, so ResNet293's 710 node outputs never
accumulate; the adapter tier validates on detached copies of the AdaIN weights
(`VALIDATION_SWAPS_IN_DETACHED_ADAIN_WEIGHTS...`), so a held-out sentence
records no tape; `TrainConfig::window_frames` crops `asr`, `f0` and `n` to the
first N decoder frames (300 samples each) before the decoder and generator run,
so the generator tape, about 1.2 GiB per second of audio, scales with the window
(`A_TRAINING_WINDOW_CROPS_THE_DECODER_INPUT...`); and `wmix` at exactly 0 or 1
skips the unused encoder's tape (ResNet293 alone holds about 0.6 GiB per second).
The engine's `/v1/voices/fit` keeps the full-sentence, two-encoder defaults; the
browser tier below sets a window and a single encoder. One adapter step on a
2.1 s sentence peaks at 3.5 GiB of host memory with a one-second window and
WeSpeaker out of the loss, against 5.3 GiB before these rules.

Stage 5b (2026-09-10): WeSpeaker ResNet293 runs on candle through a small ONNX
executor (`kokoro::onnx_exec`, fed by `python/diarization/onnx_export_graph.py`,
which walks the protobuf with the stdlib) with a differentiable kaldi fbank
(`kokoro::fbank`): embedding 1.5e-6 from onnxruntime, cosine 1.000000. That
gives the two-encoder loss natively; `kokoro::train::adapt` is the adaptation
tier on candle (AdamW on the 116 AdaIN tensors, L2 anchor, best checkpoint by
held-out WeSpeaker, patience/budget stop), and `apply_adain` is how a stored
adapter is served: the same weights, keyed by the ONNX initializer names the
Rust store already uses, so `adapter.npz` files fit both the ORT and the candle
serving paths.

Stage 5 landed 2026-09-10: the graph is differentiable end to end. candle has no
backward for its native `conv_transpose1d`, so `layers::ConvT1d` runs every
transposed convolution (the AdainResBlk1d pool, the two generator upsamplers, the
iSTFT synthesis) through an equivalent stride-1 conv1d over a zero-stuffed,
zero-padded input with the flipped, group-transposed kernel whenever the
`differentiable` switch is on (unit-tested equal to the native op); nearest x2
upsampling is a repeat. `KokoroFrontEnd::make_adain_trainable` swaps the 116
decoder + generator AdaIN projections for `Var`s. `melspec::LogMel24k` is the
speaker-encoder front end in candle (index_select framing, DFT matmul, slaney
mel; 5e-3 of the CPU reference), `load_speaker_encoder` reads the standalone
Qwen encoder. Gate: three AdamW steps on the loss `1 - cos(enc(mel(audio)),
target)` move it 0.021 -> 0.0136 -> 0.0094 on the CPU in 35 s with a non-zero
gradient norm at every step.

Stages 1-4 landed 2026-09-10: the whole forward pass is in candle. Generator
gate on the noise-free reference: waveform relative L2 error 7.6e-5, max abs
1.2e-4; harmonic source 8e-4. Two lessons for the gates: the STFT phase of a
bin whose imaginary part is rounding noise on a negative real is +pi or -pi at
random in torch too, so the source spectrogram is compared as a complex value
(magnitude times cos/sin), not as an angle; and the sine source accumulates
thousands of radians of phase in f32, so its magnitude bins agree to 6e-3, not
1e-5.

Stage 1 detail: max abs diff vs torch 2e-5 (bert), 4e-5 (d_en),
3e-5 (d), 1.5e-4 (duration logits), 2e-6 (t_en); 96/96 durations identical.

Stages, each a commit with a `cargo test -p nv-tts` gate against the dump:

1. **Front end**: ALBERT, `bert_encoder`, `text_encoder`, DurationEncoder,
   duration LSTM/proj. Gate: `d`, `duration_logits`, `pred_dur`, `t_en` match to
   1e-4 (LSTM sums in f32; tolerance measured, not assumed).
2. **Prosody**: alignment matrix from durations, `shared` LSTM, F0/N blocks
   (AdainResBlk1d with the ConvTranspose1d pool). Gate: `en`, `F0_pred`,
   `N_pred`, `asr`.
3. **Decoder**: F0/N conv, encode/decode blocks. Gate: `dec_encode`,
   `dec_pre_gen`.
4. **Generator**: source module, noise path, upsampling stages, Snake
   resblocks, iSTFT. Gate: mel-spectral distance to the torch audio under the
   noise floor, WeSpeaker cosine between candle and torch output >= 0.98.
5. **Autograd**: AdaIN `fc` weights as `Var`s, everything else detached;
   `candle_nn::AdamW`; the two-encoder loss with `nv-tts::SpeakerEncoder`
   (Qwen ECAPA, already candle) and a candle port of WeSpeaker ResNet293 with a
   differentiable kaldi fbank. Gate: one adaptation epoch on the reference speaker's clips
   moves the held-out WeSpeaker score the way the torch run did (0.59 -> >= 0.65
   after one epoch).
6. **Serve**: adapted voices served by the candle model from the store
   (`adapter.npz` deltas applied to the `fc` weights), replacing the per-voice
   ONNX session; `tts::fit` gets `tier: adapter`. Shipped as described above;
   the remaining gate is an adapter fit through a running engine on a GPU host.

## candle notes (0.11)

BiLSTM = two `candle_nn::lstm` with `Direction::Forward/Backward` on the same
`VarBuilder` prefix (`weight_ih_l0` / `weight_ih_l0_reverse`), outputs
concatenated. `conv_transpose1d` supports groups (the AdainResBlk1d pool is
depthwise). InstanceNorm1d is mean/var over time per channel with affine.
Reflection padding and linear interpolation are written by hand; `atan2` for
the harmonic STFT phase runs on the CPU side of the source module, which is
under `no_grad` in torch as well. Dropout is inference-only and dropped.
