# Rust idioms: one way per concept across the workspace

The tree carries no comments, so the conventions that keep nineteen crates
reading as one codebase live here. Each rule names the symbol or file that
carries it; a deviation is a defect to fix, not a style to tolerate.

## 1. Errors

- Every fallible function returns `anyhow::Result<T>` and propagates with `?`.
  A message that adds information goes through `.context("...")` or
  `.with_context(|| format!(...))`, never through
  `.map_err(|e| anyhow!("prefix: {e}"))`. A source that already implements
  `std::error::Error + Send + Sync + 'static` is propagated by bare `?`.
- A typed error enum exists only where a caller matches on the variant:
  `nv_ocr::Error` (thiserror, the OCR pipeline's one public failure surface),
  `nv_kernels::wgpu_backend::WgpuError` (hand-rolled `Display`, because the
  crate builds without thiserror; `wgpu_backend::Result<T>` is the workspace's
  only `Result` alias and stays inside that module), and
  `nv_layers::backend::BackendError` (the backend-selection verdict the server
  renders to the client). Nothing else defines an error type or a `Result`
  alias.
- Error text is API: a message a test or a doc quotes does not change when the
  code around it is refactored.

## 2. Environment knobs

- A boolean knob is read through `nv_config`'s `env_arm_*` family, never by an
  inline `std::env::var(..).ok().as_deref() == Some("1")`. The four truth tables
  are `opt_in_eq_some_1`, `opt_out_default_on_unless_eq_some_0`,
  `present_at_all` and `opt_in_set_to_anything_but_0`; each exists as a
  `_reread_every_call` function and a `_cached_first_read_wins!` macro. A knob
  on a per-token path uses the cached macro; a knob a test flips at runtime
  uses the reread function.
- A value-bearing knob (`NV_FOO=<n>`, a path, a mode word) reads
  `std::env::var` once, parses, and names the default in the binding
  (`let rows = env_usize("NV_X_ROWS").unwrap_or(ROWS_DEFAULT)`); the raw read
  never appears twice for the same variable.
- A real-weight test gates on `NV_<FAMILY>_TEST=1` with the same helper and
  returns early printing `skip`, so an empty run is visible in the log.
- A default flips in place: the superseded path and the env var that would
  restore it leave in the same commit (the bitwise-or-instrument law in
  `AGENTS.md`).

## 3. Device and dtype dispatch

- A boolean backend question is `device.is_cuda()`, `device.is_metal()` or
  `device.is_cpu()` (candle's own predicates), never
  `matches!(device, Device::Cuda(_))`.
- A `match device { Device::Cuda(dev) => ... }` appears only when the arm binds
  the inner handle (`dev.cuda_stream()`, `dev.clone()`), and the other arms are
  spelled out rather than `_ =>` so a new backend is a compile error.
- Dtype dispatch matches on `DType` with every arm named; a dtype the kernel
  does not support is an `ensure!`/`bail!`, not a silent fallback to f32.

## 4. Shape and invariant assertions

- Code returning `Result` validates a caller-supplied shape with
  `anyhow::ensure!(cond, "<tensor> {:?}: expected ...", dims)`; the message
  names the tensor and the expectation.
- `assert!` is for an invariant no input can reach: a kernel wrapper's
  precondition where a violation would be undefined behaviour at the FFI call
  (the `nv-kernels` launchers and the WGSL dispatch helpers), and a test body.
- `debug_assert!` appears only inside a per-token or per-element hot loop
  where the release build measurably pays for the check.

## 5. cudarc host/device copies

- Host to device is `stream.clone_htod(&host)`; device to host is
  `stream.clone_dtoh(&dev)`. The cudarc 0.19 names `memcpy_stod` and
  `memcpy_dtov` are deprecated aliases with identical bodies and do not appear,
  so `#[allow(deprecated)]` does not appear either.

## 6. Tests

- A test name is a sentence in snake case stating the property
  (`fn the_draft_class_tie_picks_the_lowest_id`), not a label
  (`fn test_draft`). The name is the only place the test's rationale lives.
- A real-weight or GPU-measurement test is `#[ignore]`, feature-gated, and
  opts in through `NV_*_TEST=1` (rule 2). A measurement probe carries `_bench`,
  `_ladder`, `_rate_` or `measured` in its name and stays `#[ignore]` so the
  sweep never times it.
- A test that compares two backends asserts bitwise equality on the raw bits
  (`u16` for bf16, `u8` for fp8), and names the oracle in its name
  (`..._matches_the_host_oracle`).
- Integration tests share setup through `tests/common/mod.rs` of their crate;
  a second copy of a model-dir resolver or a context constructor is a defect.

## 7. Backend twins

- A model family is split by backend into files named
  `<family>.rs` (candle/CUDA eager), `<family>_graph.rs` (the captured CUDA
  graph step), `<family>_wgpu.rs` (the WGSL arm), `<family>_cpu.rs` (the
  quantized host arm) and `<family>_msl.rs` (a Metal-only shader arm); the
  Voxtral set is the reference. `gpt_oss_cuda.rs` keeps the `_cuda` suffix
  because its base file is backend-neutral host-weight code.
- CUDA and wgpu are parallel backends: deleting a path in one never removes its
  twin in the other, and a shared host reference (`*_host_ref`, `*_oracle`)
  stays as long as either twin exists.
- A kernel wrapper's wgpu twin has the same public name and parameter order as
  its CUDA wrapper so a model file dispatches by backend with one call shape.

## 8. Constructors

- `new(cfg, ..)` builds an in-memory value; `load(dir | &WeightLoader, device)`
  reads weights from disk; `from_<source>` converts from another in-memory
  representation. A free function constructs only a tuple or a closure.
- A builder (`<Type>Builder` with consuming `with_*` setters and `build()`)
  exists only when a constructor would otherwise take more than two optional
  arguments (`VoxtralBuilder`).

## 9. Binding a kernel

- A CUDA kernel is `cuda/<name>.cu` exporting
  `nv_kernels_<name>_<dtype>`, declared in `include/nv_kernels.h` and listed
  exactly once in
  `launcher_signatures_listed_once_so_the_no_gpu_stub_arm_cannot_drift`
  in `launcher_registry.rs`, which expands both the real launcher and the
  no-GPU stub so the two signatures cannot drift. `build.rs` compiles every
  file under `cuda/` it finds; a new kernel needs no build-script edit.
- The wgpu twin is `wgsl/<name>.wgsl` plus `src/wgpu_backend/kernels/<name>.rs`
  holding `WGSL` (`include_str!`), `WORKGROUP_SIZE`, the `ENTRY_*` names, a
  `#[repr(C)] bytemuck::Pod` params struct and `source()` through `compose`.
- Every kernel ships with a bitwise oracle test: `tests/<name>.rs` for CUDA,
  `tests/wgpu_<name>.rs` for wgpu, each comparing the device output bits
  against a host reference under `tests/support/` or `tests/common/`.

## 10. Lint suppressions

- The workspace `Cargo.toml` grants `too_many_arguments`, `type_complexity`,
  `needless_range_loop`, `large_enum_variant`, `neg_cmp_op_on_partial_ord`,
  `missing_safety_doc` and `field_reassign_with_default`; a per-item
  `#[allow]` for one of those is redundant and does not appear.
- A crate-level `#![allow(dead_code)]` does not appear: it hides every unused
  item from clippy, which is how dead code survives. An item kept for a reader
  outside the compiler (an FFI export, a serde field name, a typeshare type)
  carries its own `#[allow(dead_code)]` at the item. The one file-level allow
  is a shared test module (`tests/common/mod.rs` and its siblings), which every
  test binary of the crate compiles while using a subset of it.
- `#![allow(non_upper_case_globals, non_camel_case_types, non_snake_case)]`
  belongs only to the bindgen output module in `nv-kernels`.

## 11. Size

- Always optimize for small code: a single-use wrapper is inlined, a
  one-implementation trait is a struct, repeated setup is a helper, repeated
  registrations are a table. A knob proven by its suite replaces the path it
  supersedes in the same commit.
