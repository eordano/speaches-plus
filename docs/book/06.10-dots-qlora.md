# dots.ocr QLoRA — handwriting adaptation on the 4-bit snapshot

The dots.ocr text decoder fine-tunes as literal QLoRA: the frozen base
is the served `mlx-community/dots.ocr-4bit` snapshot (affine u4 gs64, quantized
trunk + embed + lm_head), fp32 LoRA A/B adapters train through an exact
candle-autograd forward, and the adapter saves in PEFT layout under the
checkpoint's own `language_model.model.*` module names so both serving routes
(merge and live-hook) can consume it. The vision tower never trains and never
loads in the trainer.

## Components

- `nv-train/src/dots.rs` — the trainer. 4-bit-only by construction
  (`DOTS_QLORA_TRAINS_ONLY_THE_MLX_AFFINE_U4_GS64_EXPORT`): `DotsW4Weights`
  refuses any checkpoint whose quantization block is not
  `{mode: affine, bits: 4, group_size: 64}` or whose layer-0 tensors lack
  `.scales`. Dequant rides `nv_quant::mlx_affine::dequantize_mlx_affine_linear`;
  q/k/v carry their fp bias rows on `nv_layers::Linear` (the LoRA hook lands on
  the pre-bias GEMM output, so bias composes untouched); norms load raw
  (`DOTS_NORMS_LOAD_RAW_BECAUSE_THE_MLX_EXPORT_FOLDS_THE_PLUS_ONE`). The
  frozen prefix streams one layer at a time and caches hidden states; the top
  `--grad-layers` layers train with full-graph backward. Loss is CE masked to
  completion tokens only (`TokenRow` masking, shared with the qwen38 trainer).
- `nvk-dots-lora-train` (nv-train bin, `metal` feature for the GPU device) —
  CLI over `dots::run`. Emits a JSON summary: per-step losses, seconds,
  before/after held-out CE, per-module delta amax, grad finiteness.
- `nvk-dots-vision-dump` (nv-models bin, `wgpu` feature) — dataset builder.
  Replays the serving path exactly
  (`DUMP_REPLAYS_THE_SERVING_PATH_SO_TRAIN_AND_SERVE_SEE_THE_SAME_INPUTS`):
  `RgbImage::decode_file` (+ optional bbox crop with margin), `prepare`
  smart-resize/patchify, the wgpu vision tower, `build_prompt_tokens` with the
  serving mode prompt and `PromptStyle::from_env`, label tokens appended after
  the assistant token, EOS `<|endofassistant|>` (151673, `--eos-id`
  overridable). One safetensors per sample: `ids` u32, `rows` f32
  `[n_vis, 1536]`, `vision_start`, `completion_start`, plus an `index.jsonl`.
  Input JSONL rows: `{"image": path, "text": label, "bbox": [x1,y1,x2,y2]?}`.
- Gates: the suite covering the QLoRA invariants
  (`nv-train/tests/dots_qlora.rs`) fabricates a tiny affine-u4 checkpoint and
  asserts: zero steps leave eval CE bit-identical (B initializes to zeros), a
  few steps drop train loss and held-out CE with finite grads, the adapter
  saves under `base_model.model.language_model.model.layers.N.{self_attn,mlp}.*`
  with correct shapes and `adapter_config.json`, dequant output is finite with
  out-of-vocab ids refused, and the dump format round-trips.

## Running it

Any resident engine must be stopped first, and on a shared box every
GPU-touching step (labeling, dump, training) wraps in
`rust/scripts/gpu-flock.py /tmp/claude-501/nvk-gpu0.lock <cmd>` so perf
sessions and training serialize on the one GPU. Measured footprint at
grad-layers 8, rank 16, 25 samples of seq ~240: peak RSS 22.6 GB on CPU
(21.5 GB peak footprint), 23.9 GB peak footprint on Metal — the
pre-run 8–10 GB estimate undercounted the per-sample hidden-state cache and
the optimizer copies; budget ~25 GB and re-measure before longer sequences.

```sh
sudo launchctl bootout system/org.nixos.speaches-plus
```

```sh
# 1. labels: region bbox + text JSONL (bootstrap: /v1/ocr layout-all output;
#    real gains: human-corrected text from the portal /ocr-read editable mode)
# 2. dataset
nvk-dots-vision-dump --dots-dir <rednote snapshot> \
  --data train.jsonl --out dump-train/
# 3. train (adapter saves only at the end; a killed run leaves nothing partial)
nvk-dots-lora-train --base <mlx-4bit snapshot> \
  --data dump-train/ --eval-data dump-eval/ \
  --out adapter/ --steps 40 --grad-layers 8 --rank 16
```

```sh
sudo launchctl bootstrap system /Library/LaunchDaemons/org.nixos.speaches-plus.plist
```

Both build from the `no-models` devshell:
`NVK_SHELL=.#no-models NVK_LANE=dotsq NVK_PKG=nv-train NVK_FEATURES=metal
scripts/nvk.sh build --bin nvk-dots-lora-train --release`. The dump tool is a
cargo example, not a bin: `NVK_PKG=nv-models NVK_FEATURES=wgpu scripts/nvk.sh
build --example nvk-dots-vision-dump --release`. Bootstrap labels without a
running engine come from the `dots_ocr` example (`NVK_FEATURES=metal,wgpu`,
`--json`), which on a Metal device takes the serving defaults: wgpu tower plus
the graphed wgpu decoder.

## Metal training

Metal trains unfenced. What presented as a nondeterministic backward race
(non-finite grads past one trained layer, always on k/v projections) was an
out-of-bounds read in candle-metal-kernels 0.11.0's rank>=5 strided-reduce
indexer: `get_strided_idx_fallback` decomposed the logical index
outer-dim-first, so the GQA expand backward's rank-5 broadcast sum read wrong
(often out-of-buffer) elements, and whether the garbage happened to contain
NaN bits depended on buffer-pool adjacency — which is why sync fences
"suppressed" it without fixing it, and why the fenced arm converged to 0.031
while CPU reached 0.0017: the fenced runs read stable-but-wrong memory into
the k/v grads. The workspace pins candle at upstream main (rev `4761e00b`),
which carries the indexer fix; Metal shader validation reports zero invalid
loads, and the suite covering rank-5 strided reduces and the tiny-m
transposed gemm (`nv-train/tests/metal_gemm_edge.rs`) gates it against CPU
bitwise.

Measured at seq ~240 / grad-layers 8 / rank 16 / 25 samples on the M2 Ultra
(mlx-community/dots.ocr-4bit @ 4ab989e, seed 7, GPU lock held): ~11.9 s/step
steady (3 runs: 11.92–11.98, within-arm spread <= 0.09 s), 7.7x over CPU's
~91.5, with 3/3 twenty-step runs bit-identical at loss 0.212043 → 0.001704 —
matching CPU convergence, so arms may now be compared at identical
hyperparameters. Two knobs remain for the old paths:
`CANDLE_METAL_BACKWARD_SYNC_EVERY=N` (per-node backward sync; `=1` is the old
fenced default that measured ~24.9 s/step) and
`NV_DOTS_METAL_EXAMPLE_READBACK=1` (per-example grad readback, ~2% cost, the
attribution probe that localized the bug — prints module + LoRA half for any
non-finite grad).

## Open items to full completion

1. **The data loop** — the full editable mode ships; what remains is using
   it. The portal's `/ocr-read` is a document workspace: a library over the
   feedback store (thumbnails, correction progress, drop-to-upload), a read
   view with region overlays, hover serving-crop previews, and an anchored
   editor (Cmd-Enter saves, Esc reverts, dictation streams the portal ASR
   lane into the draft and stamps `source: voice`), a review table with
   inline editing, and a records drawer over the growing corrections JSONL.
   A save posts `{t:'correct'}` with the region index and source; the portal
   appends `{ts, page_sha, region, bbox, category, model_text,
   corrected_text, source, basis}` to
   `PORTAL_DATA_DIR/ocr-feedback/feedback.jsonl`, stores the page bytes once
   per sha under `pages/` with an elements sidecar so documents reopen, and
   `{t:'attach', sha}` binds a stored page into a fresh session for later
   corrections without re-running OCR (suite
   `portal/tests/test_ocr_feedback.py`, 9 cases; proven live on an archival
   notebook scan: 13 regions in 21.5 s, typed + voice corrections through a
   live and a reattached session, converter emits training rows).
   `scripts/ocr_feedback_to_dump.py <ocr-feedback dir> --out rows.jsonl
   [--only-corrected]` converts to dump-input rows, preferring
   `corrected_text` and keeping only the newest correction per (page, bbox).
   One writer's letter is ~30 regions; 200–500 corrected lines is the first
   real dataset.
2. **CER/WER eval gate** — the tooling ships; the gate first means something
   on real corrected regions. `dots_ocr --plain --rows rows.jsonl` reads each
   held-out region through the serving pipeline in one model load, cropping
   with the dump's exact margin
   (`ROWS_CROP_MATCHES_THE_DUMP_SO_EVAL_AND_TRAIN_SEE_THE_SAME_PIXELS`);
   `scripts/ocr_cer_eval.py refs.jsonl base.jsonl [adapter.jsonl]` reports
   micro-averaged CER/WER raw and markup-neutral, with deltas when both arms
   are given. Neutral is the gating number and its normalization is a port of
   the conformance `markup_neutral`, so a layout-vs-plain formatting
   divergence (e.g. `**bold**`) moves raw but not the gate. The trainer's CE
   summary stays a proxy; the shipping decision reads the neutral CER delta.
3. **Serving the adapter — both routes ship.**
   - *Merge*: `nvk-lora-merge` /
     `nv_weights::lora_merge::merge_lora_adapter_into_quantized_snapshot`
     folds the adapter into a requantized snapshot; point `NV_DOTS_MLX_DIR`
     at the result. Costs one requantization of quality headroom.
   - *Live hook*: the q3d bias arm hot-loads a PEFT adapter beside the packed
     w4 weights. `NV_DOTS_LORA_DIR` loads it at pipeline construction
     (`DotsQ3dDecoder::from_snapshot_with_lora`), and with
     `NV_ALLOW_RUNTIME_LORA_UPDATING=1` the server exposes
     `POST /v1/ocr/load_lora_adapter {lora_path}` /
     `POST /v1/ocr/unload_lora_adapter`, which rebuild the q3d decoder and
     swap it under the pipeline mutex. Live only on `NV_DOTS_DEC_ENGINE=q3d`.
   - *Live hook, graph arm (the fast path)*: `NV_DOTS_GRAPH_LORA_DIR` loads a
     PEFT adapter into `DotsDecoderWgpuGraph::from_loader` (`DgLora`), pushing
     one shrink+expand pass pair after every adapted projection on both the
     decode list and every prefill chunk list — QLoRA serving on the affine-w4
     arm, plain LoRA on bf16, since the passes ride the converged
     post-projection buffers and are quant-agnostic. Measured over the 25
     bootstrap regions on the served W4 arm: 285 → 397 passes per decode step
     and 88.8 → 81.4 tok/s (−8.3%) with all 56 modules resident. Gated three
     ways plus off: the shrink/expand kernels match a bitwise host mirror
     across six site geometries (`dg_lora_kernels_match_a_bitwise_host_mirror
     _across_site_geometries`), the prefill sites land bitwise what the decode
     sites land token-by-token over every chunk width
     (`graph_lora_prefill_chunk_matches_per_token_steps_bitwise`), a single
     application tracks a host bf16 merge inside 3e-2
     (`graph_lora_first_decode_step_tracks_the_host_merged_weights` — longer
     comparisons measure the merge's own bf16 rounding, which loses small
     deltas entirely, so the live arm is the more exact one), and with no
     adapter dir the graph is pass-for-pass unchanged
     (`GRAPH_LORA_OFF_IS_BITWISE_OFF`). The `/v1/ocr` load/unload endpoints
     are engine-aware (`DotsOcrPipeline::reload_adapter`): they rebuild
     whichever arm the pipeline booted with, landing on the exact fresh-boot
     predicates (same config source, loader, factored quant mapping, same
     constructor), refusing truthfully on the candle arm, with the reload's
     transient double-residency cost stated
     (`RELOAD_REBUILDS_BESIDE_THE_RESIDENT_DECODER_SO_PEAK_IS_TWICE_ONE_ARM`)
     and `reload_adapter(None)` a true unload that outranks the env. Since
     the graph W4 arm is now the metal serving default, the default-path
     round trip holds live: load answers resident, the served page takes the
     adapter's distribution (region-trained adapters EOS early on full pages
     — an out-of-distribution input for a region-only corpus), and unload
     reverts the page byte-identically. Module names did
     NOT match by construction — the trainer saves the checkpoint's own
     `language_model.model.layers.*` spelling, which
     `nv_weights::lora_adapter::normalize_module_name` now folds into the
     serving `model.language_model.layers.*` namespace (suites
     `lora_stock_compat`, `dots_q3d_lora_names`). Measured on the smoke
     adapter (56 modules, rank 16): every module attaches, decode goes
     259 → 323 passes per step and 23.1 → 21.8 tok/s (−5.6%) on 3 eval
     regions, and served text changes while base CER holds. The live-server
     round trip holds end to end: load answers `lora_resident: true`, the
     served page visibly takes the adapter's training distribution (the
     labnotes table flips from HTML to markdown, content character-perfect
     in both arms), and unload reverts the page byte-identically.
4. **Training via the API — ships.** A dots.ocr base routes `/v1/fine_tuning`
   to `TrainerFamily::DotsQloraWindowed` (`model_family_tags::is_dots`):
   `training_file` must be an `nvk-dots-vision-dump` output directory (inline
   rows cannot carry vision-tower rows, and both mismatches 400 with the
   fix named), `grad_layers`/`b_lr_ratio` resolve with the dots defaults
   (8, 1.0; rank 16, alpha 2×rank, lr 1e-4), speculators of either kind are
   refused, and a succeeded job registers its adapter in the catalog exactly
   like the qwen path (suites `fine_tuning_dots`, plus the routing/knob cases
   in the endpoint's own tests). The workspace forwards `metal`/`cuda` to
   nv-train now, so the API trainer sees the same device arms as the CLI.
6. **Scale knobs, applied only when a real run demands them**: chunked lm_head
   CE to kill the ~2 GB logits spike; activation checkpointing for
   `--grad-layers 28` (the qwen38 `window_loss_and_grads_checkpointed`
   pattern, ~15 GB uncheckpointed today); bf16 base on Metal (`--bf16`,
   halves the weight footprint, untested).
7. **Quality ladder**: rank/alpha sweep on the first corrected corpus;
   vision-tower LoRA only if decoder-only plateaus (would need tower
   gradients — a different, much larger project).
