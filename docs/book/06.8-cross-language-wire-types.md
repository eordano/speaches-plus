# 6.8 Cross-language wire types

The wire shapes non-Rust consumers parse are declared once, in Rust, and
generated into every consumer language with typeshare 1.13.4 (from the fleet's
pinned nixpkgs). Hand-rolled mirrors of a wire type are a defect: the
`response.tool_progress` frame carried a `{progress: Value}` mirror in Rust and
Go for months while the live wire (garden's mock server, Rock's frame router)
carried `{response_id, tools:[{name, status, args?, result?, error?,
summary?}]}`.

## Sources of truth

- `rust/src/realtime/wire.rs` -- the realtime server-event family.
  `OutboundEvent` is the emitter enum; each variant wraps a named
  `#[typeshare]` payload struct (`ResponseToolProgressEvent`, ...), and the
  serde representation (internally tagged newtype variants) is byte-identical
  to the old inline-struct variants. `RealtimeServerEventType` is the event
  name vocabulary; the order harness asserts it matches `type_name()` for
  every variant.
- `rust/src/oapi/trajectory.rs` -- `TrajectoryRecord`, `LabelRecord`,
  `LabelHttpRequest`, `LabelHttpResponse` (the `/v1/trajectory/label` reply,
  including `matched`, which garden's feedback route reads to report
  `relayed` truthfully).
- `../new-garden/wire-types/` -- the garden<->Rock gateway lane (frame
  envelope, method vocabulary, chat evt bodies, `task.completed`,
  `garden.assistant_message_persisted`, the `_metadata` envelope). It lives in
  garden so this repo never depends on garden semantics.

## Case lanes

The gateway WS lane is camelCase on the wire; the realtime and REST/SSE lanes
are snake_case. Lanes are encoded as serde renames on the Rust types; the wire
is the constant, the renames are not style.

## Generation and gates

`scripts/gen-wire-types.sh` emits the realtime+trajectory lane into
`../new-garden/lib/generated/wire/speaches.ts`, the Rock app's
`garden/decent/rock/wire/SpeachesWire.kt`, and `go/internal/wire/wire.go`.
`--check` regenerates into a temp dir and diffs against the committed output.
Garden's `scripts/gen-wire-types.sh` does the same for the gateway lane, and
`pnpm run wire:check` there runs both. Type mappings for `Value` and the typed
ids live in `rust/typeshare.toml`.

typeshare constraints that shape the Rust:

- Internally tagged enums are unsupported, hence the newtype-variant +
  payload-struct layout.
- Bare `u64` is unsupported; wire fields carry
  `#[typeshare(serialized_as = "U53")]`.
- `object` is a Kotlin hard keyword typeshare does not escape, so
  `ResponsePayload.object` (constant `"realtime.response"`) is
  `#[typeshare(skip)]`ped from generation.
- typeshare parses source syntactically: a struct produced by a macro is
  invisible to it. Payload structs are written out literally.

The Go implementation keeps its hand structs; `internal/realtime`'s wire
parity test pins them to the generated package with an explicit
known-divergence table (extra `previous_item_id` fields, missing
`audio_end_ms` on partial transcription). Shrinking that table is progress;
any other divergence fails the test.

The studio surface stays on ts-rs (`ts-bindings` feature,
`studio/scripts/gen-types.sh`, output committed under
`studio/src/api/generated/`); `gen-types.sh --check` is its drift gate.
typeshare owns only the cross-project lane.
