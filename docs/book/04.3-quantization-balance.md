# Quantization performance/quality balance -- per-component recipe

For Gemma-4-31B-IT-NVFP4 / Laguna-XS on Blackwell sm_120. The shipped recipe is
already the textbook production-safe one -- it matches NVIDIA ModelOpt's shipped
Gemma-4-31B-NVFP4 component for component. Per-benchmark deltas below come from
Llama/Qwen studies and are order-of-magnitude only; **re-measure on Gemma-4
before locking config.** The fp8-attn decode win and the weight-error margin are
our own measurements on the real 31B (measured on the development box).

| Component | Current | Recommend | Why |
|---|---|---|---|
| Attention q/k/v/o **weights** | bf16 | **-> fp8-e4m3** | a measured decode win at severalfold less error than the rejected nvfp4; every recipe keeps attention >=fp8. Best free win, low risk |
| MLP up/gate/down **weights** | NVFP4 | keep NVFP4 (GPTQ/AWQ; +QAD to recover) | where the byte-win is; do not go below FP4 without QAT/QAD |
| QKᵀ / softmax / score·V **compute** | bf16 | keep bf16 | most sensitive path, ~0 byte savings, divergent if quantized |
| KV cache | fp8-e4m3 | keep fp8-e4m3 | 97-98% recovery, already shipped |
| **lm_head** | bf16 | **keep bf16** | tiny bytes (2.82 GB, run once/token) projecting straight to vocab logits, so it sits on the *most* argmax-sensitive path for the *smallest* win; skipped by default in vLLM/ModelOpt/LLM-Compressor. If ever pursued: fp8 per-row only, never fp4, and only behind a greedy token-agreement diff proving zero token flips vs bf16 |
| Embeddings, norms | bf16 | keep bf16 | boundary/scale-sensitive, negligible bytes |
| First 1-2 / final ~8 blocks | NVFP4 | consider bf16/fp8 insurance | NVFP4-pretraining keeps first-2/final-8 bf16 ("final layers need more dynamic range than FP4 provides") -- check our checkpoint honors this |

**The "quantize more" lever is QAD, not a finer scheme.** Quantization-Aware
Distillation (arXiv 2601.20088, NVIDIA) recovers the NVFP4 PTQ gap on
*post-trained* models where plain QAT is unstable, with only 0.3-6B tokens of KL
distillation from a bf16 teacher (Llama-Nemotron-49B: MATH500 91.4->94.6, AIME25
32.3->45.6), and `nv-train` plus the dense GPU trainer can run it. Rotation
(QuaRot 2404.00456 / SpinQuant 2405.16406) is the outlier fix and the
prerequisite for *fp4* attention, but the cost/benefit is weak -- bank the
fp8-attn win instead.
