# Prefix cache: when KV reuse is legal, and what the key must be

Read this before touching KV reuse on either serving path. The counts and symbols
below are the ones the suites assert, and the suites are the authority.

## The rule

**Exact-prefix reuse is sound exactly when every layer's per-position history is
addressed by position.** A layer that carries running state which is not indexed
by position — a recurrent cell, a causal-conv window — cannot be rewound by moving
a cursor, because there is no slot to move back to. Check the decoder's state
buffers before adding a model, never the architecture name. That condition is a
field, not a comment: `RewindLimits::positional_state_only` in
`nv-models/src/prefix_reuse.rs`. `RewindLimits::NONE` has it `false`, and
`max_advance` returns `None` for it, so every rewind admission check fails closed.

One reuse form needs no rewind at all: exact extension. When the new prompt's
LCP with the cached token stream reaches the frontier and the decoder's live
position is exactly the frontier, serving continues from where the state already
is — nothing moves, so the positional condition is not needed.
`exact_extend_target` is that decision. It is what makes a persisted snapshot
useful on a `RewindLimits::NONE` decoder; divergence before the frontier needs a
rewind and falls through to the admission policy below.

A non-positional decoder rewinds only to a state it saved. The qwen3.5-dense
decoder keeps one resume checkpoint: `save_resume_checkpoint`
(`nv-models/src/qwen3_5_dense_wgpu.rs`) copies every `recurrent_states` buffer
GPU-side — the exact buffer list `verify_chain`'s rollback snapshots — and
`rewind_to` admits exactly the saved position, restoring the copies and moving
`pos`. Attention KV needs no copy: rows past the target stay resident but are
masked by `fd.total`, the invariant the verify rollback already stands on
(`RESUME_CHECKPOINT_COPIES_DELTANET_STATE_BECAUSE_ONLY_ATTENTION_KV_REWINDS_BY_POS`).
The serving loop saves the checkpoint at `last_idx` — one token before
end-of-prompt — because the qwen chat template's generation prompt ends
`<think>\n` and that trailing newline BPE-merges with the next rendered newline on
the turn-N+1 re-render, so the LCP lands at `P-1`; a checkpoint at `P` would sit
one token past the divergence and never be admitted. Both `save_resume_checkpoint`
and `rewind_to` refuse while an MTP head is attached or mrope rows are installed,
and `reset()` forgets the checkpoint.

Cursor-only reuse leaves KV bytes in place. A saved-state rewind also restores
the overwritten state at that position. CUDA Laguna restores sliding and draft
windows from host checkpoints and restores full rows only when they are no
longer resident. These copies restore the owning cache's state; sharing a snapshot
does not authorize reuse across unrelated model, adapter or numerical identities.

**A cache that serves the wrong KV is a silent wrong answer — the worst failure
class here.** A miss costs a prefill; a bad hit costs correctness. Everything
below fails closed for that reason.

## What a rewind must clear

`RewindLimits::admits_from_high_water`, `RewindLimits::admits` and
`RewindLimits::target` govern cursor-based wgpu rewinds. Saved-state checkpoints
use their own restore contract. A cursor target must satisfy all of:

| bound | why | where |
|---|---|---|
| `positional_state_only` | the rule above | `RewindLimits::NONE` for every decoder that has not opted in |
| `max(frontier, high_water) - target <= max_advance()` | sliding-window KV is a ring: the WGSL indexes it `sp = p % ring`, and a slot holds whatever position wrote it last. Writes reach past the live frontier: a padded tail chunk writes whole-chunk rows, and a rewind to a shorter stream leaves the longer stream's rows in place. So the reach is measured from the highest write, not from the frontier | `max_advance` = `ring_slots + 1 - window - RING_REWIND_RESERVED_SLOTS`; `admits_from_high_water` |
| `target` is a multiple of `prefill_chunk` | a resumed prefill restarts chunking from the resume point, so an off-boundary target lands chunk boundaries where a cold run never puts them | `target` rounds the LCP down to a chunk multiple |
| `0 < target <= frontier` | position 0 is a reset, not a reuse, and past the frontier there is no KV to keep, whatever was written there | `admits`, `admits_from_high_water` |

The high-water mark is `Gemma4Wgpu::kv_high_water`: the end of the highest KV row
written since `reset()`. Decode steps, chained decode and every prefill or verify
chunk row raise it, padding rows included. A rewind lowers the frontier and leaves
the mark. `reset()` clears it. `restore_pos` sets it to the frontier plus one ring,
because a disk snapshot does not carry its writer's mark. A restored ring is
therefore never rewound, though exact extension at the frontier still reuses it.
`Gemma4Wgpu::rewind_to` admits through `admits_from_high_water`. Without a ring
(`ring_slots == 0`, as on `Gemma4E4b` and on `Gemma4Dense` with the ring off) the
advance is unbounded, so the mark cannot change an admission.

`RING_REWIND_RESERVED_SLOTS = 1` is the slot the ring must keep beyond the window
so a rewind re-reads what it wrote rather than what wrapped over it. The
arithmetic is gated on the host with no GPU and no checkpoint, in
`nv-models/tests/prefix_reuse_bound.rs`. The suite measures the ring oracle from
the high-water mark and checks two-rewind histories against a slot-by-slot replay
of the ring. Its tests include
`a_rewind_is_refused_wherever_the_ring_no_longer_holds_what_it_would_re_read`,
`a_rewind_after_a_shorter_rewound_stream_is_measured_from_the_highest_write`,
`every_rewind_the_high_water_rule_admits_rereads_only_what_the_ring_still_holds`,
`a_decoder_carrying_state_that_is_not_indexed_by_position_refuses_outright`,
`the_chunk_boundary_a_target_lands_on_is_the_one_a_cold_run_would_have_used`,
`a_prompt_that_extends_the_folded_stream_resumes_at_the_frontier_without_rewinding`,
and `exact_extension_refuses_divergence_and_a_decoder_that_left_the_frontier`.
The suite covering a served ring rewind against a cold prefill is
`nv-models/tests/proof_fix_g4_ring_rewind_high_water.rs`. It runs a tiny ring
model on the wgpu adapter and skips without one. It covers a rewind below an
earlier, longer stream and a rewind after a disk-style restore.

## The serving paths

### wgpu chat: one cached entry, in-process, always on

One worker thread owns one `Decoder` and services jobs serially, so there is
exactly one KV cache in the process and no concurrency to design around.
`plan_prefix_reuse` (`rust/src/oapi/chat_engine_wgpu.rs`) computes
`common_prefix_len` against the previous request's token stream, clamps it to
`prompt_ids.len() - 1` (the last prompt token must go through `step` to produce
logits), first asks `exact_extend_target` (resume at the live frontier, no decoder
call at all), then `rewind_limits().target(...)` and `rewind_to`, then the resume
checkpoint: `resume_checkpoint_pos()` filtered to `0 < ckpt <= lcp <= frontier`.
On refusal it returns 0 and the request does a full `reset()`; `rewind_to`
re-checks admission itself, so the decoder refuses even if a caller skips the
planner.

- Always on: every request plans reuse and the resume checkpoint is always saved;
  no env var restores cold prefill every turn.
- The qwen3.8 checkpoint GRID is also on by default at 4096 tokens per boundary
  (`PREFIX_REUSE_GRID_ENV_DEFAULT_4096_SET_0_FOR_THE_SINGLE_CHECKPOINT_ARM`,
  `NV_WGPU_PREFIX_REUSE_GRID=0` keeps only the end-of-prompt checkpoint, any
  other value sets G): a diverging suffix rewinds to the highest grid boundary
  under its lcp instead of running fully cold. Slots allocate lazily (149.6 MiB
  class each on the 27B, capped by
  `GRID_SLOT_CAP_BOUNDS_VRAM_AT_CAP_DELTANET_CLONES_AND_EVICTS_THE_LOWEST_BOUNDARY_BECAUSE_A_DIVERGING_SUFFIX_REWINDS_TO_THE_HIGHEST_BOUNDARY_UNDER_ITS_LCP`),
  so short-prefix workloads never pay.
- Only `Gemma4Dense` and `Gemma4E4b` return real limits from
  `Decoder::rewind_limits`; `Gemma4Moe`, `Qwen3_5Moe`, `Qwen3_5Dense`, `GptOss`
  and `Laguna` return `RewindLimits::NONE`. `Qwen3_5Dense` instead rewinds
  through its resume checkpoint (the rule above): the multi-turn append shape —
  turn N+1's rendered prompt extending turn N's prompt — hits it, because the
  think-stripping re-render diverges right after the previous prompt, below the
  post-generation frontier that exact extension needs. A diverging suffix over a
  shared document (same doc, different question in ONE turn) still runs cold on
  qwen: its LCP ends below the checkpoint. `Qwen3_5Moe` and `Laguna` carry the
  same recurrent state and have no checkpoint yet, so exact extension is their
  only hit shape. Checkpoint VRAM for the 27B is ~157 MB (48 DeltaNet layers of
  48x128x128 f32 plus conv), allocated lazily on the first save.
- The cache holds the prompt plus emitted ids and the post-request frontier
  (`PrefixCache { tokens, frontier }`, `frontier = decoder.current_pos()`). The
  planner's `target` checks the ring bound against this frontier, and `rewind_to`
  re-checks it against the higher of the frontier and the decoder's KV high-water
  mark. The spec and chain paths can commit tokens
  the emit loop never pops, pushing `frontier` past `tokens.len()`; positions
  `[0, tokens.len())` always hold exactly the recorded stream, and a frontier past
  it refuses both exact extension and the disk-restore validation — cold prefill,
  fail closed.
- The request takes the cache (`std::mem::take`) before using it and rebuilds it
  at the end, so an aborted or failed request leaves no entry to hit. The batched
  path clears it: per-slot KV is a different lifecycle.
- `prefix_tokens_reused()` counts tokens actually reused, and is the only honest
  way to tell a hit from a miss — a wall-clock ttft drop can be caching anywhere
  in the stack.

The checkpoint arm has two gates:
`nv-models/tests/q3d_resume_checkpoint.rs` (tiny model, no gating — asserts the
rewound continuation is bit-identical to a cold prefill of the shared prefix,
that the un-rewound stream differs at the divergence point, and the
refuse-at-any-other-pos / forgotten-by-reset semantics) and
`rust/tests/wgpu_qwen38_multiturn_kv_reuse.rs`
(`a_second_turn_reuses_the_first_turns_prefill_and_serves_the_cold_completion`,
`NV_QWEN38_KV_REUSE_TEST=1`, `#[ignore]`d — real 27B multi-turn: positive cached
tokens, TTFT collapse, and a turn-2 stream byte-identical to a cold reference
that follows an unrelated one-turn prompt sharing only the template header). On
gemma-4, `a_media_request_leaves_no_prefix_the_next_text_request_can_reuse`
(`rust/tests/gemma4_wgpu_mm_e2e.rs`, `NV_G4_WGPU_MM_TEST=1`, `#[ignore]`d)
requires a warm text hit and no reuse after a media request. No suite compares a
gemma-4 rewind-reused completion with a cold prefill end to end; the served ring
rewind is covered at the model level (above).

### nv-engine: paged sharing that reduces work

`BlockManager` is a genuine paged prefix cache — `compute_block_hash_tagged`
chains the previous block's hash into the next, `allocate_for` shares a block when
the stored tokens match, with refcounts and COW. `Scheduler` reaches it through
`allocate_with_prefix` and feeds `alloc.cached_tokens` into
`transition_to_prefill_with_cache`, so a shared prefix is not re-prefilled.
That hand-off is the whole difference between memory dedup and compute reuse:
sharing blocks without seeding the computed count allocates less and prefills
exactly as much, which is the failure mode to check for first when a reuse path
reports hits and saves nothing. `prefix_cache_reuse` (default `true`) forces
`cached` to 0 when off, which is the A/B control.

Two hazards stay open. `share_or_pop` guarantees the token ids match, not that
the KV bytes in that block came from the same code path; `fork_tail_for_write` —
the COW guard — has no production caller (only `block_manager.rs`'s own tests) and
in any case covers only the tail. This is a hazard, not a demonstrated bug:
today the writer is the same graph writing the same values, and it becomes a wrong
answer the moment two adapters share one engine, or prefill and decode write
bit-different KV for the same position — and the private status ledger already records that
batched decode is not bitwise deterministic w.r.t. batch composition. Separately,
`allocate_for_tagged` and `commit_filled_block_tagged` have no production caller
either, so `nv-engine/tests/lora_prefix_isolation.rs` guards a path serving does
not take.

### cuda Laguna: checkpoints at cold boundaries, an LRU across streams

One `SpecState` in `nv-models/src/laguna_serve.rs` owns the serial target cache,
with or without DFlash. Laguna XS has ten full-attention layers and thirty
sliding-window layers, with no recurrent state. The planner is `laguna_prefix.rs`;
`laguna_step_graph::prefix` bridges target snapshots in `laguna/prefix.rs` and
`laguna_fp8/prefix.rs`; `laguna_dflash/prefix.rs` supplies draft context snapshots.
`laguna_serve/prefix.rs` owns request history, admission and restore selection.

- Supported storage. BF16 target KV and FixedOne E4M3 full-layer KV with
  BF16 sliding windows have explicit snapshot formats. The FP8 format preserves
  raw codes and actual F32 K/V scales, requiring exactly-one scale bits on save
  and restore. It does not dequantize through BF16. Compacting ring storage is
  required; legacy KV, ring-attention mode, other FP8 scale policies,
  full-BF16 overrides of the FP8 cache, and legacy/non-ring draft context refuse
  reuse. Actual batch lanes have a separate lifecycle and do not use this LRU.
- Explicit arms. BF16 reuse retains the existing default-on policy;
  `NV_LAGUNA_PREFIX_REUSE=0` is the cold arm. FP8 reuse additionally requires
  the existing variable explicitly set to `1` while complete serving-path
  qualification remains open. `NV_LAGUNA_PREFIX_EXACT_EXTEND=1` independently enables exact
  extension; it defaults off and does not bypass storage, history or theta checks.
- Checkpoint position. `checkpoint_position(n, chunk)` chooses
  `((n - 1) / chunk) * chunk`, strictly inside the prompt. A prompt fitting one
  chunk keeps no checkpoint. `next_prefill_chunk_len` preserves a final
  1..256-token tail even with larger bulk chunks; the checkpoint stays at a full
  bulk-chunk boundary, before any shorter tail region. Selection uses the actual
  rendered token prefix and filters unavailable or incompatible snapshots before
  choosing the highest matching boundary. Thinking removal can therefore select
  an older checkpoint, but the template must actually produce that divergence.
  `checkpoint_preserves_sliding_layout` also requires the restored window and
  cold cache to expose the same row count after the next prefill preparation.
  An incompatible first checkpoint at a larger chunk size becomes a cold miss;
  no extra rows are copied or declared initialized to force a hit.
- Recorded history. The resident keeps the completed prompt plus every
  emitted token ID, including the final token that is not fed back into the
  decoder. History length and committed KV frontier are separate. Exact extension
  requires matching history, an initialized target frontier and matching draft
  context length. Budget/EOS clipping can leave more committed KV than emitted
  history; that state refuses exact extension. Decode-built KV and shifted
  prefill chunk boundaries require a separate cold-trajectory qualification.
  LRU snapshots sit at prefill boundaries; this is not a grid of decode snapshots.
- Draft identity. Stored checkpoints and resident history carry the draft's
  active RoPE theta bits (`active_rope_theta`) and refuse a different theta.
  Geometry validation alone cannot make already-rotated draft K reusable under
  another theta.
- Admission before copying. `NV_LAGUNA_PREFIX_LRU` defaults to 4 entries;
  `NV_LAGUNA_PREFIX_LRU_BYTES` defaults to 2 GiB. The charged bytes are private
  sliding/draft snapshot payload, each checkpoint token Vec's capacity, and each
  unique shared full allocation once while any entry retains it. Checked
  estimators and the read-only `can_admit` query test whether a copy fits;
  `insert_with` and `attach_with` reserve capacity before invoking its
  materialization closure. Protected restore candidates survive real
  least-recently-used eviction. Removing the first owner of a shared Arc does
  not remove its remaining charge. Zero entries or zero bytes disable snapshots.
- Full rows only on eviction. Checkpoint creation copies sliding windows and
  optional draft context to host; full rows remain on the device. Resident rewind
  restores those windows without downloading full rows. On a conversation switch,
  the highest checkpoint whose full image fits is archived; optional older
  entries may be evicted to make room. Surviving matching ancestors can share
  that image. If a larger image cannot fit, an older fitting checkpoint is tried;
  unavailable entries are dropped instead of copied without admission. For ten
  full XS layers with KV8/head128, BF16 payload is 40 KiB/token and FixedOne
  payload including scales is 20.625 KiB/token. A full 168000-row FixedOne image
  alone exceeds the default 2 GiB cap; resident reuse and smaller checkpoints
  have different storage costs.
- Memory and failure limits. Resident token history, optional diagnostic
  history, snapshot layout metadata, allocator overhead and the active model/KV
  pool are outside the retained-payload cap. Size queries avoid payload copies
  but can allocate small geometry vectors. Fallible host-buffer reservation lets
  allocation failures propagate before that buffer's transfer; it is not a
  guarantee against OS overcommit termination. Validation precedes destination
  writes, and transfers complete while their buffers remain alive. A failed
  restore removes the bad checkpoint; observed request failure/cancellation
  invalidates resident-only state. A poisoned CUDA context still belongs to the
  worker retirement policy.
- Client and artifacts. `SpecServeEvent::PromptCached(n)` becomes
  `ChatEvent::PromptCached`, then `usage.prompt_tokens_details.cached_tokens` in
  buffered and SSE responses. `NV_LAGUNA_SERVE_STATS=1` enables diagnostics;
  diagnostic recording can remain active on a cold arm and is accounted
  separately. Laguna prefix serving writes no disk cache.

No suite runs Laguna prefix reuse through the real model. The CUDA primitive
gates below load no model and generate no tokens, so cold-versus-reused
trajectory identity, HTTP cancellation and recovery, FP8 reuse as a default,
exact extension and the handoff composition are unqualified on the real
checkpoint.

The separate default-off BF16-prefill handoff requires
`NV_LAGUNA_PREFILL_BF16_HANDOFF=1` and explicit `NV_LAGUNA_PREFIX_REUSE=0`.
Its persistent BF16 source supplies prefill while FixedOne FP8 supplies decode.
Prepared `NV_LAGUNA_BATCH_GRAPH=m2` and `m2-spec` workers share one such source
between two retained destination caches. One lane owns the source until its
prompt finishes; ready lanes decode between prefill chunks. Completion converts
the source into the owning destination once, without reallocating the captured
destination buffers. The speculative route appends target auxiliary states only
to that lane's draft context. Cancelling the owner resets the source; cancelling
the other lane preserves it. This route uses the NVFP4 checkpoint and packed
draft linears; BF16 prefill cache and activation storage is independent of weight
precision. The draft also uses the target's shared output head, whose precision
is not covered by the packed-draft loader count.

Both prepared modes require `NV_LAGUNA_BATCH=2`, interleaved prefill, and their
normal graph selectors. With handoff enabled, `NV_LAGUNA_FP8_KV` and
`NV_LAGUNA_FP8_UNIT_SCALE` must be unset: the worker constructs typed FixedOne
destinations independently of the BF16 source. Direct-FP8 prefill instead
requires both variables set to `1`. The memory plan charges one full-capacity
BF16 source in addition to both destinations and any draft allocations.

The ordinary checkpoint path snapshots the target step cache, so source-unaware
reuse is refused rather than restoring the wrong frontier. Handoff-plus-prefix
reuse remains unqualified; ordinary BF16/FixedOne checkpoint support does not
establish that composition.

### cuda qwen4_exp: grid checkpoints in kept sessions

Qwen3.8-Flash-Next carries 36 GatedDeltaNet layers and a PLE causal-conv window,
neither indexed by position, beside 12 full-attention layers and the MTP attention
slot, which are. A resume therefore restores a saved state. `session_prefill`
(`nv-models/src/qwen4_exp.rs`) saves a `PrefixCkpt` -- every GDN `LinAttnState`
plus `ple_conv`, `Qwen4ExpConfig::prefix_ckpt_bytes` (about 110 MiB) -- at each
full prefill-chunk end strictly inside the prompt. The next request restores the
highest checkpoint strictly below its LCP with the session's previous prompt
(`saved_state_resume_point` in `prefix_reuse.rs`) and prefills only the rest.
Attention, indexer and compressed-indexer rows below the checkpoint stay resident,
rows above it are masked by `pos`, and `ple_history` is re-derived from the prompt.

- Bitwise by construction. The grid is the prefill chunk
  (`PREFILL_CHUNK_2048_IS_THE_PREFIX_CHECKPOINT_GRID_SO_A_RESUMED_PREFILL_CHUNKS_EXACTLY_AS_A_COLD_ONE`),
  so a resumed prefill chunks exactly as a cold one and every kernel sees the
  inputs a cold run gives it. A finer grid would change cold chunking too.
- Strictly below the LCP. MTP row `p-1` is written with token `p`, so a checkpoint
  at `p` is valid only when the new prompt also matches token `p`.
- Prompt positions only. Decode, verify and draft rows never hold checkpoints, so
  exact extension through generated tokens is not a hit shape. The multi-turn
  append resumes at the previous prompt's highest grid boundary below the
  re-render's divergence and prefills only from there.
- The window. `NV_Q4EXP_PREFIX_CKPTS` (default 4) keeps the highest grid states per
  session, evicting the lowest and recycling its buffers; `0` is the cold arm. A
  prefill that fails leaves the session's prompt record empty, so nothing it saved
  can match a later prompt.
- Sessions. `take_session` keeps two, neither dropped after a request. The prompt
  length picks the state, never `max_tokens`: prompts up to 8192 tokens use the
  short one, so an agent's side call (a short prompt asking for a long completion)
  never overwrites a long conversation's resident rows. Each state is at least 8192
  tokens and is sized to its request's window rounded up to
  `QWEN4_EXP_LONG_SESSION_GROWS_IN_32768_TOKEN_STEPS_SO_A_GROWING_CONVERSATION_REALLOCATES_ONCE_PER_STEP`.
  A conversation that crosses 8192 tokens carries the short state up into the long
  one when the short state reuses more of its prompt (`session_source` in
  `prefix_reuse.rs`); a short prompt never takes the long state.
  When a request outgrows its state and shares a checkpointed prefix with it,
  `grow_session` copies the rows below the highest checkpoint through host memory
  into the new state, releasing the old one first, so the device never holds both.
- Parked long sessions. The long state is the working session; before its buffers
  serve a different conversation, `park_working` (`nv-models/src/qwen4_exp_residency.rs`)
  keeps that conversation's resumable state: its token stream, its highest checkpoint
  and the attention, indexer and compressed-indexer rows below it -- the rows
  `grow_session` already carries. `SessionLru` (`nv-models/src/session_lru.rs`) holds
  it in one of three tiers: in place (the working session, no extra memory), a device
  copy, or a spill file. A later prompt that resumes further from a parked state than
  from the working sessions gets it copied back into the working buffers
  (`install_parked`) and prefills only from its checkpoint; matching is the same
  exact, token-level `saved_state_resume_point`. A parked state keeps one
  checkpoint, so a prompt that diverges below it resumes from nothing.
- Residency policy. `NV_Q4EXP_SESSION_KV_MIB` (default 0) bounds the device copies;
  a copy is also refused when free VRAM would fall below
  `NV_Q4EXP_SESSION_KV_MIN_FREE_MIB` (default 4096). A state that does not fit goes
  to `$NV_KV_CACHE_DIR/q4exp-sessions` when that is set, bounded by
  `NV_Q4EXP_SESSION_SPILL_GIB` (default 32) and deleted after
  `NV_Q4EXP_SESSION_SPILL_MAX_AGE_SECS` (default 28800, eight hours) unused; else it is
  dropped. Eviction is least recently used, and each model's most recently used
  state is never evicted, so with every knob at its default the engine keeps exactly
  the working session, as before. A new turn of a parked conversation supersedes its
  older state. Spill files are named by the weights tag (`weights_tag_for_dir`: config
  bytes, safetensors names, sizes, mtimes and headers) and a hash of the prefix;
  `read_spill` refuses any file whose format, tag, checkpoint, token stream or tensor
  geometry differs from its index entry, and a refused restore prefills cold. Files
  not in the index (a previous process's) are deleted at boot. A device copy costs
  `parked_bytes`: about 30 KiB per prefix token on the checkpoint (13 attention slots)
  plus one `prefix_ckpt_bytes`.
- Metrics. `/metrics` carries `speaches_prefix_session_lookups_total{result=...}`
  (`hit_in_place`, `hit_device`, `hit_disk`, `hit_short`, `miss`),
  `speaches_prefix_session_tokens_total{kind="reused"|"prefilled"}`,
  `speaches_prefix_session_evictions_total{to=...}`,
  `speaches_prefix_session_restore_failures_total` and the
  `speaches_prefix_session_resident{,_bytes}{tier=...}` gauges.
- Reporting. `run_sampling_qwen4_exp` takes the session before it answers, then
  sends `PromptCached` with the planned resume point ahead of `Started`.

The suite covering resumed-versus-cold identity is
`qwen4_exp_prefix_checkpoint_resume_matches_cold` in
`nv-models/tests/qwen4_exp_greedy.rs` (`#[ignore]`, `NV_Q4EXP_TEST=1`, the full
checkpoint): bit-identical first-token logits and equal greedy ids for the append,
a divergence one token below a checkpoint, a grown session, and a short side call
that leaves the long state's checkpoints in place. Parking is gated on a
synthetic two-layer checkpoint by `nv-models/tests/qwen4_exp_session_residency.rs`
(CUDA, no gating, run with `--test-threads=1` on a shared card): two long sessions
taking turns both resume from their parked copies with first-token logits and
greedy ids bit-identical to a cold prefill, the device budget evicts the least
recently used state, a spill restores bit-identically while a truncated or
over-age spill is refused, and a conversation that shares only a short prefix
never resumes from another's state. The tier rules are gated on the host by the
`session_lru` tests. The resume and routing rules are
gated on the host by `a_saved_state_resumes_strictly_below_the_shared_prefix` and
`a_short_prompt_never_takes_the_long_state_and_a_growing_conversation_carries_its_own_up`.

## The cache key

The key must contain everything that changes the KV bytes at a position: the
token ids `[0..L)` in order (the KV at position i is a function of tokens
`[0..=i]`, taken after BOS insertion, which mutates the list); decoder
identity (model id + checkpoint dir); the LoRA adapter (a LoRA on `k_proj`/
`v_proj` changes the KV); `max_seq` (`NV_WGPU_CHAT_MAX_SEQ`, which resizes the KV
slabs so slot arithmetic changes); the KV quantization format (fp8 codes + f32
scale planes; a format change reinterprets every stored byte); rope settings
(theta per layer type, rotary dim, baked into the graph at build); and every
graph-build knob that changes numerics (w4 scale grain, flash-1 route, fused-norm
unroll, preenc, chunk width).

On the wgpu path every component but the token ids is **fixed for the life of the
decoder object**, and the cache lives on the worker that owns that object — so
identity of the decoder subsumes them and only the token ids are compared.
**Persisting KV to disk, or sharing it between two decoders, re-opens every one of
those rows and the key must then carry them explicitly**: the disk layer
(`05.10-kv-disk-persistence.md`) carries model id, kind label, adapter, `max_seq`,
`prefill_chunk`, `sliding_window` and the per-layer buffer geometry in its
snapshot header and rejects any mismatch;
`BlockManager::compute_block_hash_tagged` is the equivalent shape on the paged
path.

Two things that are not in the key, stated so nobody adds them.
Sliding-window geometry: `window_start` masks what attention reads; it never
changes what a position writes, so it bounds a rewind (above) but does not key
it -- it would enter the key in a paged design where out-of-window blocks are
never materialised. Sampling — temperature, seed, top-p, penalties, grammar,
logit bias: none of it reaches the KV.

## What reuse is worth

Prefill cost grows super-linearly with context, so the saving on a hit is
super-linear in the shared fraction. On-box numbers live in the private status ledger with
their basis tuples; **a reuse claim needs `prefix_tokens_reused()` and a null
control, never a bare ttft delta.** What holds on any box:

- A full hit removes prefill and leaves decode untouched. Nothing here makes a
  cold prompt faster, and no decode number moves.
- Hit rate is a workload property. Related turns can hit when their actual
  tokenized history matches. Unrelated prompts miss; a cursor-only cache pays an
  LCP scan, while CUDA Laguna can also archive an admitted prior checkpoint.
- Cursor-only reuse needs no extra KV slabs. Saved-state checkpoints and CUDA
  Laguna's host snapshots consume their separately bounded storage.
- Multi-turn hit rate is capped by the tokenizer, not by this cache. If
  `ChatTemplate` is not append-only across a turn boundary, turn N's ids are not
  a prefix of turn N+1's and the only reachable win is a literal repeated
  prompt. That property is host-only and free to check; check it before sizing any
  e2e arm.

## Running the gates

`AGENTS.md` mandates `rust/scripts/nvk.sh`; a bare `cargo` inside
`nix develop .#no-models` has no Vulkan loader, so under
`NV_KERNELS_WGPU_REQUIRE=1` it fails on adapter acquisition rather than telling
you anything about prefix reuse.

```sh
NVK_LANE=<lane> NVK_PKG=nv-models rust/scripts/nvk.sh test --test prefix_reuse_bound

NVK_LANE=<lane> NVK_PKG=speaches-plus NVK_FEATURES=cuda,wgpu NV_QWEN38_KV_REUSE_TEST=1 \
  rust/scripts/nvk.sh test --test wgpu_qwen38_multiturn_kv_reuse -- --ignored --nocapture
```

The Laguna gates cover the planner and the device copies.
Run from `projects/speaches-plus` on the selected host, using its existing lane at
an idle experiment boundary. Each composed binary needs its own result and
source receipt; these commands specify coverage and do not assert a pass.

```sh
NVK_LANE=perfroom NVK_PKG=nv-models NVK_FEATURES=cuda \
  /usr/bin/env bash rust/scripts/nvk.sh gate --release --lib laguna_prefix::tests \
  -- --nocapture --test-threads=1

env -u NV_LAGUNA_RING_ATTN -u NV_LAGUNA_FP8_BF16_FULL \
  NV_LAGUNA_PREFIX_CUDA_TEST=1 NV_LAGUNA_FP8_UNIT_SCALE=1 \
  NVK_LANE=perfroom NVK_PKG=nv-models NVK_FEATURES=cuda \
  /usr/bin/env bash rust/scripts/nvk.sh probe --lib prefix_cuda_gate \
  -- --ignored --nocapture --test-threads=1
```

The planner gate needs no model or device execution. The three `prefix_cuda_gate`
tests require actual CUDA and verify BF16, FixedOne and draft-context snapshots,
including initialized scale metadata, resident/covering restore, malformed-source
refusal and reset/reuse. The FixedOne fixture also exercises retained writer
graphs and the StepCache bridge. Require all three passes, successful process
exit, and `LAGUNA-PREFIX-CUDA`, `BF16-PREFIX-CUDA`, `DFLASH-PREFIX-CUDA` markers.
They load no model and cannot qualify model trajectories or HTTP recovery.
