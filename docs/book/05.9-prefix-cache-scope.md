# Prefix cache: when KV reuse is legal, and what the key must be

Read this before touching KV reuse on either serving path. The counts and symbols
below are the ones the suites assert, and the suites are the authority.

## The rule

**Exact-prefix reuse is sound exactly when every layer's per-position history is
addressed by position.** A layer that carries running state which is *not* indexed
by position — a recurrent cell, a causal-conv window — cannot be rewound by moving
a cursor, because there is no slot to move back to. Check the decoder's state
buffers before adding a model, never the architecture name. That condition is a
field, not a comment: `RewindLimits::positional_state_only` in
`nv-models/src/prefix_reuse.rs`. `RewindLimits::NONE` has it `false`, and
`max_advance` returns `None` for it, so every rewind admission check fails closed.

**One reuse form needs no rewind at all: exact extension.** When the new prompt's
LCP with the cached token stream reaches the frontier and the decoder's live
position is exactly the frontier, serving continues from where the state already
is — nothing moves, so the positional condition is not needed.
`exact_extend_target` is that decision. It is the only reuse a
`RewindLimits::NONE` decoder can perform, and what makes a persisted snapshot
useful on one; divergence before the frontier needs a rewind and falls through to
the admission policy below.

**Reuse means moving `pos`, never moving bytes.** The KV for a reused prefix is
already in the slots it belongs in. Any design that copies KV between contexts has
left this document; a disk restore recreates state in the slots it came from, it
does not share it.

**A cache that serves the wrong KV is a silent wrong answer — the worst failure
class here.** A miss costs a prefill; a bad hit costs correctness. Everything
below fails closed for that reason.

## What a rewind must clear

`RewindLimits::admits` and `RewindLimits::target` are the admission policy for
every reuse that is not an exact extension. A target must satisfy all of:

| bound | why | where |
|---|---|---|
| `positional_state_only` | the rule above | `RewindLimits::NONE` for every decoder that has not opted in |
| `frontier - target <= max_advance()` | sliding-window KV is a **ring**: the WGSL indexes it `sp = p % ring`, so a position far behind the frontier has already been overwritten by a later one | `max_advance` = `ring_slots + 1 - window - RING_REWIND_RESERVED_SLOTS` |
| `target` is a multiple of `prefill_chunk` | a resumed prefill restarts chunking from the resume point, so an off-boundary target lands chunk boundaries where a cold run never puts them | `target` rounds the LCP **down** to a chunk multiple |
| `0 < target <= frontier` | position 0 is a reset, not a reuse | `admits` |

`RING_REWIND_RESERVED_SLOTS = 1` is the slot the ring must keep beyond the window
so a rewind re-reads what it wrote rather than what wrapped over it. The
arithmetic is gated on the host with no GPU and no checkpoint, in
`nv-models/tests/prefix_reuse_bound.rs` — including
`a_rewind_is_refused_wherever_the_ring_no_longer_holds_what_it_would_re_read`,
`a_decoder_carrying_state_that_is_not_indexed_by_position_refuses_outright`,
`the_chunk_boundary_a_target_lands_on_is_the_one_a_cold_run_would_have_used`,
`a_prompt_that_extends_the_folded_stream_resumes_at_the_frontier_without_rewinding`,
and `exact_extension_refuses_divergence_and_a_decoder_that_left_the_frontier`.

## The two serving paths

### wgpu chat: one cached entry, in-process, default off

One worker thread owns one `Decoder` and services jobs serially, so there is
exactly one KV cache in the process and no concurrency to design around.
`plan_prefix_reuse` (`rust/src/oapi/chat_engine_wgpu.rs`) computes
`common_prefix_len` against the previous request's token stream, clamps it to
`prompt_ids.len() - 1` (the last prompt token must go through `step` to produce
logits), first asks `exact_extend_target` (resume at the live frontier, no decoder
call at all), then falls back to `rewind_limits().target(...)` and `rewind_to`. On
refusal it returns 0 and the request does a full `reset()`; `rewind_to` re-checks
`admits` itself, so the decoder refuses even if a caller skips the planner.

- Gated on **`NV_WGPU_PREFIX_REUSE=1`** (`PREFIX_REUSE_ENV`), default off.
- Only `Gemma4Dense` and `Gemma4E4b` return real limits from
  `Decoder::rewind_limits`; `Gemma4Moe`, `Qwen3_5Moe`, `Qwen3_5Dense`, `GptOss`
  and `Laguna` return `RewindLimits::NONE`. The Qwen3.5 decoders are the rule's
  motivating case: their DeltaNet layers carry conv and recurrent state that
  `reset()` zeroes and no cursor can restore, so exact extension is their only hit
  shape — a multi-turn continuation whose rendered prompt re-tokenizes to the
  folded stream.
- The cache holds the **prompt plus emitted** ids and the post-request frontier
  (`PrefixCache { tokens, frontier }`, `frontier = decoder.current_pos()` — what
  the ring bound is measured against). The spec and chain paths can commit tokens
  the emit loop never pops, pushing `frontier` past `tokens.len()`; positions
  `[0, tokens.len())` always hold exactly the recorded stream, and a frontier past
  it refuses both exact extension and the disk-restore validation — cold prefill,
  fail closed.
- The request takes the cache (`std::mem::take`) before using it and rebuilds it
  at the end, so an aborted or failed request leaves no entry to hit. The batched
  path clears it: per-slot KV is a different lifecycle.
- `prefix_tokens_reused()` counts tokens actually reused, and is the only honest
  way to tell a hit from a miss — a wall-clock ttft drop can be caching anywhere
  in the stack.

The end-to-end gate is `rust/tests/wgpu_prefix_reuse_ab.rs`
(`a_reused_prefix_serves_the_completion_a_cold_prefill_serves`): it asserts the
reused answer equals the cold one and that reuse is off with the env unset. It is
`#[ignore]`d and needs `NV_WGPU_SERVE_TEST=1` plus a model dir, and its
`cfg(not(feature = "wgpu"))` arm prints that a cfg-out is a SKIP, not a pass.

### nv-engine: paged sharing that reduces work

`BlockManager` is a genuine paged prefix cache — `compute_block_hash_tagged`
chains the previous block's hash into the next, `allocate_for` shares a block when
the stored tokens match, with refcounts and COW. `Scheduler` reaches it through
`allocate_with_prefix` and feeds `alloc.cached_tokens` into
`transition_to_prefill_with_cache`, so a shared prefix is not re-prefilled.
**That hand-off is the whole difference between memory dedup and compute reuse**:
sharing blocks without seeding the computed count allocates less and prefills
exactly as much, which is the failure mode to check for first when a reuse path
reports hits and saves nothing. `prefix_cache_reuse` (default `true`) forces
`cached` to 0 when off, which is the A/B control.

Two hazards stay open. `share_or_pop` guarantees the *token ids* match, not that
the KV bytes in that block came from the same code path; `fork_tail_for_write` —
the COW guard — has no production caller (only `block_manager.rs`'s own tests) and
in any case covers only the tail. **This is a hazard, not a demonstrated bug**:
today the writer is the same graph writing the same values, and it becomes a wrong
answer the moment two adapters share one engine, or prefill and decode write
bit-different KV for the same position — and `01.4-STATUS.md` already records that
batched decode is not bitwise deterministic w.r.t. batch composition. Separately,
`allocate_for_tagged` and `commit_filled_block_tagged` have no production caller
either, so `nv-engine/tests/lora_prefix_isolation.rs` guards a path serving does
not take.

## The cache key

The key must contain everything that changes the KV bytes at a position: the
token ids `[0..L)` in order (the KV at position *i* is a function of tokens
`[0..=i]`, taken **after** BOS insertion, which mutates the list); decoder
identity (model id + checkpoint dir); the LoRA adapter (a LoRA on `k_proj`/
`v_proj` changes the KV); `max_seq` (`NV_WGPU_CHAT_MAX_SEQ`, which resizes the KV
slabs so slot arithmetic changes); the KV quantization format (fp8 codes + f32
scale planes; a format change reinterprets every stored byte); rope settings
(theta per layer type, rotary dim, baked into the graph at build); and every
graph-build knob that changes numerics (w4 scale grain, flash-1 route, fused-norm
unroll, preenc, chunk width).

On the wgpu path every component but the token ids is **fixed for the life of the
decoder object**, and the cache lives on the worker that owns that object — so
identity of the decoder subsumes them and only the token ids are compared.
**Persisting KV to disk, or sharing it between two decoders, re-opens every one of
those rows and the key must then carry them explicitly**: the disk layer
(`05.10-kv-disk-persistence.md`) carries model id, kind label, adapter, `max_seq`,
`prefill_chunk`, `sliding_window` and the per-layer buffer geometry in its
snapshot header and rejects any mismatch;
`BlockManager::compute_block_hash_tagged` is the equivalent shape on the paged
path.

Two things that are **not** in the key, stated so nobody adds them.
**Sliding-window geometry**: `window_start` masks what attention *reads*; it never
changes what a position *writes*, so it bounds a rewind (above) but does not key
it -- it would enter the key in a paged design where out-of-window blocks are
never materialised. **Sampling** — temperature, seed, top-p, penalties, grammar,
logit bias: none of it reaches the KV.

## What reuse is worth

Prefill cost grows super-linearly with context, so the saving on a hit is
super-linear in the shared fraction. On-box numbers live in `01.4-STATUS.md` with
their basis tuples; **a reuse claim needs `prefix_tokens_reused()` and a null
control, never a bare ttft delta.** What holds on any box:

- A full hit removes prefill and leaves decode untouched. Nothing here makes a
  cold prompt faster, and no decode number moves.
- Hit rate is a workload property. Multi-turn chat hits by construction; a fan-out
  of unrelated prompts never hits and pays only an LCP scan — a `u32` compare per
  prompt token, against a prefill.
- Memory cost is zero: the KV slabs are already allocated at `max_seq` and already
  survive `reset()`.
- **Multi-turn hit rate is capped by the tokenizer, not by this cache.** If
  `ChatTemplate` is not append-only across a turn boundary, turn *N*'s ids are not
  a prefix of turn *N+1*'s and the only reachable win is a literal repeated
  prompt. That property is host-only and free to check; check it before sizing any
  e2e arm.

## Running the gates

`CLAUDE.md` mandates `rust/scripts/nvk.sh`; a bare `cargo` inside
`nix develop .#no-models` has no Vulkan loader, so under
`NV_KERNELS_WGPU_REQUIRE=1` it fails on adapter acquisition rather than telling
you anything about prefix reuse.

```sh
NVK_LANE=<lane> NVK_PKG=nv-models rust/scripts/nvk.sh test --test prefix_reuse_bound

NVK_LANE=<lane> NVK_PKG=speaches-plus NVK_FEATURES=cuda,wgpu NV_WGPU_SERVE_TEST=1 \
  rust/scripts/nvk.sh test --test wgpu_prefix_reuse_ab -- --ignored --nocapture
```

The first needs no GPU and no checkpoint. The second loads a model and drives the
device: do not run it against a busy one, and grep the output for `skip` — a
cfg-out prints `0 passed` **and** `0 ignored`, and the env-gated early return
prints `1 passed` in 0.00s.
