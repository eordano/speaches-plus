## Serving support matrix -- model x backend

Authority is the code: `backend_select::ModelClass` and
`cuda_model_unservable_reason` / `wgpu_model_support` for what the selector
answers; `chat_engine/build.rs`'s `detect_family` and `try_load` for what the
engine will load; `chat_engine_wgpu::classify_wgpu_model` for the wgpu side.
`GET /v1/backends` (`backends_report()`) is the live machine-readable form, and
`backend_wgpu_gate.rs` derives its assertions from the same two functions so a
new family cannot silently stale it.
[`02.1-model-compat-matrix.md`](02.1-model-compat-matrix.md) carries
per-checkpoint blocker detail.

**Three selector/engine divergences are live and are the first thing to check
when a model refuses on one path and loads on the other:**

1. `cuda_model_unservable_reason` refuses `Qwen35Dense` unconditionally while
   `detect_family_with_dense_cuda_serve` honours `NV_QWEN35_DENSE_CUDA_SERVE`.
   `Qwen38Dense` checks that same variable, so qwen3.5-dense is refused by the
   selector where qwen3.8-dense is not.
2. `NV_E4B_CUDA_SERVE` has opposite polarity on the two sides: the selector
   demands `=1`, the engine bails only on `=0`.
3. `ModelClass::Unknown` falls into the catch-all `None` arm, so an
   unrecognised model id is reported cuda-servable.

`QWEN35_DENSE_NO_CUDA`'s message still says cuda has no loader for the family;
`Qwen3Moe::from_loader_dense_quantized` is that loader, so the message is stale.

### wgpu serving (`NV_SERVE_BACKEND=wgpu` + `NV_WGPU_CHAT_MODEL_DIRS`)

`chat_engine_wgpu.rs` runs one worker thread per model, official-template-only
prompts, host or in-shader sampling, LoRA adapters (E4B only) and spec decode
(E4B only, `NV_WGPU_SPEC` default-on: suffix automaton plus a learned assistant
drafter auto-discovered from the HF cache). Batched decode is opt-in
(`NV_WGPU_BATCH>1`, Gemma4Dense graph only -- measured a LOSS on this kernel, so
the default stays single-stream). Model-crate default flips (int8 lm_head,
W8-FFN, fp8 attn formats, NVFP4-v2 routing) are read from env inside the
`nv-models` constructors, so the serving path inherits them with no plumbing lag.

**Chunked prefill is default-on and universal.** All seven `WgpuModelKind`
decoders implement `prefill_tokens`; `chunked_prefill_enabled()` is
`NV_WGPU_CHAT_CHUNKED_PREFILL != "0"` and engages wherever
`prefill_chunk_len() > 0`. Per-decoder widths default to 16 (qwen3.5-dense,
gpt-oss) or 64 (qwen3.5-moe, laguna), overridden by `NV_WGPU_PREFILL_M` or the
per-model `NV_*_WGPU_PREFILL_M` (`NV_G4_WGPU_PREFILL_M` and friends); `0` or `1`
disables. What is *not* universal is media-row splice prefill, which exists only
for qwen3.5-dense and gpt-oss (image rows) and gemma4 dense/moe (embed rows).
**On gemma4-dense the only epilogue that disables chunking outright is the
legacy row-scale one (`NV_WGPU_ATTN_FP8_LEGACY`)**, which scales after the
reduction and has no mk twin; the other disablers are the 256-byte
storage-offset shape rule, any nvfp4 projection surviving to the graph, and a
prefill width of 0 or 1. `NV_WGPU_PIPELINE_LOG` (default off; `1` = stderr,
another value = an append-to-file path) dumps the per-boot pipeline set.

|---|---|---|---|---|
| `Gemma4Dense` | yes | no | opt-in slots | real weights over HTTP |
| `Gemma4E4b` | yes (the reference wgpu model) | yes, default-on | no -- multi-row route excluded | real weights, bf16 + qat-w4a16 snapshots |

| `Qwen38Max`, `DiffusionGemma` | **NO** | -- | -- | capacity and block-diffusion refusals |

Prefix reuse and KV disk persistence are
[`05.10-kv-disk-persistence.md`](05.10-kv-disk-persistence.md). In-memory prefix
reuse (`NV_WGPU_PREFIX_REUSE=1`) is gated green on gemma4-dense real weights,
byte-identical cold vs reused, and asserts per-request
`usage.prompt_tokens_details.cached_tokens`. Disk persistence
(`NV_KV_CACHE_DIR`) covers every wgpu decoder, with snapshot capacity flat
across 8k-128k. Gemma templates reload warm; **Laguna and Qwen3.6 resume
cold-but-correct because their templates do not re-render history to the folded
stream** (the [`05.9-prefix-cache-scope.md`](05.9-prefix-cache-scope.md)
template cap; a token-splice resume would lift it and is unbuilt).

### Gaps filed, not attempted

1. **Qwen3 cuda arm ignores quantization.** `Qwen3::from_loader_quantized`
   exists and degrades to bf16 on unquantized configs; the `build.rs` arm calls
   plain `from_loader`, so NVFP4 qwen3-architecture checkpoints fail to load.
2. **Laguna DFlash default lookup misses this box's snapshot.**
   `laguna_loop::laguna_dflash_dir()` falls back to
   `models--poolside--Laguna-XS-2.1-DFlash/snapshots/main`; the cache holds
   `-DFlash-NVFP4` only, so a default boot serves spec without a draft (M=1
   graph only) and merely warns. Add the `-NVFP4` name to the lookup, or ship
   `NV_LAGUNA_DFLASH_DIR` in the run config.
3. **Qwen MoE serving graphs** -- serving hardwires no capture for 3.6-MoE.
4. **Gemma4Moe cuda residue** -- eager host-routed experts only; grouped
   dispatch, graphs, spec decode and any real-weights run remain open.
5. **Missing real-weights wgpu evidence**: GptOss, Gemma4Moe, Qwen38Dense.
6. **DiffusionGemma decode loop** -- block-diffusion serving, both backends.

## Gemma4-31B CUDA serving -- shipped defaults

Eagle3 spec-decode default-on with ctx-gated k (4 for prompts <8192 tokens, 3
above), the B2 trio on, **`NV_ATTN_PROJ_QUANT` opt-in (default OFF)**.
`ATTN_PROJ_QUANT_DEFAULT_ON` is `false` in `gemma4.rs` and the default flip is
**refused**: a direct probe over all 9430 MMLU-Pro reasoning items with CoT
untruncated shows a statistically significant accuracy loss failing the
pre-registered -1.5-pt non-inferiority bound, and "quant lengthens chains" is
falsified — CoT length is a clean null. The record config
(`NV_ATTN_PROJ_QUANT=nvfp4 NV_DRAFTER=dflash NV_DFLASH_QUANT=nvfp4`) beats the
default at short ctx, inverts at 16k, and stays opt-in.

`NV_DETERMINISTIC=1` is required for exact-match quality gating and is not a
serving default: Marlin NVFP4 GEMM atomic split-K makes serving argmax
non-deterministic at a per-position rate that matters without it.

## Laguna (Poolside Laguna XS/S 2.1)

Architecture (`nv-models/src/laguna.rs`): mixed sliding(512)/full attention 3:1,
per-layer query-head counts (XS: 48 full / 64 sliding, kv=8), per-head QK
RMSNorm, dual rope (YaRN partial-0.5 θ=5e5 + attention_factor on full layers;
plain θ=1e4 on sliding), softplus per-head output gating before o_proj,
sigmoid-router MoE (256 experts top-8, `e_score_correction_bias` selection-only
bias, norm_topk, routed_scaling 2.5, ungated shared expert), dense layer 0.
`LagunaKvCache` implements the `Gemma4Cache` trait (sliding compaction, bf16);
NVFP4 experts load via the compressed-tensors path; EOS ids [2, 24]. **No
numerical parity claim** -- architectural verification plus greedy-agreement and
near-tie gates only.

**Defaults on:** grouped MoE prefill and device-side MoE routing for decode;
device argmax plus incremental detokenization (`NV_LAGUNA_HOST_SAMPLE=1`
reverts); `NV_LAGUNA_M1_FLASH`, `NV_LAGUNA_M1_QKV`, `NV_MOE_TAIL_FUSE` (`=0`
disables each); `NV_LAGUNA_LMHEAD_FP8` scoped-on — fp8 head on the base tiers
(M=1 step graph, eager decode, serve-spec no-draft) and bf16 head inside the
DFlash speculative round, because the fp8 head shifts prose τ there; and
`NV_LAGUNA_SERVE_SPEC` + dflash draft at k=4 with the checkpoint rope-θ fixed
policy.

**Prefill is grouped MoE, chunked at 256 tokens**, because the sliding cache
caps at `window + slack = 768`.

**Per-expert NVFP4 copies are released after the grouped MoE prebuild**,
reclaiming 1.6875 MiB/expert x 256 x 39 sparse layers off the resident plateau,
free on the eager path too. `NV_LAGUNA_KEEP_EXPERT_COPIES=1` keeps them and with
them the host `moe.forward()` path; with the experts freed a host-MoE request
logs a one-time degradation notice and completes;
`NV_LAGUNA_HOST_MOE=0/off/false` silences even that, and `=1` skips the grouped
prebuild entirely and decodes severalfold slower. **Host prefill is never faster
than grouped prefill.**

Two opt-in decode-MoE arms (both default-off, argmax-class not bitwise):
`NV_MOE_FP4_DECODE_GEMV=1` swaps the CUTLASS m=1 grouped GEMMs for the
weight-streaming grouped GEMV (`moe_grouped_fp4_gemv_m1_bf16`);
`NV_MOE_SHARED_FOLD=1` folds the shared expert into the grouped decode pipeline
as a fixed extra tile — routing writes k routed slots plus a weight-1.0 shared
slot per token (`moe_route_topk_shared_tail`), the shared expert's activations
quantize through the same nvfp4 path as routed experts, and the aux-stream
candle shared path drops out of the M=1 step entirely. Fold applies to the
single-token grouped decode (eager and captured); grouped prefill and the
verify path keep the separate shared expert, which is why the shared expert's
weights stay resident.

`NV_LAGUNA_SERVE_SPEC` routes eligible greedy requests through a persistent spec
engine (`laguna_serve.rs`) on a dedicated `laguna-spec-serve` thread, with the
identity-safe M=1 whole-step graph as the default spec path and a persistent
DFlash draft + `DflashGraphProposer` + `LagunaVerifyGraph` above it. All
captures happen at engine-build warmup, so the first request runs at full speed.
Routing is gated on `is_greedy` ∧ no penalties ∧ no guided ∧ empty `logit_bias`
∧ `!logprobs` ∧ `NV_LAGUNA_HOST_SAMPLE` unset ∧
`prompt + max_new + k + 2 <= max_seq`. **Spec-vs-normal identity is asserted
byte-identical on the no-draft path** (text, finish_reason, completion_tokens,
including EOS-terminated and max_new-truncated cases, and across sequential
requests on one reused engine) and **not** asserted on the draft path, where
M-shape verify numerics can flip near-ties.

**The 300 tok/s target is not met, and round cost is not the reason.** The
graph-capturable timestamp profiler (`NV_LAGUNA_VERIFY_PROF=1`, zero nodes
captured when off) measures overhead-above-compute far under the threshold the
launch-fusion / PDL / megakernel family needed to be worth starting, so that
whole family is NO-GO; the M=5 verify residual is real compute (MoE ffn roughly
doubles vs M=1). **The sole remaining blocker is τ** — drafter quality against
the NVFP4 target.

**Long context:** the graphed stack runs to 52 K tokens bf16 with needle recall
exact; the depth cost is entirely verify round time and τ is content-dominated,
not monotonic. **fp8 KV composed with speculation is a net effective-tok/s
LOSS** — the verify graph is bf16-ring-only, so fp8 falls back to eager verify;
do not compose them. With fp8 KV alone the smem cap is raised via
`attention_fp8_decode_gscores` (a global-scratch scores sibling; sub-cap
dispatch is the old kernel byte-for-byte) plus the `kv_fp8.cu` token-axis grid
fix: needle FOUND and spec identity EXACT at 69,675 and at 254,823 tokens.

The bar for default-ON is tie-class-clean (gray = 0, real = 0) at BOTH 2 K and
depth. Only the scoped Laguna lm_head meets it.

### Laguna kill list -- reviewed, rejected, do not re-litigate

L2 hot-expert cache / expert reordering (the routed-expert line is a tiny slice,
the per-token expert stream dwarfs L2, the free-repeat ceiling is sub-noise).
Sliding-layer KV in smem or persistent-kernel residency (the entire sliding KV
read is sub-noise). fp8 hidden states / activations end to end (sub-noise
ceiling; M=1 is weight-bandwidth-bound, and accuracy risk runs through q/k-norm,
partial rope, softplus and the router). Multi-block (k=2, 32-token) verify (each
extra block consumes gigabytes of extra unique experts, consumed only when all
15 drafts accept). Tree verification, EAGLE-2 style (the τ gain cannot pay the
round-cost growth — fine-grained 256-expert top-8 MoE inverts dense-model tree
economics). Router-gate quantization (sub-noise, in the checkpoint's ignore
list, top-8 selection flips under noise). Embed-row quantization (8 KB/token).
KVFlash-style host-RAM KV paging (exists to fit 24 GB cards; revisit only for
multi-request serving). Multi-step N-token single-graph capture (obsoleted by
the draft + block-verify step structure). Adaptive block truncation
(measured-negative at k=4, stays opt-in off, bucketed verify-graph
infrastructure retained). Confidence-truncated drafting as a serving win (Laguna
verify is width-flat, so the maximum width-proportional saving is
sub-millisecond per round). Deferred rather than killed: persistent megakernel,
Blackwell PDL on graph nodes, w4a16 attention (needs a quality-eval harness
first), prefill chunk 256->1024 (decode-neutral).

## Qwen3.6 (Qwen3.5-MoE)

Device-routed grouped MoE is default ON (`GroupedMoeDispatch` in
`qwen3_5_moe.rs`: per-layer grouped NVFP4 weights prebuilt eagerly, one
persistent `GroupedDecodeContext` across the 40 layers, `moe_route_topk` softmax
mode 0, capture-safe shared-expert tail; `install_grouped_moe()` wires it and
any build error leaves the hook uninstalled, falling back to the existing clean
refusal). Its gates are green: answer-agreement 8/8 on real 35B against the i64
integer-lattice oracle, flip gate all 11 controls 100% token-exact. Grouped is a
different-but-valid activation-rounding realization, not a bit-exact one.
**Cost:** the grouped expert copy holds a large extra VRAM block on top of the
host-path weights and the boot line WARNs; `NV_QWEN_MOE_GROUPED=0` restores host
dispatch and frees it.

**Whole-step capture works bench-side only** (`NV_QWEN_MOE_GROUPED=1
NV_GRAPH_CAPTURE_FORWARD=1`); serving hardwires no capture. Root cause of the
earlier capture failures: **candle ops are not graph-capturable** —
candle uploads `[dims, strides]` metadata per call via `clone_htod` of a
temporary host `Vec`, so a single `index_select` inside a capture replays against
freed host memory. The graceful-fallback path is in place, so a capture failure
degrades instead of wedging.

**Instrument rule:** thinking-ON packs measure CoT-trace stability, not answers.
`NV_CHAT_EVAL_THINKING=0` is the eval-correct rendering for thinking-default
models.

### Spec-decode / serving-perf frontier

1. **hd512 verify (`NV_MK_VERIFY_HD512`): default ON.**
   `mk_verify_hd512_from(raw) = raw != Some("0")`, and the effective gate also
   requires `NV_EAGLE3_TREE` unset. Still `#[cfg(feature = "cuda")]` — no Metal
   build has a reader, so do not A/B it on Apple silicon. Remaining: the M>=5
   register droop fix.
2. **Serving-tau residue is DISPROVEN — do not reopen.** The serve loop matches
   offline `generate_greedy` EXACTLY on rounds and accepted at matched theta
   (16.3k ctx, real weights, k=4 and k=15); both named suspects (aux-capture,
   ctx-ring) are falsified by construction.
3. **The drafter-KV budget cap is in force.** The boot check (`DrafterKvCharge`) and the
   per-request eagle3 admission charges use `min(kv_max, sink+window+slack)`
   rows when `NV_DRAFTER_KV_WINDOW` is set, byte-identical when unset. The
   dflash charge is deliberately uncapped — `DFlashContextKv` grows to context
   length, pinned by
   `capped_eagle3_charge_never_undercuts_the_uncapped_dflash_term`.
4. **Verify slice map: CLOSED.** In-graph segmentation of a real spec session
   (`rust/scripts/verify-trace.sh`; `analyze.py <trace> graphs` is the
   segmentation of record) shows GPU idle inside the verify graph is a small
   share, so the Lt-stall slice buys under a millisecond, and the
   rmsnorm->quantize fusion pair measured slower than separate. The int8 lm_head
   is v2 (`normx_mk` pre-kernel + `gemv_i8_prenormed_mk`, auto-selected
   at K>=4096, `NV_LMI8_PRENORM=0` reverts; E4B shapes keep the old kernel
   bit-for-bit) with 48/48 teacher-forced agreement, but the
   `NV_VERIFY_LMHEAD_INT8` flip decision is **[NEEDS-USER]** and the default
   stays OFF. **The remaining gap to the round target IS the bf16
   attn-projection GEMMs**: closing it needs either attn-proj quant (refused on
   the MMLU-Pro probe) or a materially faster bf16 GEMM/format **[NEEDS-USER]**.
5. **Spec-loop dedup + VerifyMaskDev threading** (E2/E4; E3/E1 landed
   det-gated).
6. **Fused context-KV precompute, lifted into Eagle3.** In DFlash/DSpark,
   context tokens never run through the draft decoder stack: every layer's
   context K/V is projected from the same input. The same legality argument
   holds in the Eagle3 drafter in degenerate (L=1) form — a context row's K/V
   are pure per-row functions of `block_in`, with no recurrence from row *i-1*'s
   drafter output, yet `encode_context_rows` runs the full block per chunk and
   discards everything except `cache.k`/`cache.v` and the last row's
   `block_out`. The lift — one k_proj GEMM + one v_proj GEMM + RoPE over rows
   `0..n-2`, full block for the final row only — deletes the O(n^2) sdpa term
   and the per-row MLP from preencode and should be bit-identical. Care points:
   exact norm/RoPE order, the shift-mode pairing of the final row with the bonus
   token, and whether `tail_append_device` expects the layout a projection-only
   fill writes.
7. **Laguna structural items**: device argmax on the remaining non-greedy paths,
   a sliding-KV ring buffer with an in-place write kernel, and a whole-block
   M=k+1 verify graph with attention included.

### Engine / serving

1. **Batched paged-attention kernel** — one call for all B rows, taking a `[B]`
   block-table array and `[B]` context lengths; the per-row loop body in
   `forward_decode_batched` is the drop-in seam.
2. **Spec `Verify` batches through `BatchEngine`** — the scheduler supports the
   batch kind; `step()` returns an explicit error for it.
3. **Stepper-side chunked prefill** — the scheduler splits at the token budget,
   but the shipped Gemma4 steppers do not override `step_mixed`, so non-final
   chunks are deferred rather than executed.
4. **Qwen3 steppers** mirroring `Gemma4PagedBatchStepper`.
5. **Continuous-batching throughput ramp** — blocked by GPU OOM under co-tenant
   load; needs a quieter box.
6. **Engine-path chunked prefill for sliding fp8 layers** —
   `LagunaDflashEngine` prefills the whole prompt in one shot into the sliding
   fp8 cache and fails cleanly past capacity, which blocks the fp8 spec depth
   datum.
7. **CUDA loops do not emit `ChatEvent::StoppedBy`.** The shared `StreamEmitter`
   records the matched stop string, but only the wgpu path and `EchoEngine` emit
   the event, so `/v1/messages` responses served by the CUDA loops report
   `end_turn` and a null `stop_sequence` on a stop-string hit. The fix is one
   `if let Some(s) = emitter.matched.take()` push before each loop's `Done`
   send, across `chat_engine/{qwen,gemma4_loop,gemma4_moe_loop,laguna_loop}.rs`.

## #53 long-context spec-decode crossover

Eagle3/dflash spec decode crosses to a net LOSS at roughly 9.4 K ctx on both
code-long and chat-long prompts. **The root cause is the PRODUCT of two
effects**: verify ms/round grows superlinearly (M=k+1 rows each pay long-KV
attention) while no-spec decode is weight-bound and flat, AND τ collapses with
depth. Holding either constant flips it back to a win. The k=3 ctx gate is
validated optimal — k=4 at depth is worse, because draft cost exceeds
position-3 acceptance. `NV_MK_VERIFY_HD512` (default ON) cuts verify round time
enough to turn code-long from LOSS to WIN and chat-long from LOSS to
break-even, leaving short ctx untouched, and **`NV_SPEC_CTX_DISABLE` is the
guaranteed-no-regression floor** (default off, byte-identical when off): above
the configured prompt length the gemma4 serve loop falls through to non-spec, so
spec can never lose. Set it to 8192 with hd512 off, or ~9-16 K with hd512 on.

Two related standing results. DFlash rope-theta at long ctx: the shipping
default (fixed = checkpoint theta 500000) is optimal at >=16k for code and prose
alike, and `NV_DFLASH_ROPE_THETA_POLICY=auto` is dominated there — use
`policy=depth` for per-class picks below 8192 ctx. And **the prose tau deficit
is drafter capability, not a serving bug**: prose mean accepted prefix is
roughly half of code's on real 31B + DFlash, nearly all prose prefix-kills are
content-word starts, and drafter confidence discriminates match from mismatch
cleanly.

## Operational notes

- Work directly in the tree on `main` and isolate concurrent agents by disjoint
  file ownership, not by worktrees or branches.
- `/tmp` is a 32 GB tmpfs mounted at root and can fill under concurrent cuda
  builds. Set `TMPDIR=$HOME/.cache/cargo-tmp` for cuda invocations, and reclaim
  stale scratch with `find /tmp -name 'nix-shell.*' -mmin +60 -exec rm -rf {} +`.
- `scripts/strip-comments.py` is the canonical formatter for new code.
- **No-spec serving arm (gemma4): the only working switch is `NV_NO_SPEC=1`**
  (accepts anything except empty/`0`/`false`). `NV_SPEC_DECODE` is read nowhere
  in the tree, and `NV_DRAFTER=none` is an invalid arm that warns then defaults
  to `eagle3` — both produce spec-enabled "no-spec" runs.
- **Benchmarking: there is one GPU and a permanent idle co-tenant.** Idle-gate
  to 0% external util before and after every run, keep runs strictly serial, and
  record `nvidia-smi` occupancy with each number.
- **Silent-failure guards.** A zero-init Qwen3-TTS vocoder is **fatal at boot**,
  with `NV_TTS_ALLOW_SILENT_VOCODER` as the opt-in restoring the silent path and
  `503 tts_vocoder_zero_init` at request time, and `/v1/audio/speech` answers
  `404 model_not_found` rather than silently substituting Kokoro.
  `EOU_AUDIO_REQUIRED` mirrors `NV_EAGLE3_REQUIRED`/`NV_DFLASH_REQUIRED` for
  `EOU_KIND=audio|fusion` with no smart-turn model — boot logs an error naming
  `EOU_AUDIO_MODEL_PATH` and the flag makes it fatal — and the absent audio head
  scores `NaN` (`MissingAudioEouModel`) instead of a constant `1.0`, so fusion
  degrades to the text head instead of being pulled toward "turn complete".
  `/v1/ocr` refuses an unqualified request with `400 ocr_backend_ambiguous` once
  two or more backends are loaded, and `x-spec-decode` plus `spec_decode` on
  `/v1/models` expose the spec state.
