# GGUF loader -- format notes and upstream citations

`nv-weights/src/gguf.rs` implements `GgufLoader`, an alternate `TensorSource`
backend (02-model-loading.md, "Weights") for GGUF checkpoints. The Stage-1
target is `unsloth/gemma-4-26B-A4B-it-qat-GGUF`, uniformly Q4_0 (every weight
matrix) plus F32 (norms / router / scales).

**The dimension-reversal quirk.** GGUF is key-value metadata plus a tensor-info
table in one `mmap`-friendly file (ggml-org/ggml, `docs/gguf.md`), and that spec
does not say how tensor dims are ordered on disk: ggml stores them
fastest-varying-first (C convention), the opposite of PyTorch's row-major
`[out, in]`. candle's reader undoes this itself (`dimensions.reverse()` in
`candle-core`'s `quantized/gguf_file.rs`), so by the time `GgufLoader` sees a
shape it is already in the `[out, in]` order every other backend here expects —
a 3-D stacked-expert tensor stored as ggml's `[in, 2*inter, experts]` comes back
as `[experts, 2*inter, in]`. **No manual transpose or permute is needed anywhere
in `gguf.rs`.**

**Q4_0: the two-precisions-of-one-scale gotcha.** Q4_0 packs 32 contiguous
values (`QK4_0`) into one block: a single `f16` delta `d` plus 16 bytes of 4-bit
signed-offset nibbles (`stored = signed + 8`, low nibble first, per element).
candle's exact reimplementation is `BlockQ4_0::{from_float, to_float}` in
`candle-core`'s `quantized/k_quants.rs`, itself citing llama.cpp's
`quantize_row_q4_0` / `dequantize_row_q4_0`. The gotcha the test suite exists to
pin: **the quant index and the dequant multiply use two different precisions of
the same scale.** `from_float` computes `d = max/-8` and picks each element's
4-bit index with the full-precision `f32` `d` (`id = 1/d`), then stores `d`
truncated to `f16`; `to_float` dequantizes with that *truncated* value, not the
`f32` one that picked the index. Using the untruncated scale on the dequant side
— the "obviously more precise" choice — reproduces different bytes than ggml on
rounding ties. `q4_0_dequant_matches_candle_bit_exact` is an independent
reimplementation of both halves, checked against candle's `QTensor::quantize`
output for exactly this reason; its 1e-4 max-abs tolerance is the f16-rounding
hair, not slack in the format.
