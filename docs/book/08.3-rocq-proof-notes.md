# rocq/ -- what each proof mirrors, and what it does not claim

`rocq/README.md` says *what each module proves*; this file says *what code it
mirrors, why the model is faithful, and what is deliberately not claimed*. Keep
it in sync when a module's anchors move.

**Every anchor here is a symbol name, never a line.** The tree moves faster than
a transcribed line number survives, and a stale `file.rs:1079` points at a `}`
or at an unrelated call that reads as if it were the subject. Anchors go stale
anyway -- when a symbol is renamed -- but a wrong name fails a grep, where a
wrong line silently succeeds.

The four `Gen*.v` modules are excluded -- `GenTraffic.v` and `GenRoofline.v`
from `gen/gen.py`, `GenClaims.v` from `gen/claims.py`, `GenLaunch.v` from
`gen/extract/launch_geometry.py`. Each emits its own provenance header (config
paths, machine constants, the measurement log the numbers came from). Read that
header in the generated file; do not copy it here. They are the modules that
cannot rot: their constants are extracted rather than transcribed, and
`gen/run.sh --check` fails when a generated file and the source it describes
drift apart.

## WindowClamp.v

The clamped iteration range in `tree_verify_attn.cu` equals the mathematical
sliding-window attention set, for all positions.

Source anchors: the Rust reference predicate `tree_window_attends` (`gemma4.rs`)
-- `kpos > qpos -> false` (causal), `window <= 0 -> true` (full attention), else
`qpos - kpos < window`; the kernel's committed-prefix clamp
(`tree_verify_attn.cu`) -- `qpos = (window > 0) ? positions[qi] : 0`,
`win_start = max(0, qpos-(window-1))`, loop
`for (p = win_start + warp; p < nc; p += kWarps)`, so the committed keys visited
are exactly `{p | win_start <= p < nc}` (the warp stride partitions, it does not
skip); the kernel's tree-token clamp -- skip if `mask[qi*K + j] == 0`, skip if
`window > 0 && qpos - positions[j] >= window`; and per-layer window selection
`tree_layer_window` (`gemma4.rs`), sliding layers passing `sliding_window` (> 0)
and full layers passing 0.

Committed rows are stored contiguously with row index == absolute position
(`tree_verify_attn.cu`'s own layout contract), which is why the committed-key
position *is* the loop index `p`. Queries live at absolute positions `>= nc`
(they extend the committed prefix) -- that is the `nc <= qpos` hypothesis.

`cap_retains_attended` is the geometric fact that makes window-capped KV
storage sound: a buffer retaining the `cap` most recent positions
(`cap >= window`) retains every key any query can attend. `KvBudget.v` builds on
it.

## KvBudget.v

Faithful ports (the Rust being mirrored):

| Model | Rust |
|---|---|
| `kv_window` | `chat_engine.rs` |
| EAGLE3 constants (`K_MIN=2`, `K_MAX=64`, `K_DEFAULT=4`, `SPEC_VERIFY_HEADROOM=16`) | `chat_engine.rs` |
| `spec_verify_cache_len` | `chat_engine.rs` |
| `verify_cache_capacity` (grain 256) | `chat_engine.rs` |
| `assert_kv_window_invariants` (the Kani/CPU-test contract these theorems subsume) | `chat_engine.rs` |
| `assert_kv_step_in_bounds` | `chat_engine.rs` |
| per-layer window cap | `gemma4.rs` |
| `SLIDING_COMPACT_SLACK = 256` | `gemma4.rs` |
| fp8 KV per-row bytes | `gemma4.rs` |
| block-granular hybrid pool `PagedPoolConfig::from_gemma4_hybrid` | `paged_fp8.rs` |

Cap policy: `cap = max_seq` for full-attention layers, `cap = min(max_seq, w +
SLACK)` for sliding layers (`w = 1024`). Geometry from `gemma4.rs`: 60 layers =
50 sliding (16 KV heads x 256) + 10 full (4 x 512) => 8320 B/token sliding,
4128 B/token full, 457280 B/token uniform -- matching the boot line
`per_block_kb=7316.48` byte-exactly.

The 256-slot slack covers in-flight verify rows (`K <= EAGLE3_K_MAX = 64 << 256`)
before compaction. The `+1` spare block in `window_blocks` means the pool always
covers the window plus at least one in-flight block of new writes; sliding layers
take `min(window_blocks, full_blocks)` (`paged_fp8.rs`), never more than
the full layers' allocation, mirroring `layer_cap`'s `min`.

The base footprint is counted in full even though it already *contains* the
current caches -- conservative on purpose.

**Integer semantics.** Rust `usize` arithmetic here never overflows or
underflows in-domain (the subtraction in `kv_window` is guarded by the early
return; sizes are `< 2^40`). `usize` values are modeled as `Z` with `0 <= _`
hypotheses; `Z` floor division equals Rust `usize` division on non-negative
operands, so the ports are exact on the whole domain the Rust functions accept.

Supersedes `KvBudget.v`'s hybrid closed form. `KvBudget.v` models a
`window+256` ring; the shipped ring is
`window + VERIFY_PREFILL_CHUNK + VERIFY_RING_HEADROOM = 2176` slots, which is
what this module models. Where the two disagree, this one is current.

Code under formalization:

  for term: `ring_slots`, the vslots/dslots ring cap, fp8 bytes-per-row
  `2*stride + 2*nkv*4`, scratch, drafter, and the `KvBudget` struct fields.
- `gemma4.rs` -- `kv_fp8_ring_slots = sliding_window +
  VERIFY_PREFILL_CHUNK + VERIFY_RING_HEADROOM`.
- `gemma4.rs` -- `VERIFY_PREFILL_CHUNK = 1024`, `VERIFY_RING_HEADROOM = 128`.
- `gemma4.rs` -- `KvBudget::verify_total` / `decode_total` /
  `worst_total` (verify + decode + drafter summed as the conservative
  cross-request worst case).
- `chat_engine.rs` -- `enforce_gemma4_vram_budget`: refuse startup when
  measured weights + `worst_total` exceed `NV_VRAM_BUDGET_GIB` (default 76).
- `chat_engine.rs` -- `drafter_row_elems = scorer.config().kv_out_dim()`.
- `eagle3_loader.rs` -- `kv_out_dim = num_key_value_heads * head_dim =
  16 * 256 = 4096`.
- `gemma4.rs` -- `attention_tree` refuses a single append of `k` rows
  unless `k <= ring - window + 1`. Every chunked-prefill append is at most
  `VERIFY_PREFILL_CHUNK` rows on both the spec and non-spec prefill loops in
  `chat_engine.rs`, and the merged ring is sized so that bound can never fire on
  those paths, with 129 slots to spare.
- `chat_engine.rs` -- the spec-path chunk selector
  clamps to `[16, 65535]` then `.min(VERIFY_PREFILL_CHUNK)`, so *any* env value

Shapes are the same environment as `GenTraffic.v` / `KvBudget.v`: 60 layers (50
sliding nkv=16 hd=256, 10 full nkv=4 hd=512, pattern 5:1), `sliding_window`
1024, `max_position_embeddings` 262144.

Key values: one 262144-window request's verify cache is 10.953 GiB (10.921 GiB
slabs + 32.5 MiB compact scratch) -- k256-validate's measurement agrees to a
fraction of a percent. Worst-case simultaneous per-request KV is
27,782,103,040 B = 25.874 GiB, matching the measured ladder's entry
(measurements: `perf/runs.jsonl`). The gate passes at the
full-window default: weights plus worst KV land under the 76 GiB bound.

**Honesty.** The Rust gate compares f64 GiB values (`chat_engine.rs`);
this module compares exact bytes. At tens of GiB the f64 rounding of `x / 2^30`
is `< 1e-6` GiB and the measured-weights term is only nvidia-smi-precise (MiB)
anyway, so the byte-exact statement is the stronger and honest one.
`weights_measured_bytes` is a measured constant (38200 MiB, the process after
model + drafter load), not derived -- so it is only as current as the last time
someone re-measured it.

## AcceptSoundness.v

In the greedy regime, the shift-mode accept rule (accept iff drafted token ==
verify-row argmax) emits EXACTLY the sequence the target model would emit
decoding alone -- for every draft the drafter can possibly produce. This is the
greedy case of the distribution-preservation theorem (spec §2 Tier B), the case
the production default (temp 0 / greedy sampler) actually runs.

Source anchors, all in `src/oapi/chat_engine.rs`. The on-device accept rule
takes row `i` iff `batch[i] == amax[i-1]`, where `amax[i-1]` is the argmax of the
target logits after consuming `batch[0..=i-1]` -- the token the target itself
would emit after that prefix. On reject, the row argmax becomes the next round's
bonus, and the row argmax is exactly the CPU path's rejection replacement (the
residual of a point mass); when all rows are accepted the bonus is `amax[k-1]`,
pure greedy, `draw_from_logits` over a point mass being the row argmax. The CPU
path agrees in the greedy regime: `Sampler::accept_draft` accepts iff drafted ==
`argmax(row)` and replaces with `argmax(row)`. The initial bonus is drawn from
the prefill logits, i.e. `next(prompt)` -- the `bonus = next ctx` hypothesis of
the main theorem.

Emission order is bonus first (verify row 0), then accepted drafts in order,
with the loop breaking at the first reject. One expression covers the next
round's bonus in BOTH the reject case (replacement = rejecting row's argmax) and
the all-accepted case (`amax[k-1]`), because in both the round ends with the
bonus equal to `next(committed)`. Early termination (max_new / EOS / stop
strings, breaking mid-round) emits a PREFIX of the round-concatenated stream,
and every prefix is itself the greedy stream of its own length.

`draft_fn` may inspect the whole committed context and the bonus and produce ANY
drafts of ANY length -- this covers the real EAGLE-3 drafter, a broken drafter,
an adversarial drafter, and K-1 = 3 chain drafts alike.

**Honesty.** `next : list token -> token` models the target as a function from
committed context to greedy next token. Determinism of `next` is where "exact
arithmetic" enters: on the GPU, bf16 near-tie trajectories can flip under
kernel-shape changes, and `forward_decode_logits` breaks argmax ties
LAST-vs-FIRST differently from the CPU sampler. Both are outside this model,
which assumes ONE well-defined argmax; under that assumption the theorem is
exact and unconditional in the drafts. Tokens are `nat`; nothing depends on the
token type beyond decidable equality.

## ChunkedPrefill.v

Code under formalization:

- `chat_engine.rs` -- spec-prefill while loop:
  `len = prefill_chunk.min(initial_len - committed); committed += len`.
- `chat_engine.rs` -- non-spec prefill loop, same shape with
  `c = (prompt_ids.len() - off).min(VERIFY_PREFILL_CHUNK)`.
- `chat_engine.rs` -- `last = committed + len == initial_len`;
  `logit_rows = if last { 1 } else { 0 }`.
- `gemma4.rs` -- `forward_verify_tail` (logit_rows plumbed) and
   `forward_verify_dev_rows` (lm_head over `logit_rows` rows only).
- `gemma4.rs` -- `VERIFY_PREFILL_CHUNK = 1024`.

Why it matters: running the lm_head over EVERY prompt row costs ~1.6 MiB/token
of device transients (22.8 GiB at a 14.5k prompt, enough to 500 a full-window
spec request), and a drafter context encode that materializes O(ctx^2) scores is
the same shape of bug. The chunked loops make the per-forward working set a
function of the CHUNK instead. The three proved pieces: `chunk_pieces p c`
partitions `p` into pieces each `1 <= piece <= c`; any transient model
`t(rows) = a*rows + b` with `a,b >= 0` peaks over the loop at `t(c)`,
independent of `p`; the seed/logits transient is O(vocab) charged once (only the
last piece computes logits, over 1 row) vs the pre-fix O(vocab · p) -- a constant
512 KiB vs ~7.08 GiB of lm_head output rows at the 14500-token repro, a 14500x
improvement.

**Honesty.** "transient(rows) is affine in rows" is a MODEL of the per-chunk
allocations (activations k x hidden per layer, quant buffers, aux rows), cited to
the code and consistent with the adv-eagle measured slope (2.09 -> 1.01 MiB per
prompt token after the seed-row fix); it is not extracted from the Rust. The
theorem is the structural guarantee: WHATEVER the affine constants are, the peak
is set by the chunk.

## Roofline.v

An axiomatized hardware model plus the theorem that no schedule of one verify
forward can beat the weight-bandwidth floor -- hence a hard ceiling on tokens/s
parameterized by measured acceptance. This is the strongest honest form of "this
cannot be accelerated further": it bounds EVERY possible kernel schedule, not
just ours.

THE HARDWARE MODEL IS AXIOMATIC by nature. The two `Definition`s are the physics
assumptions, taken as hypotheses of every theorem -- so the development is
assumption-explicit, and `Print Assumptions` shows only the classical-real axioms
of Stdlib's `R`:

1. **`respects_bandwidth`** -- data crossing the HBM interface at bandwidth `BW`
   bytes/s for `time` seconds is at most `time * BW` bytes. DRAM is a shared
   serial resource; this is the definition of bandwidth.
2. **`weight_traffic_lb`** -- one decode/verify forward must CONSUME every one of
   the `W` weight/static bytes (each parameter multiplies the activations at
   least once per forward -- dense NVFP4 GEMMs, no conditional sparsity on the
   verify path), and at most `L2` bytes can be served from on-chip residency
   carried across forwards; the rest must cross HBM each forward. Hence
   `hbm_bytes >= W - L2`. This is the classical red-blue pebble / min-traffic
   argument specialized to weights-larger-than-cache, in its weakest (hence
   safest) form: it credits the L2 with FULL retention and charges nothing for
   activations, KV, or write traffic.

A `forward_exec` is one forward abstracted to `(hbm_bytes, wall_time)`. A
"schedule" (kernel fusion, tiling, graph capture, overlap, ...) only changes WHICH
pair is realized. The speed-of-light step: one decode round contains at least one
verify forward, so its period `T >= wall_time f`; the round emits `tpr` tokens
(`E[accepted] + 1` bonus), so `r * (W - L2) <= r * (wall * BW) <= r * (T * BW) =
tpr * BW`.

**Honesty.** `Measured.*` in this module are a hand-entered operating point,
including a 256 MiB L2 placeholder that is a deliberately generous UPPER bound
on cross-forward residency (a larger L2 only WEAKENS the bound, never
invalidates it). **Do not read the ceiling off this module.** Its 18.3 GB
per-verify-pass estimate undercounts the bf16 attention stream; the
checkpoint-derived figure is 31.48 GB, which moves the honest ceiling from 218
tok/s to 134. Every theorem above the constants is parameterized, so
re-instantiation is a constant swap, and `GenRoofline.v` carries the generated
instances -- extracted rather than transcribed, and therefore the ones to
quote.

## StreamK.v

Code under formalization:

- `nvfp4.rs` -- `CUTLASS_SM120_TILE_{M,N,K} = 128`.
- `nvfp4.rs` -- `NV_NVFP4_STREAMK` env: `0`/`1`/`auto`.
- `nvfp4.rs` -- `streamk_wanted`: auto routes iff
  `ceil(m/128) * ceil(n/128) <= 192` (m,n tiles of the DP grid).
- `nvfp4.rs` -- Stream-K launch, sticky DP fallback on failure
  (`streamk_failed`).

The question this module answers formally -- *does the reduction-split change the
traffic formula's assumptions?* NO, for two machine-checked reasons:

1. **Weight traffic is invariant under K-partition.** Stream-K splits the K range
   of one output tile across CTAs; each weight element belongs to exactly one
   K-slice, so summed over the slices the weight bytes read equal the unsplit
   GEMM's (`streamk_weight_traffic_invariant`). The `kernels.json` manifest term
   `n*k*(0.5+1/16)` therefore counts Stream-K and DP executions identically.
2. **The floor theorems quantify over every execution.**
   `Roofline.verify_time_lower_bound` is `forall f, ...`: a Stream-K execution is
   just another `forward_exec`. Stream-K's ADDITIONAL traffic (partial
   accumulator tiles spilled to the 64 MiB workspace, `nvfp4.rs`, and
   their reduction reads) only INCREASES `hbm_bytes`, which cannot break
   `weight_traffic_lb`, a *lower* bound on `hbm_bytes`
   (`streamk_extra_traffic_preserves_floor`).

Decision table at the verify GEMM shapes (m padded to 128 by the verify graph;
only the NVFP4 MLP GEMMs reach this router -- attention projections and lm_head
are bf16 and use the dense path):

| GEMM | n | tiles | route |
|---|---|---|---|
| `gate_up` | 43008 | 336 | DP |
| `down` | 5376 | 42 | Stream-K |

(Measured route effects: `perf/runs.jsonl`.)

What Stream-K changes is the measured side (the `r` in "within r of light"),
not the floor. Those numbers land in the regenerated `GenRoofline.v`, not
here.

**NOT claimed here:** that Stream-K is optimal, or that the fp4 MLP GEMMs are the
only routed shapes *because of* dtype. The attention projections are bf16
(checkpoint `quantization_config.ignore`, see `GenTraffic.v`) and never enter
`Nvfp4GemmRunner` at all -- that is a code-path fact cited, not proved.

## RoPE.v

The relative-position property of rotary embeddings, stated so that it actually
covers the pairing our kernels use rather than the one the paper writes down.

Code under formalization:

- `nv-layers/src/rope.rs` -- table construction:
  `theta = p * inv_freq[i]`, `cos_host[p*half+i] = cos theta`. This is the
  `rope fs m` of the model: pair `i` of a head at position `m` is rotated by
  `m * fs[i]`.
- `nv-layers/src/rope.rs` -- the candle path's pairing:
  `half = head_dim/2`, `lo = x[..half]`, `hi = x[half..]`,
  `out = cat(lo*cos - hi*sin, lo*sin + hi*cos)`. **HALF-SPLIT**, i.e. pair `i`
  is `(x_i, x_{i+half})`, matching HuggingFace `rotate_half`.
- `nv-kernels/cuda/rope.cu` -- the CUDA path's pairing, identical:
  `a = q[base+pair_idx]`, `b = q[base+pair_idx+half_dim]`.
- `nv-models/src/gemma4.rs` -- partial rotary by zero-padding:
  `rope_angles = min((partial * head_dim / 2) as usize, half)`, `inv_freq` is
  `vec![0f32; half]` with only `[..rope_angles]` filled. Matches the reference
  `_compute_proportional_rope_parameters`.
- `nv-models/src/gemma4.rs` -- sliding layers get the full table
  (`partial_rotary_factor` defaults to 1.0, `gemma4.rs`).
- Shapes: `global_head_dim = 512` for full-attention layers
  (`gemma4.rs`), `partial_rotary_factor = 0.25`
  (`nv-models/tests/gemma4_loader.rs` asserts it on the shipped config), so
  `rope_angles = 64` of `256` pairs rotate and 192 are the identity.
  `head_dim = 256` for sliding layers, full rotary, 128 pairs.

**RoFormer specifies INTERLEAVED pairs `(x_2i, x_2i+1)`; we do not implement
that.** Transcribing the paper's formula and asserting our code satisfies it
would be false, so the module does not. What it proves instead is the bridge:

1. `pairing_invariance` quantifies over an abstract assembler
   `asm : list pairv -> list R` satisfying `faithful asm` (assembly preserves
   the inner product), and shows `<asm(R_a x), asm(R_b y)> = <asm(R_{a-b} x),
   asm y>`. The *same* `asm` appears on q and on k -- that side condition is
   the whole content.
2. `any_pairing_faithful` discharges `faithful` for every *joint* coordinate
   permutation, via `sumprod_perm` / `dot_perm` (a dot product is invariant
   under any reordering of the coordinate pairs, `Permutation` on
   `combine u v`). So "any pairing" is proved, not assumed.
3. `halfsplit_perm_interleave` shows our half-split layout is a joint
   permutation of RoFormer's interleaved one, giving `halfsplit_faithful` and
   `layout_equivalence`: at the level of the *pair view*, the two conventions
   produce identical attention scores. `halfsplit_neq_interleave` records that
   the two flat vectors are nonetheless different objects.
4. `mixed_pairing_unsound` is the falsification: with two pairs, angles
   `PI/2`, `X = [(1,0);(0,0)]`, `Y = [(0,0);(1,0)]`, `a = 0`, `b = 1`, scoring
   a half-split q against an interleaved k gives `0` where the relative-position
   form gives `-1`. The side condition is necessary, not decorative.

Partial rotary:

- `rope_zeros` -- a zero frequency is the identity rotation (`rot 0 = id`).
- `partial_tail_identity` -- with `padded A h = A ++ repeat 0 (h - |A|)`, the
  padded pairs come out of `rope` byte-for-byte unchanged.
- `partial_relative_split` -- the score on the MIXED table decomposes as
  `pdot (rope A (m-n) XA) YA + pdot XB YB`: a relative-position term over the
  rotated block, plus a term over the unrotated dims that does not mention
  `m` or `n` at all. `partial_tail_position_independent` states that
  consequence directly (equal `m - n` implies equal score).
- `gemma4_full_rope_angles : rope_angles 1 4 512 = 64` and
  `gemma4_full_identity_pairs : 512/2 - 64 = 192` pin the 0.25 config;
  `gemma4_full_partial_relative` and
  `gemma4_full_partial_pairing_invariance` are the instances at 64 rotated /
  192 identity pairs, the latter through the half-split assembler.

**Scope limits.**

- The proof binds a `.v` definition of RoPE, **not** `cuda/rope.cu` and not the
  wgpu shader. Nothing here is extracted from or checked against those sources.
  The kernels are gated by `parity_rope.rs`, `parity_rope_bf16.rs` and
  `wgpu_rope*.rs`; this module is not a substitute for them and does not make
  them redundant. The `rope.rs`/`rope.cu` line citations above are a *reading*
  of that code, transcribed by hand.
- Everything is over exact `R`. The shipped `cos`/`sin` table is `f32`
  (`rope.rs`), which carries 1.2e-2 cos error at ctx 262143. These
  theorems say nothing about that drift: they hold of the real-valued angles,
  and a table built in f32 satisfies them only up to its own error. In
  particular `rope_compose` (`R_a . R_b = R_{a+b}`) is exact here and is *not*
  exact in the shipped f32 table.
- `layout_equivalence` is a statement about the pair view. It does NOT say a
  half-split checkpoint and an interleaved checkpoint are interchangeable --
  the projection weights decide which coordinate lands in which pair, and
  permuting the layout without permuting `W_q`/`W_k` changes the pair view and
  therefore the score. The theorem is: given the same pair view, the layout is
  invisible to attention.
- The model is one head. Heads, batching, GQA head-count mismatch between q and
  k, and the `positions` gather are all outside it. So is softmax, scaling, and
  everything downstream of the q-k inner product.
- `rope` is total in the length of the frequency list: a table shorter than the
  head is treated as identity on the tail. That is a modelling convenience;
  `from_inv_freq` (`rope.rs`) *rejects* `inv_freq.len() != half` at
  runtime, so the shipped code never takes that branch.
- Falsifiability is checked rather than assumed: eight planted defects (sign
  flips in `rope_relative` and `rot`, `repeat 0` -> `repeat 1` in `padded`,
  weakening `mixed_pairing_unsound` two ways, dropping the rotation from `rope`,
  `64` -> `65` active angles in the Gemma4 instance, and asserting `rope` is the
  identity) each break the build.

## TrainBackward.v -- the training backward and LoRA algebra, at the layout level

Matrices are flat buffers (`Buf := nat -> R`) indexed by the `i*cols + j`
row-major flattening (`idx`). Every GEMM in the module is DEFINED on flat
indices (`c / n`, `c mod n`), so a transposed copy, a swapped operand, or a
wrong leading dimension is not a different reading of the same theorem -- it is
a different function, and the theorems stop being provable about it.
`transposed_copy_backward_is_not_the_adjoint` demonstrates that concretely.

Code under formalization:

- `nv-quant/src/matmul.rs` -- `TensorCoreGemm::bf16_matmul_row_major_bt_offs`,
  the serving bf16 transposed-B GEMM. `linear.rs` `matmul_bf16` reaches it only
  on its dense route: at `leading == 1` (the decode hot path) it returns early
  into `matmul_bf16_gemv`, a custom kernel OUTSIDE this model, unless
  `force_dense` / `force_dense_bf16_enabled` / `NV_LINEAR_BF16_FORCE_CUBLAS`
  flips it to cuBLAS; when a cached `weight_t` is present it routes to
  `bf16_matmul_row_major_offs` (the nn config below) with the pre-transposed
  weight copy; at `2 <= leading <= 16` under `small_m_det_enabled` it takes
  `bf16_matmul_row_major_bt_det_offs`, the same contract on the deterministic
  path. `matmul_bf16_rows` has the same gemv-first shape ahead of its own
  `bt_offs` call. The `MatmulConfig` literal --
  `transa: true, m: n, n: m, k, alpha, lda: k, ldb: k, beta, ldc: n`, operands
  `(w, x)` -- is transcribed field-for-field into `bt_offs_cfg`, and every
  transcribed field is load-bearing: `cublas_cm` computes only inside the
  `cm_m x cm_n` output block and leaves C untouched outside it
  (`cublas_cm_writes_only_the_m_by_n_block`), so un-swapping the `m: n, n: m`
  pair back to the natural-looking assignment makes the theorem unprovable
  and breaks the build. `bt_offs_config_realizes_alpha_x_wt_plus_beta_c`
  proves the column-major swap trick realizes
  `y[i*n+j] = alpha * sum_p x[i*k+p] * w[j*k+p] + beta * c0[i*n+j]` on that
  block, i.e. `y = alpha * x W^T + beta * C` with `W` row-major `[n][k]`;
  `bt_offs_config_realizes_x_times_w_transposed` is the instance at the
  `alpha = 1.0, beta = 0.0` every serving call site passes (`matmul_bf16`,
  `matmul_bf16_rows`, `matmul_bf16_det` in `linear.rs`, and
  `deepseek_ocr/decoder_graph.rs`). The cuBLASLt column-major semantics
  itself (`cublas_cm`: element `(r,c)` at `r + c*ld`,
  `C = alpha * op(A) . B + beta * C` on the `m x n` block) is the modelling
  assumption; `transb: false`, `transc: false` and the `None` strides are
  baked into that assumption (B's access pattern and the flat output
  decomposition), not independently mutable fields; the config arithmetic on
  top of it is what is proved.
- `nv-quant/src/matmul.rs` -- `bf16_matmul_row_major_offs`
  (`transa: false, lda: n`, operands `(b, a)`), the plain row-major GEMM:
  `nn_offs_config_realizes_alpha_x_b_plus_beta_c` (serving instance
  `nn_offs_config_realizes_x_times_b`) proves it realizes
  `c[i*n+j] = sum_p a[i*k+p] * b[p*n+j]` -- byte-for-byte the loop of the CPU
  reference `cpu_bf16_matmul_row_major`, which is `gemm_nn_at`'s statement.
- **Bf16LinearOp** (`nv-layers/src/linear.rs`, a candle `CustomOp1`): fwd is
  the row-major transposed-B GEMM (`bf16_matmul_row_major_bt_offs`), bwd
  computes `dx = dy * W` via the non-transposed row-major GEMM
  (`bf16_matmul_row_major_offs`), and the weight lives inside the op as a
  struct field, so it is not a graph argument and candle builds no gradient
  for it. `gemm_bt_backward_is_adjoint` is the
  orientation theorem: `<bwd(dy), dx> = <dy, fwd(dx)>` for all `dy`, `dx`.
  `bf16linearop_backward_computes_the_gradient` is the "for all L" form: if `L`
  has gradient `G` at `y = fwd(x)` (in the `derivable_pt_lim` directional
  sense, `has_grad`), then `L . fwd` has gradient `bwd(G) = dy*W` at `x`.
  `backward_contract_is_the_unique_adjoint` closes the escape hatch: ANY map
  satisfying the adjoint equation agrees with `gemm_nn _ w k n` on every
  in-range index, so no differently-oriented implementation can satisfy the
  statement.
- `nv-weights/src/lora_adapter.rs` -- `LoraLayerWeights::optimize`, the
  load-time `scaling` fold (`lora_b.affine(scaling, 0.0)`, then
  `scaling = 1.0`): `optimize_scaling_fold_preserves_delta` proves the folded
  and unfolded deltas agree at every output index for every input.
- `nv-train/src/lib.rs` -- `lora_delta_raw` (`x.matmul(a.t())` then
  `.matmul(b.t())` then `* scaling`) and `TrainingLoraHook::apply`, plus
  `LoraSlotStack::delta` (`nv-layers/src/lora_slots.rs`), all the same
  `delta = s * ((x A^T) B^T)` shape with `A` row-major `[r][k]`, `B` row-major
  `[n][r]`. `lora_backward_is_adjoint` / `lora_backward_computes_the_gradient`
  prove the backward candle autograd derives from that graph --
  `dx = ((s*dy) B) A`, which is `((dy) B) A` once `optimize` has folded `s` --
  is the adjoint and the true gradient. `hooked_linear_backward_*`: the full
  Linear-with-hook forward `y = x W^T + delta(x)` backprops exactly
  `dx_base + dx_delta`.
- `nv-kernels/wgsl/lora_grouped.wgsl` / `lora_fused.wgsl` -- the shrink stage
  multiplies `scale` into the rank-space buffer (`acc * lg_p.scale`,
  `lf_h[r] = ... * scale`) while the algebraic spec scales the delta:
  `scale_in_shrink_equals_scale_on_delta` proves the placement equivalent.
- `nv-train/src/lib.rs` -- `lora_delta_raw`'s `b.narrow(0, off, rows)` under
  `win`, feeding `Linear::forward_rows`' windowed output: for a contiguous
  row-major `B`, narrowing rows `[off, off+rows)` is the flat shift by `off*r`,
  and `window_narrow_is_column_restriction` proves the windowed delta equals
  columns `[off, off+rows)` of the full delta.

**Faithfulness.** The Rust GEMM entry points are transcribed as their
`MatmulConfig` field values, not their kernels: what is proved is that the
transcribed configuration under column-major semantics computes the row-major
contract, which is exactly where operand-swap and lda/ldb bugs live. The
candle-autograd side (`.t()`, `.contiguous()`, `matmul` backward) is not
extracted; `lora_bwd` is the composition candle's rules produce for the
transcribed forward, and the adjoint theorems are what make any OTHER
composition unprovable.

**NOT claimed.**

- Nothing about floating point. All theorems are over exact `R`; bf16
  rounding, f32 accumulation order, split-K reduction order, and cuBLASLt's
  internal tiling are all outside the model (Flocq is out of scope for this
  development). The theorems bind index arithmetic and algebra, not rounding.
- No gradient with respect to `W`, `A`, or `B` is stated. The Bf16LinearOp
  spec deliberately keeps the weight out of the graph (`dx` only); `dA`/`dB`
  for the LoRA path are candle's business and are not modelled.
- The prompt-masked loss the parallel workflow is landing in nv-train is not
  modelled here at all.
- `has_grad` states directional-derivative gradients over `R`; existence of
  `L`'s gradient is a hypothesis, not a construction.
- The dropout branch of `TrainingLoraHook::apply` (train-time mask) is not
  modelled; the theorems cover the `dropout = 0` path that
  `attach_window_loras` ships with (`lora_dropout: 0.0`).
- `matmul_bf16_gemv` (the `leading == 1` decode route) and the correctness of
  the cached `weight_t` pre-transpose are outside the model: the theorems
  bind the two cuBLASLt configs, not the code that runs when `matmul_bf16`
  takes the gemv early return or the `weight_t` nn route. `nvk::gemv_bf16` is
  gated against a CPU reference by `pdl_norm_gemv_chain_matches_cpu`

Falsifiability is checked, not assumed: planting `lda: n` in `bt_offs_cfg`
(the wrong leading dimension), un-swapping its `m`/`n` fields

`transposed_copy_backward_is_not_the_adjoint`.

## LoraSlices.v -- fused-slice offsets and the gated-q lane split

Code under formalization:

- `nv-kernels/src/wgpu_backend/kernels/lora.rs` -- `build_meta`: `slice_start`
  is the running cumsum of the width table (`acc += w`), `b_off` the cumsum of
  `max_loras * w * rank`, `b_d0 = w * rank`. The module's `slice_start` is
  that fold (`list_sum (firstn s ws)`).
- `nv-kernels/wgsl/lora_grouped.wgsl` `lora_expand` -- the write
  `yi = row * y_row_stride + slice_start[slice_id] + n`, `n < curr_n`:
  `sliced_write_equals_monolithic` proves the assembled output at
  `slice_start[s] + j` is exactly the per-slice GEMM value `D s j`, for an
  ARBITRARY width table, unequal widths included --
  `every_output_column_lands_in_one_slice` and `slice_decomposition_unique`
  make the offset arithmetic a bijection, which is the fact an off-by-slice
  bug would falsify. `uniform_stride_offsets_are_not_the_cumsum` refutes the
  tempting `s * max_width` stride on a two-slice unequal table.
- `nv-kernels/wgsl/lora_fused.wgsl` `lora_fused` -- the windowed write
  `col = s_start + nl`, live iff `win_off <= col < win_off + win_len`, stored
  at `col - win_off`: `windowed_write_equals_monolithic`.
- `nv-train/src/lib.rs` -- `FusedSplitHook::apply`, the CPU shape of the same
  thing: per-part zero-padding (`left = off`, `right = out - off - rows`) and
  summation. `pad_contrib`/`fused_padded_sum` transcribe that padding-sum
  form, and the main theorem shows the sum collapses to the single owning
  slice when the offsets are the cumsum.
- `nv-specdecode/src/lora_spec.rs` `WgpuLoraRuntime::install_gemma4_qkv` and
  `nv-models/src/train_runner.rs` `build_targets` -- the GQA width tables
  `[q_dim, kv_dim, kv_dim]` (offsets `0, q_dim, q_dim + kv_dim`) and
  `[inter, inter]` for `gate_up_proj`: `qkv_slice_offsets` and
  `gate_up_slice_offsets` pin the transcription, `q_dim <> kv_dim` allowed.
- `nv-models/src/qwen3_5_moe.rs` -- `load_attention`'s
  `q_out = n_heads * head_dim * 2` under `attn_output_gate`, and the eager
  split in `project_qkv`: reshape to `(b, t, n_heads, head_dim * 2)`, value =
  `narrow(3, 0, head_dim)`, gate = `narrow(3, head_dim, head_dim)`
  (`nv-train/src/qwen38.rs` `TrainAttn::forward` is the same split). In flat
  q_proj output columns: head `c / (2*hd)`, value lane iff
  `c mod (2*hd) < hd`. `value_lane_split` / `gate_lane_split` /
  `every_column_is_value_or_gate` prove the split indexing is a bijection onto
  per-head value/gate slots.
- `value_only_adapter_leaves_gate_lanes_unadapted`: an adapter `B` whose rows
  are zero on every gate-lane index contributes exactly zero to every gate
  column, so the sigmoid input is byte-identical to the base model's
  (`adapted_output_agrees_with_base_on_gate_lanes`). This is the positive
  direction of the gate-width constraint: a lane-aware adapter CAN leave the
  gate untouched.
- `corner_padded_half_width_b_adapts_the_wrong_lanes`: the hazard theorem.
  `LoraSlotStack::set_lora` (`nv-layers/src/lora_slots.rs`) accepts
  `b_rows < out_features` and `corner_pad`s the missing rows with zeros at the
  BOTTOM. For a gated q_proj (`out_features = nh * 2 * hd`), a B sized for the
  un-gated layout (`nh * hd` rows) therefore lands on rows `[0, nh*hd)` --
  which, for `nh >= 2`, provably contains gate lanes (row `hd` is one) and
  misses value lanes (row `(nh-1) * 2*hd` is one). The adapter silently
  modulates the sigmoid gates of the low heads and leaves the high heads
  un-adapted. This is the theorem behind the load-time reject the shipped
  gated consumer enforces: `Q3dLora::from_adapter`
  (`qwen3_5_dense_wgpu.rs`), the only LoRA consumer of a gated projection in
  the tree, refuses any gated q_proj adapter whose `lora_b.dim(0)` is not the
  doubled `q_out`, under
  `Q3D_LORA_Q_GATE_ADAPTER_MUST_COVER_VALUE_AND_GATE_LANES`, before
  `build_lora_site`/`set_lora` ever runs. The generic
  `LoraSlotStack::set_lora` keeps accepting `b_rows < out_features` BY DESIGN
  -- corner-padding is what lets un-gated stacks serve partial adapters -- so
  the guard belongs at the gated consumer's loader, not in the stack: a
  strict `b_rows == out_features` reject in `set_lora` would break the
  legitimate under-width uses, and a future gated consumer that wires
  adapters through the stack without its own loader-side guard re-opens
  exactly this hazard.

**Faithfulness.** The WGSL index expressions are transcribed by hand from the
shader source (`lora_expand`'s `yi`, `lora_fused`'s `col`/`win_off` test);
the kernels themselves are gated by `wgpu_lora.rs` / `lora_spec_wgpu.rs`
parity suites, and this module is not a substitute for them. The CUDA slice
path (`nv-kernels/src/lora.rs` `lora_expand`/`lora_fused`, `slice_start` /
`slice_n` device arrays built by the same cumsum in `lora_slots.rs`) shares
the offset scheme but its kernel bodies are not transcribed here.

**NOT claimed.**

- Exact arithmetic only: the bf16 encode/decode round trip in the shaders and
  the f32 rank-space buffer are outside the model (Flocq out of scope).
- The token-grouping half of the kernels (`LoraKernelMeta::prepare`'s sort,
  `token_indices_sorted`, per-lora grid z) is not modelled; the theorems fix
  one token row and quantify over output columns.
- `fused_padded_sum` models `FusedSplitHook`'s padding-sum for the cumsum

## Nvfp4Semantics.v

NVFP4 pack/dequant semantics and train/serve dequant agreement, over exact
`Z` (indices) and `Q` (values). The e2m1 nibble decode and the ue4m3 scale
decode are ABSTRACT functions `Z -> Q`: every theorem is about index
arithmetic, layout, and scale composition, and holds for any decode tables.

Source anchors, and what each side of the agreement transcribes:

- **Storage model** (`nv-quant/src/nvfp4.rs`): `BLOCK_SIZE` (= 16, two values
  per byte, 8 bytes per block), `pack_e2m1_pair` (`(hi << 4) | (lo & 0x0F)`,
  transcribed as `16 * hi + lo` -- bitwise-or of disjoint nibbles is addition,
  under the precondition both nibbles are in `[0, 16)`, which `encode_e2m1`
  guarantees by construction), `unpack_e2m1_pair` (`b mod 16`,
  `(b / 16) mod 16`), and the row-major layout of
  `Nvfp4Tensor::quantize_rows_with_global`: scale for block `(r, b)` is pushed
  at position `r * blocks_per_row + b`, packed byte for element `(r, j)` at
  `r * bytes_per_row + j / 2`.
- **Serving reference dequant** (the oracle the GEMMs are validated against):
  `dequantize_packed_linear` -- per block, `scale =
  decode_ue4m3(scales[r * bpr + b]) * weight_mult`, then
  `out[r*cols + b*16 + i*2 + p] = decode_e2m1(nibble) * scale`. This is the
  serving-side truth twice over: `dequantize_packed_swizzled` (= unswizzle
  then this) is the oracle of `m1_gemv_bf16act_matches_the_swizzled_dequant_oracle`
  (`nv-quant/tests/nvfp4_m1_gemv_ab.rs`), and `Nvfp4Tensor::dequantize` (same
  loop, no `weight_mult`) feeds `cpu_nvfp4_matmul_weight_row`, the oracle of
  `nvfp4_block_scaled_matmul_matches_cpu_dequant` (`nv-quant/tests/nvfp4.rs`).
  `serve_loop_val`/`serve_at` transcribe the loop; `loop_writer_unique` and
  `loop_covers` prove the loop writes each output index exactly once, so the
  functional model is the loop.
- **Scale swizzle** (`swizzle_scales`/`unswizzle_scales`, same file): `sw_dst`
  transcribes the destination formula digit for digit (`m_tile = m/128`,
  `d2 = (m/32) % 4`, `d3 = m % 32`, `k_tile = kb/4`, `d5 = kb % 4`,
  `dst = ((m_tile*k_tiles + k_tile)*32 + d3)*16 + d2*4 + d5`), with
  `m_tiles = div_ceil(rows,128)`, `k_tiles = div_ceil(k_blocks,4)` and buffer
  length `m_tiles*128*k_tiles*4`. The functional model `swizzled` (read the
  unique preimage if in bounds, else 0) is justified, not assumed:
  `sw_roundtrip` (g . f = id on in-bounds pairs), `sw_dst_complete`
  (f . g = id on the whole padded buffer), `sw_dst_injective` (no two writes
  collide), `sw_dst_range` (no write escapes the buffer). Together these say
  the loop's writes ARE the functional model, including the tail tiles when
  `rows` is not a multiple of 128 or `k_blocks` not a multiple of 4 -- the
  padding slots are exactly the out-of-preimage indices, they hold the
  `vec![0u8; ..]` initial value (`swizzle_pad_reads_zero`), and unswizzle
  never reads them for an in-bounds query (`unswizzle_swizzle_id`,
  `unswizzle_swizzle_flat_id`).
- **Training dequant, side 1** (`nv-train/src/qwen38.rs`):
  `HostDequantWeights::dense_matrix`, `ModuleStorage::Nvfp4Packed` arm --
  `weight_mult = 1/global` guarded (`weight_global_scale` read via
  `scalar_f32`, guard `global == 0.0 || !is_finite -> 1.0`), and the
  `par_row_blocks` slicing: chunk `bi` covers rows `[bi*block, bi*block +
  min(block, rows - bi*block))`, slices `packed[start*cols/2..]`,
  `scales[start*bpr..]`. `train_host_at` transcribes the composed index
  arithmetic including the Rust's `(start * cols) / 2` parse;
  `chunk_covers`/`chunk_exists`/`chunk_len_matches` prove the chunking
  partitions the rows and that `chunks_mut` piece lengths match what
  `copy_from_slice` requires. `par_row_blocks` refuses `rows = 0` and
  `cols = 0` through its `Result` (`ensure!` at entry -- `chunks_mut(0)`
  panics, so a zero-dim rank-2 weight must error, not abort), and
  `par_row_blocks_guarded_block_positive` proves `div_ceil` yields a
  positive chunk size on the whole admitted domain, discharging the model's
  `0 < blk` hypothesis for every shape the Rust lets through.
  `train_host_agrees_serve`: equal to the serving reference on every
  in-bounds index.
- **Training dequant, side 2** (`nv-models/src/train_runner.rs`):
  `Nvfp4DequantSource::get` -- packed nibbles live in `.weight` itself
  (`in_f = shape[1] * 2`), block scales in `weight_scale`, and
  `weight_mult = safe_recip(safe_recip(weight_scale_2))` -- the exact
  composition the serving side applies to the same checkpoint dialect:
  `nv-layers/src/moe.rs` `nvfp4_linear_from_disk_inner` with
  `Nvfp4Suffixes::GEMMA_MODELOPT` (`global_scale_is_inverse: false`) computes
  `stored = safe_recip(weight_scale_2)`, `weight_alpha = safe_recip(stored)`.
  Both transcribe to `qguard_inv (qguard_inv weight_scale_2)`
  (`train_runner_fixed_mult` = `modelopt_serve_alpha`, definitionally --
  `train_runner_fixed_mult_is_serve_alpha`), and
  `train_runner_fixed_agrees_serve` proves the training dequant equals the
  serving composition on every index, unconditionally. The double guard is
  load-bearing, not defensive: `modelopt_alpha_faithful` proves the
  double-recip collapses to `weight_scale_2` whenever it is nonzero
  (`train_runner_agrees_serve` on that class), while the guardless multiplier
  -- what `get` computed before the guard -- COMPUTES A DIFFERENT FUNCTION at
  `weight_scale_2 = 0`: training dequantizes the base model to all-zeros
  while serving falls back to multiplier 1
  (`train_runner_zero_scale2_collapses` / `serve_zero_scale2_is_unscaled` /
  `train_runner_raw_zero_scale2_diverges_from_serving`); dropping either
  `safe_recip` re-opens that divergence, and
  `train_runner_guarded_agrees_serve` covers the equivalent single-branch
  guard form.
- **Second serving path** (`nv-layers/src/moe.rs` `dequantize_nvfp4_to_bf16`,
  the sub-`MIN_TILE` fallback): same index arithmetic, grouping
  `decode * (block_scale * inv_global)` with `inv_global` under the same
  `== 0.0 || !is_finite` guard as `safe_recip` on the `MIN_TILE`-and-up path
  of the same checkpoint -- both halves transcribe to `qguard_inv`, so a
  small matrix and a large matrix get the same multiplier
  (`small_serve_agrees_serve`).
- **Tensor-scale grouping** (`Nvfp4Tensor::dequantize_scaled` and
  `nv-weights/src/gguf.rs` `requantize_nvfp4_dense`, which computes
  `q.dequantize()` then multiplies `weight_alpha = 1/stored_global`):
  `(decode * block_scale) * alpha` vs the reference's
  `decode * (block_scale * alpha)` -- `grouping_immaterial_exact`, by
  associativity over `Q`.

Faithfulness. Rust `usize` division/modulo on non-negative operands is `Z`
floor division; every index hypothesis carries the non-negativity. `cols` is
modeled as `16 * q` with `0 < q` because `quantize_rows_with_global`,
`dequantize_packed_linear` and the wgpu loader (`laguna_wgpu/weights.rs`
`load_nvfp4`) all assert or ensure `cols % 16 == 0` -- there is NO tail-block
path in the packed layout; the only padding in the format lives in the
swizzled scale buffer, and that is where the tail theorems bite.
Falsifiability is checked, not assumed: five planted defects (swapping the
swizzle's `d2*4 + d5` digits, an off-by-one block scale index in the serving
dequant, `start*cols` for `start*cols/2` in the training slice, swapping the
lo/hi nibble decode order, and an untransposed backward in `TrainStepSpec.v`)
each break the build.

**Non-claims.**

- Nothing about floating-point values: `decode_e2m1`, `decode_ue4m3`,
  `encode_ue4m3` and all f32 arithmetic are abstracted into `Q`; Flocq is out
  of scope. In particular `grouping_immaterial_exact` is an exact-arithmetic
  statement -- the f32 groupings differ by rounding, and no bound on that
  difference is claimed.
- The `!is_finite` half of the Rust guards has no `Q` counterpart; the model's
  `qguard_inv` captures the `== 0.0` half. That every dequant path maps a
  NaN/inf global scale to multiplier 1.0 (rather than poisoning or zeroing
  the matrix) is therefore a code-reading claim about the shared guard shape,
  not a theorem; the `= 0` branch is the theorem.
- The quantize side (`encode_ue4m3` fitting, `closed_form_scale_byte`,
  clamping) is not modeled; round-trip value preservation through
  `requantize_nvfp4_dense` for exactly-representable values needs e2m1/ue4m3
  value semantics and is deferred.
- `par_row_blocks` thread scheduling, mutexes and the failure channel are not
  modeled; what is proved is that the chunk geometry writes each row exactly
  once with matching slice lengths. The model's `0 < blk` and `0 < q`
  hypotheses match the Rust's entry `ensure!(rows > 0 && cols > 0)`:
  the degenerate shapes are refused before the chunking they would break,
  and `par_row_blocks_guarded_block_positive` closes the gap between the
  guard and the hypothesis.
- The wgpu path's `input_global_scale` factor and everything the GPU does with
  the swizzled buffers is outside the model; the theorems stop at the byte
  layout plus host dequant the kernels are tested against.

## TrainStepSpec.v

Anchored to the landed Bf16LinearOp (`nv-layers/src/linear.rs`) and
prompt-masked loss (`ce_mean_over_unmasked_positions`,
`nv-train/src/lib.rs`): fwd is the row-major transposed-B GEMM
(`bf16_matmul_row_major_bt_offs`, `y = x . W^T`), bwd is `dx = dy . W` via
the non-transposed row-major GEMM (`bf16_matmul_row_major_offs`), and the
weight is a field of the op, not a graph argument.

`bwd_dx_is_adjoint_of_fwd` is the statement that makes that backward THE
correct backward for that forward: `<fwd(x), dy> = <x, bwd(dy)>` over exact
`Q`, all shapes, by sum interchange. `untransposed_fwd_breaks_the_adjoint`
is the falsification twin: pairing the same `dy . W` backward with an
untransposed forward (`x . W`) fails the identity on an explicit `1x2x2`
witness -- the transpose convention is load-bearing, not notational. Masked
loss: `prompt_positions_cannot_affect_loss` (losses at masked-out positions
are arbitrary), `fully_masked_batch_has_zero_sum_and_count` (the
divide-by-zero hazard of a mean over an all-prompt batch, stated so the
implementation must guard it), and `completion_mask_sums_exactly_the_completion`
/ `completion_count_is_completion_length` / `completion_boundary` (with mask
`p <= t`, position `p` is the first counted one -- the off-by-one home).

**Non-claims.** No statement about `dW` (the spec says the weight is not a
graph argument; the model simply has no weight gradient). Exact `Q` sums --
nothing about bf16 accumulation order or rounding. The label-shift convention
(which logit row is scored against which token) is not part of the fixed spec
and is NOT pinned here; if the landed loss shifts labels, the reconciliation
must add that layer or record it as unmodeled.

## PdlOrder.v -- the PDL happens-before obligation

Programmatic Dependent Launch lets a consumer kernel begin before its producer
drains. The safety rule lives in prose in
`nv-kernels/include/nvk_pdl.cuh`: `NVK_PDL_EPILOG` must follow the producer's
LAST write of every buffer a dependent reads. This module discharges that rule
as a theorem, which is the only form of it that survives a comment strip.

This is the one hazard in the development that testing is demonstrated unable to
see: planting the exact stale-read defect in `rmsnorm`'s epilog -- or in three
more epilogs, independently -- changes no test outcome. Everything else here is
catchable by a test, which is the standard a new module has to clear.

Theorems:

- `pdl_writes_precede_reads` -- under a monotone schedule, if the producer's
  epilog dominates its writes to `b`, the consumer's prolog precedes its reads
  of `b`, and the PDL edge holds, then every write time is strictly less than
  every read time.
- `unwired_neighbour_is_safe` -- a consumer without the launch attribute is
  serialized after the producer, so the ordering holds with no epilog
  hypothesis. Wiring one kernel of a pair cannot make things worse.
- `multi_output_needs_all_writes` -- the obligation holds for EVERY output
  buffer. This is the rule under which `quantize_nvfp4_bf16` and
  `rmsnorm_residual` are EXCLUDED from wiring rather than wired.
- `epilog_hypothesis_is_necessary` -- a concrete schedule in which the epilog
  precedes a write and a read consequently observes the stale value: the planted
  defect, formalised. It proves the main theorem is not vacuous.

`Print Assumptions` is **closed under the global context** -- zero axioms,
matching `WindowClamp` / `KvBudget` / `AcceptSoundness`.

What it does NOT claim: it binds a `.v` model, not the CUDA. The write set per
kernel is an explicit hypothesis extracted by hand, and that extraction is
precisely the step that fails in practice. This converts a silent hazard into a
visible, reviewable assumption; it does not verify the kernels. Deliberately out
of scope: capture-vs-replay divergence, and any graph performance model -- the
repo's own record (lm_head int8 projected -1.24 ms, measured +5.9 in-graph) is
the argument against formalising a cost model reality has already contradicted.

`rocq/build.sh` fails with `BUILD-LIST-INCOMPLETE` when a `.v` in the directory
is absent from its hand-ordered `MODS` list. The list stays hand-ordered because
the order is load-bearing (`KvBudget` needs `WindowClamp`, `StreamK` needs
`Roofline`, `GenRoofline` needs `Roofline` and `GenTraffic`); the completeness
check exists because a module missing from `MODS` reports `rc=0` having compiled
nothing.

## PdlKernels.v -- the obligation instantiated

`PdlOrder.v` proves the rule; this discharges it for the kernels that carry the
intrinsics: `residual_scale.cu`, `rmsnorm.cu`, `gemv_bf16.cu`, `rope_bf16.cu`,
`kv_fp8.cu`, `flash_decode.cu`. The pairs match the captured decode adjacency --
residual->rmsnorm, rmsnorm->gemv, gemv->rope, rope->kv_fp8, and kv_fp8->flash on
BOTH of its outputs. `kvfp8_both_outputs_covered` and `rope_both_outputs_covered`
apply `multi_output_needs_all_writes`.

The positions are DERIVED, in `GenPdl.v`, by `gen/extract/pdl_sites.py`;
`gen/run.sh --check` fails on drift. Write and read sets are
over-approximations -- every store, every dereference in the body -- so no one
hand-picks a last write, and `<k>_prolog_precedes_every_dereference` closes the
gap where a prolog moved below a read used to check clean. The census refuses on
any `NVK_PDL_PROLOG` or `cudaLaunchKernelEx` callee the manifest does not model;
it is what makes `flash_splitk_fused_fp8_derivev_kernel` -- prolog, no epilog,
no programmatic launch -- visible as `pdl_kernels_with_incomplete_wiring := 1`.

`PdlKernels.v` itself holds only the pairing theorems and imports `GenPdl`. The
declared half -- which `__global__` symbol each record models, and which logical
buffer each parameter carries -- lives in `gen/pdl_kernels.json`, witnessed by
the exact quoted source text of the parameter declaration rather than by a line
number. Structural facts the extractor cannot represent are a refusal with rc=1
and nothing written; *ordering* violations are emitted, so Rocq is what fails.

## LaunchGeometry.v -- the module that refutes shipped code

Every other module here encodes reasoning. This one encodes a constraint that
production code violated.

`kv_fp8_paged.cu` launched `dim3 grid(n_kv, len)` -- the sequence length on the
**y** axis. CUDA's `maxGridDimY` is 65535 while `x` allows 2^31-1, so the kernel
was capped at 65535 tokens of context on a stack whose
`max_position_embeddings` is 262144. A 160k-token prefill dies with
`cudaErrorInvalidConfiguration` (rc=9) at position 64512, because the next
`VERIFY_PREFILL_CHUNK = 1024` chunk makes `len` 65536 -- exactly one over. The
fix is `grid(len, n_kv)`; `n_kv` is 4 (full) or 16 (sliding) and fits `y`
trivially.

**The rule: the unbounded quantity goes on the `x` axis.** Of the
multi-dimensional `dim3 grid(` launches in the tree, the ones whose extent
scales with input are covered here; the rest place the unbounded quantity on `x`
already.

Theorems:

- `dequant_fixed_launchable` -- the corrected assignment is launchable for every
  `len` up to `max_position_embeddings`.
- `dequant_old_fails_inside_the_declared_context` -- an existence proof that the
  OLD assignment is unlaunchable at a context the model explicitly supports.
  That is the shipped bug as a theorem, and it is what makes this module
  different from the rest: it does not restate a rule, it refutes real code.
- `chunk_boundary_witness` pins the arithmetic (63*1024 = 64512 fits,
  64*1024 = 65536 does not).
- `depthwise_z_safe_when_tiled` and `depthwise_z_safe_at_tile_256` cover the
  only other launch whose z-extent scales with input,
  `depthwise_conv1d_silu_bf16.cu` -- safe because `tile_t >= 256`, but safe
  *conditionally*, which is now written down rather than assumed.

`Print Assumptions`: **closed under the global context.**

Written in Z, not nat, deliberately: in `nat`, `2147483647` compiles to
`Init.Nat.of_num_uint` and `lia` cannot see through it -- every bound fails with
"Cannot find witness". The rest of the development is Z-ported for the same
reason.

Scope: this module does not check the CUDA automatically, so adding a new
launcher with a length on `y` will not fail this build. `GenLaunch.v` is the
mechanical half -- grid assignments extracted from source rather than
transcribed -- and this bug is the argument for it.

## TrainLoss.v -- masked loss and windowed-training locality

The home of silent training-on-wrong-tokens bugs: which positions the loss
reads, what the mean divides by, and whether caching the frozen prefix can
change any gradient. Everything is over exact `R`.

Code under formalization (all anchors are symbols):

- **Masked loss**: `ce_mean_over_unmasked_positions` in `nv-train/src/lib.rs`
  -- masked log-prob sum divided by the unmasked count, the per-example mean
  CE over completion positions only; batch loss = sum of per-example means.
  An all-ones mask short-circuits to `candle_nn::loss::cross_entropy`, the
  `full_mask_metric_contract` collapse. The all-masked division hazard the
  theorems carry as `0 < masked_count` is refused in code: `ensure_mask_shape`
  bails on a row whose every target position is masked. `completion_mask`
  pins the polarity (`keep` iff `prompt_len <= t`).
- The unmasked form both trainers ship today, which the all-true-mask case
  must collapse to: `candle_nn::loss::cross_entropy` (mean over all
  prediction positions) inside `forward_loss` in `nv-train/src/qwen38.rs`,
  summed per example by `summed_holdout_ce` into the `eval_loss_adapter` /
  `eval_loss_base` fields the consolidation gate reads; and in
  `nv-models/src/dense_train.rs` the `denom = seq - 1` per-example mean of
  `chunked_ce` summed across the batch by `train_step_checkpointed`.
- Windowed training, `nv-train/src/qwen38.rs`: `run` / `run_jsonl` stream
  layers `0..window_start` (`window_start = num_hidden_layers - grad_layers`)
  once over every example, cache the hidden states, drop the layers, and
  train only the window; the two assertion-constants
  `THE_FROZEN_PREFIX_IS_CACHED_AS_HIDDEN_STATES_WHICH_IS_ONLY_SOUND_BECAUSE_NO_TRAINABLE_PARAMETER_LIVES_BELOW_THE_WINDOW`
  and
  `EVAL_ROWS_SHARE_THE_FROZEN_PREFIX_PASS_BECAUSE_NO_TRAINABLE_PARAMETER_LIVES_BELOW_THE_WINDOW`
  state the soundness argument in prose; `attach_window_loras` is what makes
  "no trainable parameter below the window" true by construction.

What is proved:

- `prompt_position_batch_invariant`: updating any logit at a `keep = false`
  position changes nothing -- the loss never reads it. `prompt_logit_grad_zero`
  is the derivative corollary: the map from that logit to the batch loss is a
  constant function, so its derivative is 0 at every point. This is the
  invariance form, deliberately stronger than a pointwise derivative claim.
- `full_mask_metric_contract`: with every position kept, `batch_loss` equals
  the sum of per-example plain means -- the metric contract. A masked-loss
  landing that breaks this changes what `eval_loss_adapter`/`eval_loss_base`
  mean and silently invalidates every stored gate threshold.
- `wrong_denominator_disagrees`: masked numerator over the ALL-positions
  count is a different function whenever any position is masked and the
  masked CE sum is nonzero. `masked_numerator_over_all_positions_separates`
  is the concrete witness: two positions with uniform 2-way logits, first
  masked -- correct loss `ln 2`, wrong loss `ln 2 / 2`. The per-example
  denominator must be `masked_count`, and `masked_count` counts kept
  positions only, by definition and by these theorems.
- `runL_app` / `frozen_prefix_cache_sound`: a layered fold splits at any
  layer boundary, so the full forward factors through the cached prefix
  output. `window_grad_locality`: for ANY path `R -> list P` through the
  window parameters (which covers per-coordinate partials, LoRA A/B factor
  directions, and joint directions alike), a value is the derivative of the
  truncated-graph loss iff it is the derivative of the full-graph loss --
  the soundness of the whole windowed design. `eval_rows_share_frozen_prefix`:
  the base eval and the adapter eval factor through the SAME cached tensor,
  which is the `EVAL_ROWS_SHARE_THE_FROZEN_PREFIX_*` constant as a theorem.

**Faithfulness.** An example is a list of positions, each carrying a keep
flag, a logits row, and a target index; `ce z y = ln (sumexp z) - z_y` is
softmax cross-entropy over a finite vocab list. Batch aggregation is the sum
of per-example means because that is what both shipped summations do
(`summed_holdout_ce` accumulates `total += mean_e`; `train_step_checkpointed`
accumulates `total_loss += loss_e`). The window model is a fold of
`P -> X -> X` layers over abstract hidden and parameter types -- the prefix
layers take fixed parameters that are not in the path, which is exactly
"holds no LoRA and no Var".

**Not claimed.** No floating point anywhere -- Flocq is out of scope for this
lane; every statement is exact `R`, and bf16/f32 evaluation satisfies them
only up to its own rounding. An example with zero completion positions makes
`example_loss` a division by zero (`INR 0`); the theorems that divide carry
`0 < masked_count` -- the implementation must refuse such rows, this module
does not decide that for it. The window theorems say nothing about the GDN
recurrence internals, RoPE positions, or activation memory (the
`THE_GDN_RECURRENCE_RETAINS_*` sizing constant is not formalized); they are
statements about parameter placement, not about any single layer's forward.

## CheckpointEquiv.v -- recompute-from-boundary backward and chunked_ce

Code under formalization, all in `nv-models/src/dense_train.rs` unless noted:

- `seq_backward_checkpointed` -- the exact bookkeeping: forward once storing
  DETACHED boundaries `h_0..h_N` (`boundaries`, one per layer edge); seed
  `grad_next` from `head_loss_grad`; loop layers top-down, each iteration
  recomputing one layer from `Var(boundaries[li])`, building the surrogate
  `sum(out * grad_next.detach())`, harvesting parameter grads from the
  surrogate's backward, and replacing `grad_next` with the surrogate's grad
  at the boundary input.
- `train_step_checkpointed` -- per-example gradient accumulation by
  summation.
- `head_loss_grad` -- `pred` is `normed` rows `0..seq-2` (`narrow`), targets
  are `ids[1..]`, and a `zero_row` is appended as the last row's gradient
  before the final-norm surrogate.
- `chunked_ce` -- the manual CE gradient: rows are processed in pieces of
  `chunk.min(rows - a)`; per piece `raw = hc.matmul(w.t())` with `w` the
  DETACHED `lm_head` weight, `z = cap*tanh(raw/cap)` when
  `final_logit_softcapping > 0`, `loss += -logp[target]/denom`,
  `gz = (softmax(z) - onehot)/denom` via `scatter_add`, `gz *= dcap` with
  `dcap = 1 - (z/cap)^2`, `ghc = gz.matmul(&w)`, and the pieces are
  `Tensor::cat`'d in order.
- `nv-models/src/train_runner.rs` consumes `train_step_checkpointed`
  (`NV_TRAIN_CKPT`), with LoRA `Var`s built over `attn_mlp_layers` targets.

What is proved (model: one real number per boundary, arbitrary layer count,
true real-analysis derivatives; `chain` is the forward, `ckpt` the loop):

- `surrogate_param_backward` / `surrogate_input_backward`: the surrogate
  `f * c` with `c` the detached `grad_next` has exactly the two derivatives
  the loop harvests -- `grad_next * (df/dtheta)` and `grad_next * (df/dh)`.
- `grad_next_is_dL_dboundary`: the propagated grad equals dL/dh_i at every
  boundary -- the loop invariant that makes the bookkeeping right.
- `checkpointed_param_grad_sound`: the entry `ckpt` emits for a layer IS the
  analytic derivative of the full-graph loss in that layer's parameter.
- `retained_backward_matches_checkpointed`: any number a retained-graph
  backward produces, IF it satisfies the derivative contract, equals the
  checkpointed entry -- by `uniqueness_limite`. Recompute-from-boundary and
  retained-graph backward are extensionally equal gradients.
- `gz_entry_sound` / `capped_gz_entry_sound`: `(softmax(z)_j - [j=y])/denom`
  is the true derivative of the row loss in logit j, and with softcapping the
  code's `dcap = 1 - (z_j/cap)^2` -- computed from the CAPPED value `z`, the
  clever part -- is exactly `d(cap*tanh(raw/cap))/draw` (`softcap_deriv`,
  built on `derivable_pt_lim_tanh`, `cosh2_sinh2`).
- `chunked_grads_equal_monolithic`, `chunked_loss_equals_monolithic`, and
  their `capped_*` twins (`capped_row_gz`/`capped_row_ce` carry raw-logit
  rows through softcap): the `while a < rows` piece loop, transcribed with
  its `min(chunk, remaining)` step, concatenates to exactly the monolithic
  per-row gradient map and sums to exactly the monolithic loss on BOTH cap
  branches. `parallel_slice_agrees`: slicing `pred`
  and `targets[a..a+c]` separately equals slicing the zipped rows -- the
  chunk-boundary index arithmetic. `monolithic_grad_at_logit` /
  `capped_monolithic_grad_at_logit` close the
  loop: the assembled entry at (row r, logit j) is the derivative of the
  TOTAL loss at that logit, uncapped and capped.
- `linear_bwd_row_grad` / `chunked_ce_backward_is_dy_W`: for
  `raw = hc . W^T` with `W` row-major and constant (detached), the gradient
  in `hc` is `gz . W` -- entry h0 is the dot of the gz row with column h0 of
  `W`. **This is the landed Bf16LinearOp bwd (`dx = dy * W`, weight not a
  graph argument, `nv-layers/src/linear.rs`) instantiated at the CE
  head.** It doubles as
  the correctness certificate for porting `chunked_ce` to the qwen arm.
- `capped_linear_bwd_row_grad` / `capped_chunked_ce_backward_is_dcap_gz_W`:
  the live Gemma4 branch (`final_logit_softcapping > 0`). For
  `z = cap*tanh(hc . W^T / cap)`, the gradient of the row CE in `hc` entry
  h0 is the dot of the code's `gz*dcap` row -- `dcap` multiplied into `gz`
  per VOCAB entry, before the `W` contraction -- with column h0 of `W`
  (`mull` is the elementwise product, `dotl_mull_assoc` the reassociation
  that moves it across the dot). This is the multivariate assembly through
  `W` for the capped composite; `capped_gz_entry_sound` alone stops at the
  per-logit raw derivative and does not certify `ghc`.
- `next_token_shift_pairing`: row t is scored against token t+1 -- the shift
  both trainers construct (`pred`/`ids[1..]` in dense_train,
  `embed_rows_shifted` in qwen38.rs).
- `head_last_row_zero_grad`: the loss reads only the first `seq-1` rows, so
  the appended `zero_row` is the true gradient of the dropped last row.
- `per_example_grad_accumulation`: summing per-example gradients computes
  the gradient of the summed loss -- `train_step_checkpointed`'s outer loop.

**Faithfulness.** `chunked_ce` chunks over ROWS, not vocab: it narrows
`pred` rows (`pred.narrow(0, a, c)`) and runs the full vocab per piece.
The module transcribes that row-chunked structure -- do not cite it for a
vocab-chunked logsumexp, which is a different algorithm this code does not
implement. Row chunking is value-invariant because softmax-CE is per-row,
which is exactly what the assembly theorems state. `detach` is value-identity in exact arithmetic, which
is why storing detached boundaries and recomputing gives the same forward
values. `ckpt` processes the layer list in the same top-down order as the
Rust loop, with the same three multiplications per layer.

**Not claimed.** The hidden state is scalar per boundary: this exposes every
recursion-order, evaluation-point, seeding and detach mistake, and none of
the shape/broadcast/stride mistakes inside a layer -- those belong to the
parity suites. No floating point (Flocq out of scope): recompute equals
retain here in exact values; bitwise equality on GPU additionally needs
deterministic kernels and is not claimed. Candle's backward is modeled as
"satisfies the derivative contract", not verified. The `dy * W` and
`(dy*dcap) * W` theorems fix the downstream to softmax-CE (uncapped and
soft-capped respectively); the general-downstream Bf16LinearOp
statement is not made. The `min(chunk, remaining)` step is load-bearing in
Rust for `narrow` bounds but NOT falsifiable in this model -- `firstn`/`skipn`
self-cap, and the mutation dropping the `min` still builds; do not read the
chunk lemmas as certifying the bounds check. Gradients for `Var`s reachable
only through the head (`final_norm` gamma, `lm_head` weight, embeddings) are
structurally discarded by `head_loss_grad`/`chunked_ce` (only the boundary
grad leaves the head); that is outside the certified path and safe today only
because `build_targets` targets attn/mlp Linears.

**Hazard found by transcription, not formalized.**
`grad_store_from` in `nv-models/src/train_runner.rs` seeds its `GradStore`
with `vars[0].sum_all().backward()` -- an all-ones gradient for `vars[0]` --
then overwrites entries per var only when the accumulated grad is `Some`. If
`vars[0]` ever receives no gradient, the optimizer silently steps it on the
fake all-ones seed, and the `sg.grads.iter().flatten()` finiteness sweep
skips the `None` without complaint. `train_steps` in
`nv-train/src/qwen38.rs` guards its identical helper with a loud bail on any
`None`; `train_runner.rs` has no such guard. Latent today (attn/mlp targets
always participate in the forward), live the day a target stops
participating. Needed change: refuse `None` grads before `grad_store_from`
in train_runner.rs, mirroring `train_steps`, or make `grad_store_from`
itself fail on a missing grad.

**Falsifiability**, checked rather than assumed: planted defects each break
the build -- inverting `completion_mask`'s polarity, reseeding `ckpt` with
the head grad instead of the propagated grad, dropping the `-1` at the
target in `gz_list`, dropping the `/cap` inside the `dcap` factor,
evaluating `dcap` on the raw logits instead of the capped values, and
composing `dcap` after the `W` contraction instead of into `gz` before it.
