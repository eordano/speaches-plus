# 7.1 Voxtral TTS: architecture dossier, oracle and port plan

`mistralai/Voxtral-4B-TTS-2603` (revision `b81be46c3777f88621676791b512bb01dc1cb970`,
CC BY-NC 4.0) is a Ministral-3B decoder that autoregressively emits one
semantic codec token per 80 ms frame, a three-layer flow-matching head that
turns each frame's hidden state into 36 FSQ acoustic tokens, and a causal
convolutional-transformer codec decoder that turns the 37-token frames into
24 kHz audio. The reference implementation is vllm-omni
(`vllm_omni/model_executor/models/voxtral_tts/`, commit `e6a7e63d`, paired with
`mistral_common >= 1.10` for the prompt); the model card names it, no
transformers class exists, and the paper is arXiv 2603.25551. This page states
the inference procedure as rules, names every checkpoint tensor and its
consumer, describes the oracle fixtures under `rust/tests/data`, and ends with
the port plan. Nothing here is a measurement.

## Checkpoint inventory

`consolidated.safetensors` holds 386 bf16 tensors (8.0 GB) in four groups.
`N` ranges over 26 backbone layers, `A` over 3 acoustic layers; the codec
decoder blocks are numbered `0..7` as vllm-omni's `decoder_blocks` ModuleList
(even indices are convolutions, odd indices are two-layer transformers).

Absent on purpose: there is no `output.weight` (the text LM head is never
evaluated: text logits are faked, see the step), no `time_embedding.inv_freq`
(computed), no codec encoder (`input_proj`, `encoder_blocks`; the open
checkpoint cannot clone from reference audio), and no bias anywhere. The 20
preset voices are `voice_embedding/<name>.pt`, each a bf16 tensor of shape
`[voice_num_audio_tokens[name], 3072]` (`neutral_female` is `[218, 3072]`):
the already-summed codebook embeddings of the reference clip's frames plus its
trailing end-of-audio frame.

Weight-norm folds at load: a conv's weight is `g * v / ||v||` with the norm
over every dimension but the first (`torch._weight_norm(v, g, dim=0)`), for
`Conv1d` (`[out, in, k]`) and `ConvTranspose1d` (`[in, out, k]`) alike.

## Prompt layout

mistral-common's `encode_speech_request` builds, with tekken v7 ids:

```
[BOS]=1  [BEGIN_AUDIO]=25  [AUDIO]=24 x N_voice  [NEXT_AUDIO_TEXT]=36  <text ids>  [REPEAT_AUDIO_TEXT]=35  [BEGIN_AUDIO]=25
```

`N_voice` is `tekken.json`'s `audio.voice_num_audio_tokens[voice]` (218 for
`neutral_female`), equal to the rows of the voice tensor; with reference audio
it would be `ceil(seconds * 12.5) + 1`. Text is encoded with `bos=False,
eos=False` and no normalization (vllm-omni's `text_preprocess.py` is a demo
helper, not part of the model). The prompt embedding is
`tok_embeddings[ids]` with the `[AUDIO]` rows replaced, in order, by the voice
tensor. `[NEXT_AUDIO_TEXT]` is the paper's `<next>` between the reference
audio and the transcript, `[REPEAT_AUDIO_TEXT]` its `<repeat>` between the
transcript and the audio to generate; vllm-omni's dummy prompt swaps 35 and
36, mistral-common is the authority. `interleave_{audio,text}_tokens_per_segment
= 8192` with `single_trailing_segment = false` means a request is one text
segment followed by one audio segment: nothing interleaves unless either
exceeds 8192 tokens, and the served limit (vllm-omni stage 1
`max_instructions_length`, the deploy's `max_tokens`) keeps every request far
below that. `condition_dropped_token_id = 42` (`[CONDITION_DROPPED]`) and
`p_uncond = 0.0` are training-time classifier-free-guidance dropout and play
no part in inference; the hidden-state zeroing used for CFG at inference is
described under the flow head.

## The backbone step

Ministral-3B rules, identical to the Voxtral Realtime decoder in shape: 26
pre-norm layers of dim 3072, 32 query / 8 kv heads of head_dim 128, SwiGLU
9216, RMSNorm eps 1e-5, causal attention over the whole sequence (no sliding
window), rope theta 1e6 applied to adjacent pairs `(2i, 2i+1)` of each head
(the mistral-inference complex layout; vLLM permutes `wq`/`wk` at load to use
its neox kernels, so a port that keeps the STT decoder's neox rope must
permute the same way). Positions count from 0 over the prompt and continue by
one per generated frame. The step's output is the final-norm hidden state `h`
of the last position; the tied text head is never applied. The step after
frame `t` takes as input embedding the sum of the 37 rows
`audio_codebook_embeddings[offset_k + frame[k]]` with `offset_0 = 0` and
`offset_k = 8194 + (k - 1) * 23` for the acoustic codebooks, where `frame`
carries the +2 special-token offset described next.

## The per-frame procedure (parallel codebook pattern)

`codebook_pattern = "parallel"` means all 37 tokens of a frame are produced
from one backbone hidden state and consumed together at the next step; there
is no delay pattern and no depth-wise autoregression. Per frame:

1. `semantic_logits = semantic_codebook_output(h)` in f32. Index 0
   (`[EMPTY_AUDIO]`) and indices `>= 8194` (padding) are masked to `-inf`;
   index 1 (`[END_AUDIO]`) stays allowed. `semantic = argmax`. This is the
   only token choice in the model and it is greedy by construction: vllm's
   sampler sees fake text logits that are `-inf` everywhere except `[AUDIO]`
   (or `</s>` once `semantic == 1`), so temperature, top-k, top-p,
   repetition penalty and seed in the deploy config change nothing.
2. Flow matching for the 36 acoustic values. `x_0 ~ N(0, I)` in bf16 (the only
   randomness; the fixtures store it per frame). Timesteps are
   `linspace(0, 1, nfe + 1)` cast to bf16, `dt_i = t_{i+1} - t_i` in bf16. The
   time token is `time_projection(cat(cos(t * f), sin(t * f)))` with
   `f_j = 10000^(-j / 1536)`, `j < 1536` (the `TimeEmbedding` with theta 1e4;
   `rope_theta` in the acoustic args is unused). The condition token is
   `llm_projection(h)`; the unconditional token is `llm_projection(0) = 0`.
   For each step `i`: the input sequence is `[input_projection(x_t), t_tok,
   cond_tok]`, run through the 3 bidirectional layers (full attention over 3
   tokens, no mask, no rope) and the final norm; the velocity is
   `acoustic_codebook_output` of the first token's output. Both branches run
   as one batch of 2. `v = alpha * v_cond + (1 - alpha) * v_uncond` with
   `alpha = 1.2` carried in bf16 (1.203125, so `1 - alpha = -0.203125`);
   `x_{t+dt} = x_t + v * dt`.
3. Quantize: `x = clamp(x, -1, 1)`, `code = round((x + 1) / 2 * 20)` in
   `0..=20`. If `semantic == 1` every acoustic code becomes 0. The frame is
   `[semantic, code_1 + 2, ..., code_36 + 2]`; semantic ids already live in
   the offset space (0 empty, 1 end, 2.. codes).
4. Stop when `semantic == 1`; that frame is not decoded. Otherwise embed the
   frame and run the next backbone step. `nfe` is `acoustic_transformer_args.n_decoding_steps`;
   `params.json` omits it and vllm-omni warns and uses 7, while the paper
   states `dt = 1/8` (8 evaluations). The oracle defaults to 7 and records the
   value; see open questions.

`sigma = 1e-5` and `sigma_max = 1.0` are the conditional-flow-matching
training schedule (the `sigma_min` of `x_t = (1 - (1 - sigma) t) x_0 + t x_1`);
vllm-omni parses `sigma` and never reads it, and drops `sigma_max`. There is
no sampling knob in the acoustic path beyond `cfg_alpha` (per request via
`sampling_extra_args`, default 1.2) and `nfe`.

Sampling defaults, then: greedy semantic token; `cfg_alpha = 1.2`; `nfe = 7`
as served; stop on `[END_AUDIO]` or `max_tokens = 2048` frames (deploy
config) / 2500 (offline example); the only stochastic input is `x_0`.

## The codec decoder

Frames arrive as `[T, 37]` with the +2 offset; the decoder cuts at the first
frame whose semantic id is 1 and subtracts 2 from every column, so semantic
codes are `0..8191` and acoustic codes `0..20`. One frame is 1920 samples
(24000 / 12.5); every operator below is causal, so the output for frame `t`
depends only on frames `<= t`.

1. Latent `[292, T]`: semantic rows `embedding[code]` (256) from the bf16
   `embedding_sum / clamp(cluster_usage, 1e-5)` table, concatenated with the
   36 acoustic values `code * 2 / 20 - 1`.
2. `decoder_blocks.0`: causal conv 292 -> 1024, kernel 3, stride 1, left pad 2
   with `replicate`.
3. Four stages at 12.5, 25, 50, 100 Hz. Each stage is a two-layer transformer
   (`decoder_blocks.{1,3,5,7}`) with sliding-window causal attention of
   window 2, 4, 8, 16 respectively (a query sees itself and the `window`
   previous positions: `half_attn_window_upon_downsampling` halves the
   encoder's 16 three times to 2 and the decoder doubles it back), ALiBi bias
   `slope_h * (j - i)` with `slope_h = 2^(-h-1)` for heads `h = 0..7` (the
   `2^(-8/n_heads)` geometric rule; head 0 has slope 1 in this convention, as
   `get_alibi_slopes` computes `r^i` with `r = 0.5`), QK RMSNorm over 1024
   before the head split, pre-norm RMSNorm eps 1e-2, LayerScale vectors on
   both residual branches, SwiGLU 4096, softmax scale `1/sqrt(128)`. Between
   stages (`decoder_blocks.{2,4,6}`) a causal transposed conv kernel 4 stride
   2 doubles the rate; it computes the full transpose and trims `k - s = 2`
   samples from the right (`trim_ratio = 1.0`), which is what makes it causal.
4. `output_proj`: causal conv 1024 -> 240, kernel 7, left pad 6 with `reflect`
   (zero-extended first when the input is shorter than 7). The `[240, 8T]`
   output unpatches to `8T * 240 = 1920 T` samples, time-major within each
   patch. The reference runs the whole decoder in bf16 and clamps nothing;
   values outside `[-1, 1]` only log a warning.

The decoder's left receptive field is about 22 frames: 2 (input conv) + 4
(stage 1, two layers of window 2) + 2 (transpose) + 4 (stage 2) + 1 + 4
(stage 3) + 0.5 + 4 (stage 4) + 0.75 (output conv). A chunk decoded with at
least that much left context, with the context's samples discarded, equals
the full decode except for the replicate/reflect pads at the context's own
start, which lie outside the emitted window; the oracle verifies the served
geometry below against a full decode and records the difference
(`chunked_decode_max_abs_diff` in each fixture's json).

## Token to embedding paths, summarized

- Prompt text and markers: `tok_embeddings` (131072 rows).
- Voice reference: the preset tensor row by row at the `[AUDIO]` positions.
- Generated frame fed back: sum of 37 rows of `audio_codebook_embeddings`
  (9088 rows, sizes `[8194, 23 x 36]`, cumulative offsets).
- Codec input: semantic `embedding_sum / cluster_usage` lookup (256) plus 36
  rescaled scalars.

## Streaming and latency

vllm-omni runs two stages. Stage 0 (backbone + flow head) emits one frame per
step; the transfer manager buffers frames and forwards a chunk to stage 1 (the
codec) once `codec_chunk_frames_at_begin = 5` frames exist, then every
`codec_chunk_frames = 25`; each chunk carries `codec_left_context_frames =
25` earlier frames whose `25 * 1920` output samples are cut
(`apply_ctx_frames_cutting`). Time to first audio is therefore the prefill of
the prompt (about 230 tokens for a short sentence with a 17 s voice) plus 5
backbone steps, each with 7 batched flow evaluations, plus one codec decode
of 5 frames: 400 ms of audio arrives after 5 frames and the stream then
advances 2 s at a time. The pipeline keeps audio ahead of playback when a
frame costs under 80 ms. Because every codec operator is causal the port may
decode per frame with carried state (conv history, per-stage KV windows of
2/4/8/16, transposed-conv overlap), bounding first-audio latency by one frame
instead of five; the chunk-with-context scheme is the simpler first
implementation and is exact given the receptive field above. The flow head
is the per-frame cost center: its 7 evaluations each read all 3 layers (about
0.7 GB bf16) for a 6-row batch, so a frame reads the flow weights 7 times and
the backbone once; vllm-omni captures the whole ODE loop in one CUDA graph per
batch bucket for this reason.

## The oracle

`scripts/voxtral-tts-reference.py` is a plain-torch transcription of
vllm-omni's three modules over the consolidated checkpoint, CPU bf16, with
the prompt from mistral-common's `encode_speech_request` and an assertion
that it equals the layout above. No vllm is imported: the pinned nixpkgs
`vllm` 0.29.0 does not evaluate on python 3.14 (its closure reaches
`tensorflow-bin`, which has no 3.14 build) and on python 3.12 is uncached
(296 derivations including vllm's own CUDA build), and vllm-omni is not
packaged. The run environment and command:

```
nix shell --impure --inputs-from . --expr 'let p = (builtins.getFlake "nixpkgs").legacyPackages.x86_64-linux;
    in p.python3.withPackages (ps: [ ps.torch ps.mistral-common ps.safetensors ps.soundfile ps.numpy ps.pycountry ])' \
  -c python3 -P scripts/voxtral-tts-reference.py \
  --model-dir ~/.cache/huggingface/hub/models--mistralai--Voxtral-4B-TTS-2603/snapshots/b81be46c3777f88621676791b512bb01dc1cb970 \
  --out rust/tests/data
```

Versions: python 3.14.8, torch 2.14.1 (CPU), mistral-common 1.12.0,
safetensors 0.8.0, soundfile 0.14.0, from the repo's pinned nixpkgs;
`pycountry` is a runtime import of mistral-common's transcription module.
Defaults `--nfe 7 --cfg-alpha 1.2 --seed 42 --voice neutral_female`; the
seed drives only `x_0`. Two cases: `en` "The quick brown fox jumps over the
lazy dog." and `es` "Hola, ¿cómo estás hoy? Me alegra verte.".

Fixtures per case, `rust/tests/data/voxtral_tts_<case>.*`:

- `.json`: text, text and prompt token ids, every frame's 37 tokens (offset
  space), semantic codes, `nfe`, `cfg_alpha` and its bf16 value, the bf16
  timesteps, seed, sample count, chunked-vs-full decode delta, timings and the
  versions/command above.
- `.safetensors`: `prompt_ids` (i32), `frames` `[T, 37]` i32 as generated,
  `codec_codes` `[T', 37]` i32 after the end cut and -2, `noise` `[T, 36]`
  f32 (the bf16 `x_0` of every frame), `timesteps`, `lm_hidden_frame_{0,1,2,last}`
  (3072 f32, post final norm), `semantic_logits_frame0` (8320 f32, unmasked),
  `flow_x_frame0` `[nfe+1, 36]` (x_0 and each Euler state), `flow_v_cond_frame0`
  and `flow_v_uncond_frame0` `[nfe, 36]`, `frame_embed_0` (the summed codebook
  embedding fed back after frame 0), `waveform` f32.
- `.wav`: the waveform as 16-bit PCM at 24 kHz.

`voxtral_tts_voice_neutral_female.safetensors` holds the preset tensor
(`voice_embedding`, bf16 `[218, 3072]`) so the suite needs no `.pt` reader.

The oracle's own gate is intelligibility: the STT oracle
(`rust/scripts/voxtral-reference.py` over the fixture wav resampled to 16 kHz)
transcribes `voxtral_tts_en.wav` and `voxtral_tts_es.wav` to their input
texts verbatim, which is what
rules out a silently wrong transcription of the reference (a mis-paired rope,
a wrong codebook offset or a non-causal pad would all still produce audio).

The parity claim a suite can make against these: identical prompt ids,
identical semantic codes and acoustic codes given the stored `x_0` (bf16
reassociation across backends permits an off-by-one FSQ level near a rounding
boundary, which the suite must tolerate per code, not per frame), hidden
states within bf16 tolerance, and a waveform within a small absolute band of
the stored one. Bitwise identity with vllm on CUDA is not claimed: the
transcription uses torch's `rms_norm` where vllm-omni uses apex when present,
and CPU bf16 GEMMs reassociate differently.

## Port plan

Reuse, from the STT port and nv-tts:

- `nv-models/src/voxtral.rs`: the decoder layer code, `KvCache`, the fused
  qkv / gate-up GEMVs, the folded `1/sqrt(head_dim)` in q rows and the
  `VoxtralQuant` ladder (`NV_VOXTRAL_QUANT`), unchanged for the 26 layers;
  the backbone is the same module to the parameter. New at load: the
  consolidated name map (`layers.N.attention.wq` and friends, `norm`) and the
  q/k row permutation to neox order, or a rope variant on adjacent pairs; the
  text LM head is skipped (no `output.weight` exists, the tied embedding is
  input-only).
- `nv-layers` NVFP4 `Linear` and the M-row GEMV
  (`NVFP4_GEMV_ROWS_COVER_THE_39_TOKEN_STREAMING_PREFIX` covers the flow
  head's 6-row batches and the 1-row backbone step). The flow head and the
  codec stay bf16 as vllm-omni keeps them even under fp8, until a corpus
  instrument (an ASR-WER scorecard over the generated clips, the TTS analogue
  of the LibriSpeech instrument) blesses quantizing them.
- `nv-models/src/voxtral_graph.rs` `GraphState`: the captured step and its
  token ring become an embedding-input step (the fed-back frame embedding is
  a device-side gather-sum, graph-friendly) with the semantic head, the 7
  flow evaluations and the FSQ rounding captured in the same graph, as
  vllm-omni's `CUDAGraphAcousticTransformerWrapper` does; `x_0` is a
  device-resident buffer refilled per replay.
- The pad-draft accept kernel (`DRAFT_ACCEPT_SRC`, `nv-kernels/voxtral_spec.rs`)
  does not transfer: STT speculates on pad runs, TTS has no cheap draft of
  semantic codes. It stays STT-only.
- `voxtral_wgpu.rs` and `voxtral_cpu.rs`: the backbone twins apply as-is
  after the load map; the flow head and codec need their own small kernels
  on each backend (3-token attention, windowed ALiBi attention, causal conv,
  transposed conv), scheduled after the CUDA path is parity-green.
- `nv-tts`: `TtsStream`/`TtsAudioStream` and `TalkerLike` (one frame per
  `step` with the previous frame fed back) host the generation loop; the
  chunk/left-context streaming geometry from `audio_speech_nvtts.rs`
  (`NV_TTS_STREAM_CHUNK_FRAMES`, `STREAM_LEFT_CONTEXT_FRAMES`) carries the
  5/25/25 defaults; `Sampler` is unused (greedy); `VoiceProfileStore`
  catalogues the 20 presets as `VoiceKind` entries whose payload is the voice
  tensor.
- `rust/src/oapi/audio_speech.rs` and `audio_speech_nvtts.rs`: the
  `/v1/audio/speech` route, model-id resolution (`tts_model_type` learns
  `voxtral_tts` from `params.json`), `wav_response` and
  `pcm_streaming_response` at 24 kHz, and the voice-name validation message
  paths.
- `voxtral_tekken.rs` `TekkenEncoder`: text ids with `bos=False, eos=False`;
  the prompt builder is a dozen lines over it.

New modules:

- `VoxtralFlowHead`: the 3-layer bidirectional block over 3 tokens, time
  table precomputed at load for the configured `nfe`, CFG blend in bf16, FSQ
  rounding, the `[END_AUDIO]` mask; parity suite over `flow_x_frame0` with
  the fixture's `noise` row.
- `VoxtralCodecDecoder`: weight-norm folded at load, causal conv / transposed
  conv with replicate and reflect pads, four windowed ALiBi transformer
  stages with QK-norm and LayerScale, output unpatch; suite compares
  `waveform` from `codec_codes`, then a chunked decode against the full one.
- `MultiVocabEmbedding`: 37-row gather-sum with the cumulative offsets;
  suite checks `frame_embed_0`.
- Voice presets: a one-time conversion of `voice_embedding/*.pt` to one
  safetensors file (candle's pickle reader can load `.pt` directly, but a
  converted file keeps serving free of pickle parsing).
- Streaming chunker: chunk-with-context first; per-frame stateful decode is
  the follow-up that cuts first-audio latency to one frame.
- Suite gates, in order: prompt ids; backbone `lm_hidden_frame_0` from the
  prompt; semantic argmax at frame 0; flow trajectory at frame 0; full frame
  sequence given the stored noise; codec waveform; HTTP route end to end.

## Open questions

- `nfe`: 7 (vllm-omni's default when `n_decoding_steps` is absent, the
  served behaviour) or 8 (the paper's `dt = 1/8`). The fixtures carry 7 and
  record it; a Mistral-hosted sample decoded under both would settle it.
- Whether vllm's deployed image has apex (`FusedRMSNorm`) and flash-attn
  (codec ALiBi path); the transcription uses torch's `rms_norm` and SDPA with
  an explicit bias, which agree with those up to bf16 reassociation.
- The reference clamps nothing on the waveform; the port should clamp to
  `[-1, 1]` before PCM conversion, as the oracle's `.wav` writer does.
- Voice tensors are summed codec embeddings of clips the open checkpoint
  cannot re-encode; new voices need the closed encoder or Mistral's studio.

## Codec port status

`nv-models/src/voxtral_tts_codec.rs` (`VoxtralTtsCodec`) is the codec decoder
with a CUDA arm and a CPU arm; the Vulkan twin is `voxtral_tts_codec_wgpu.rs`
and `load(dir, device)` refuses a Metal device: on a Metal box the codec is
the wgpu twin. Both arms build from one host weight set, so a change to the
fold or the row layout reaches both. Its rules:

- `load(dir, device)` mmaps `consolidated.safetensors` and reads only the
  `audio_tokenizer.*` tensors. Weight norm folds on the host in f32
  (`fold_weight_norm`: `v * g / ||v||` over every dim but the first) and the
  semantic table is `embedding_sum / clamp(cluster_usage, 1e-5)` rounded to
  bf16 once, as the reference's bf16 division rounds it. `wq`, `wk`, `wv` are
  one row block and so are `w1`, `w3`, so a layer reads each weight once; the
  transformer weights are the checkpoint's bf16 bits and the folded convs stay
  f32 (`THE_CONVS_FOLD_AND_RUN_IN_F32_ON_EVERY_DEVICE`).
- Every convolution is a GEMM over im2col rows `[x[t-k+1] ; ... ; x[t]]` with
  the weight laid out `[out][tap][in]`; the left context is the carried `k - 1`
  rows or, on the first call, the pad the reference uses (replicate for the
  input conv, reflect for `output_proj`, zeros for the upsamplers). The
  transposed conv k4 s2 with its right trim is the same causal conv over
  `[x[i-1], x[i]]` with the kernel rearranged by output phase
  (`transpose_conv_as_causal_conv`: phase `j` of output `2i + j` reads taps
  `j + 2` from `x[i-1]` and `j` from `x[i]`); a unit test holds it to candle's
  `conv_transpose1d` trimmed on the right. The GEMM's `[m, 2 * 1024]` output
  is the `[2m, 1024]` activation rows by reshape alone.
- The CUDA arm (`THE_CUDA_CODEC_IS_ONE_GRAPH_PER_CHUNK_SIZE_OVER_DEVICE_RESIDENT_STATE`)
  keeps a frame counter, the trailing conv rows and a window-slot K/V ring per
  layer in device buffers owned by the `CodecState`, and decodes a chunk of
  `n` frames as one CUDA graph keyed on `n`: the host builds the latent rows
  and uploads them, the graph runs the kernels of
  `nv-kernels/cuda/voxtral_tts_codec.cu` (im2col and its carry, a cast-and-
  norm after each conv GEMM, the q/k norm, the windowed ALiBi attention over
  `[ring ; chunk]` keys, the ring commit, the residual-and-next-norm, the
  SwiGLU gate, the counter advance) and the cuBLAS GEMMs (bf16 operands with
  f32 accumulation for the stages, f32 for the folded convs), and the host
  reads the samples back once. The residual kernel rounds the scaled branch to
  bf16 before adding it, the sequence torch's bf16 ops take; the norms, the
  attention scores, the softmax and the gate run in f32 with one rounding to
  bf16. The scratch and the graphs belong to the state because a graph bakes
  their addresses: a fresh state captures once per chunk size it meets, and a
  chunk larger than the scratch regrows it and drops the graphs. The chunk's
  cost is dominated by the weight reads and the graph's fixed per-node cost,
  so it is nearly flat in `n` up to the route's readback batch. The arm owns
  a non-blocking stream and a cuBLAS handle bound to it and serialises its
  decodes behind one mutex
  (`THE_CUDA_CODEC_OWNS_A_NON_BLOCKING_STREAM_AND_A_CUBLAS_HANDLE_BECAUSE_THE_ROUTE_DECODES_BESIDE_A_REPLAYING_FRAME_GRAPH`):
  the route decodes on its own thread while the synthesis thread replays the
  frame graph on the device stream, and a capture there would swallow that
  thread's launches; the handle's creation and destruction take the
  capture-exclusion gate because they synchronise the device.
- `decode(codes)` takes `[T, 37]` in the emitted offset space, cuts at the
  first end-of-audio frame (`frames_before_end_of_audio`), and decodes with a
  fresh `CodecState`; `decode_frames(&mut state, frames)` decodes any number
  of frames against carried state, so a stream emits audio per frame. Both
  return f32 at 24 kHz clamped to `[-1, 1]`; the reference clamps nothing.

The suite covering the port (`tests/voxtral_tts_codec.rs`, `#[ignore]`,
`VOXTRAL_TTS_MODEL_DIR` or the snapshot path above) decodes both fixtures'
frames on CUDA and on CPU, asserts the waveform within 0.02 of the fixture's
(clamped) `waveform`, reports the fraction of samples within 1e-2, asserts
the per-frame stateful decode against the full decode, prints the full and
per-frame cost, writes `/tmp/voxtral_tts_<case>.<device>.decoded.wav`, and
on CUDA closes the loop: the STT port (`VoxtralRealtime`) over the decoded
wav resampled to 16 kHz must return the fixture text verbatim. The chunk
ladder probe in the same file
(`codec_chunk_ladder_bench_prints_the_median_ms_per_chunk_on_the_device_nv_voxtral_tts_device_names`,
`NV_VOXTRAL_TTS_DEVICE=cpu` for the CPU arm) prints the median cost of a
one-, two- and eight-frame chunk over fresh states, with the first chunk's
cost (the state's allocation and capture) beside it.

## Backbone, flow head and frame loop port status

`nv-models/src/voxtral_tts.rs` (`VoxtralTts`) is the backbone, the semantic
head, the flow-matching head and the frame loop on candle: one code path for
CUDA and CPU, eager, in the dtype `serving_dtype` picks for the STT twin (bf16
on CUDA, f32 on CPU). Its rules:

- `load_dir` reads `params.json` (`model_type` must be `voxtral_tts`; the
  backbone and acoustic shapes come from it), `tekken.json` (the byte-level
  vocab feeds the shared `TekkenEncoder`, `audio.voice_num_audio_tokens` is the
  preset table `voices()` exposes) and `consolidated.safetensors`. The 26
  backbone layers are the STT `DecoderLayer` (fused qkv with `1/sqrt(128)`
  folded into the q rows, fused gate/up) built by `load_stack` from
  `layers.N.attention.{wq,wk,wv,wo}`, `feed_forward.{w1,w3,w2}`,
  `{attention_norm,ffn_norm}` and `norm`; a step is `decoder_hidden_over`, the
  body of the STT step. No text head is loaded: the tied embedding is input-only.
- Rope: the shared neox `Rope` with theta 1e6. The checkpoint rotates adjacent
  pairs `(2i, 2i+1)` with frequency `i`; `neox_row_permutation` moves row `2i`
  of each head to `i` and row `2i+1` to `i+64` in `wq` and `wk` at load, so the
  neox kernel rotates the same pairs with the same frequency and every `q.k`
  dot product is unchanged (`wv`, `wo` untouched). The proof is the suite's
  hidden-state and semantic-argmax checks at frames 0, 1, 2 and last.
- Voice presets: `read_torch_tensor` walks the stored (uncompressed) zip of
  `voice_embedding/<name>.pt` by its central directory, parses `data.pkl` with
  candle's pickle `Stack` and reads the bf16 storage bytes directly, no `zip`
  dependency and no conversion step; the row count must equal tekken's count
  for the voice. Tensors are cached per voice on the device.
- Prompt: `prompt_ids` is the layout above over `TekkenEncoder::encode`
  (no bos/eos); `prompt_embeds` gathers `tok_embeddings` and splices the voice
  rows over the `[AUDIO]` run.
- Flow head: three `DecoderLayer`s without rope and without the folded scale
  (`THE_FLOW_HEAD_KEEPS_THE_SOFTMAX_SCALE_IN_ATTENTION_NOT_IN_Q`: `1/sqrt(128)`
  is not a power of two), full attention over the three tokens through
  `nv_layers::attn::attention` (flash on CUDA, sdpa on CPU), batch 2 with the
  unconditional row's `llm_projection` input zero. The time tokens are
  computed at load from the bf16 timesteps `i/nfe` (f32 cos/sin, then cast,
  then `time_projection`). The CFG blend (`alpha` bf16 1.203125), the Euler
  update and the FSQ rounding run on the host in `half::bf16` with one rounding
  per operation and round-half-to-even
  (`EULER_AND_FSQ_ARITHMETIC_RUN_ON_THE_HOST_IN_BF16_TO_MATCH_THE_REFERENCE_ROUNDING`),
  so the quantized codes depend on the backend only through the velocity GEMMs.
- Frame loop `synthesize(text, voice, noise, max_frames, trace)`: `noise` is a
  closure over the frame index (the fixture's rows in the suite, `SeededNoise`,
  splitmix64 + Box-Muller rounded to bf16, in serving); the semantic argmax
  masks id 0 and ids `>= 8194`; the frame is `[semantic, code + 2]` with the
  codes zeroed on `[END_AUDIO]`; the next input is the f32 sum of the 37
  codebook rows cast once (torch's bf16 reduction). With `trace` the result
  carries the hidden states of frames 0, 1, 2 and the last, the frame-0
  logits, velocities, trajectory and fed-back embedding, and per-stage
  milliseconds measured with a device synchronize after each stage.
- `synthesize` also takes a teacher: a frame sequence fed back in place of
  the generated one, which runs the loop over the oracle's own prefix and is
  what makes a per-frame comparison meaningful, because the semantic argmax
  is a knife edge. The reference's logits are bf16 GEMM outputs, and the
  fixtures hold frames whose top two logits tie or differ by one bf16 ulp
  (`en` frame 0: ids 10 and 3040 both at 10.8125, broken by torch's
  first-index rule); any backend whose accumulation order differs flips such
  a frame, and a free run then continues as a different, equally valid sample.
  Bitwise semantic identity of a free run is therefore not a property of a
  correct port, and the gate does not claim it.
- The gate is the suite covering the frame loop against the oracle fixtures
  (`rust/tests/voxtral_tts.rs`, `NV_VOXTRAL_TTS_TEST=1`; `NV_VOXTRAL_TTS_DEVICE=cpu`
  runs it on the CPU path). Teacher-forced over the fixture's frames: prompt
  ids and bf16 timesteps equal; the hidden states of frames 0, 1, 2 and the
  last within a relative band; the masked argmax over the oracle's own logits
  equals the oracle's id; the frame-0 velocities and Euler states within a
  relative band per step; the fed-back embedding of frame 0 equal; a
  semantic flip is allowed only where the oracle's id is our second choice
  within two bf16 ulps of our top logit; acoustic codes identical or off by
  one level in a small fraction and never more (the counts are printed). The
  free run is reported (frame count, agreement with the oracle's frames,
  per-stage milliseconds), must reach `[END_AUDIO]`, and is gated by the
  closed loop the oracle itself uses: its frames and the oracle's frames are
  decoded by `VoxtralTtsCodec`, resampled to 16 kHz through the WAV decoder,
  transcribed by `VoxtralStt`, and both transcriptions must equal the input
  text verbatim (the STT checkpoint resolves as in the STT suite).
- Streaming: `synthesize_streaming(text, voice, noise, max_frames, on_frame)`
  runs the same loop and hands every frame to `on_frame` as it is produced;
  returning `false` stops the utterance. `synthesize` is the closure-less
  form of the same core, and the graphed path offers
  `synthesize_graphed_streaming` with the same contract (its frames arrive in
  readback batches, so a stop lands within one batch).
- `load_dir_with(dir, device, quant, flow_quant, nfe, cfg_alpha)` takes a
  `VoxtralQuant` for the 26 backbone layers and a `FlowQuant` (bf16, NVFP4
  or per-row e4m3) for the three flow layers; `load_dir` loads both bf16,
  which is the CUDA default. Every lower grade misses the teacher-forced
  bands of the gate (the NVFP4 grades by codes off by more than one level
  and semantic flips beyond the eager knife edges, the e4m3 grades by the
  off-by-one fraction alone) even where the corpus instrument reads it
  within paired noise of bf16, so no lower grade is a default; the graph's
  `NV_VOXTRAL_TTS_GRAPH_QUANT` arms and `load_dir_with` keep them reachable
  for a caller that accepts the fidelity loss for the bytes.
- Resident bytes: the bf16 linears are built with `Linear::new_no_pretranspose`
  (`BF16_LINEARS_KEEP_NO_PRETRANSPOSED_TWIN_BECAUSE_IT_DOUBLES_THE_RESIDENT_WEIGHTS`:
  the one-row GEMV, the M-row GEMV and cuBLAS's transposed-B route read the
  weight as stored), and `load_dir` trims the device's memory pool once the
  load-time temporaries are freed
  (`THE_STREAM_ORDERED_POOL_KEEPS_THE_LOAD_TIME_TEMPORARIES_UNTIL_TRIMMED`), so
  a loaded model costs its checkpoint bytes plus the per-process CUDA modules,
  and a synthesis adds its K/V cache and the graph state's buffers. The suite's
  `vram_by_stage` prints the process's resident bytes after each stage.
- On CUDA an untraced `synthesize` replays the frame graph below
  (`CUDA_SYNTHESIS_REPLAYS_THE_FRAME_GRAPH_BY_THE_LIBRISPEECH_73_ROW_WORD_ERROR_INSTRUMENT`);
  the model keeps one `TtsGraphState` sized to the request (at least
  `GRAPH_CAPACITY_MIN` positions) and rebuilds it when a longer request
  arrives. A traced run (the suite's frame-0 comparisons) and the CPU keep the
  eager loop, whose flow head on CUDA is the graph's own kernels
  (`THE_EAGER_AND_GRAPHED_FLOW_HEADS_SHARE_ONE_KERNEL_SET_SO_A_FRAME_DIFFERS_ONLY_BY_THE_BACKBONE_ATTENTION`).

## The CUDA frame graph

`nv-models/src/voxtral_tts_graph.rs` (`TtsGraphState`,
`VoxtralTts::synthesize_graphed`) runs a frame as one captured CUDA graph on
the serving device's stream, the idiom of the STT `GraphState`. Its rules:

- The body
  (`ONE_GRAPH_PER_FRAME_RUNS_THE_SEMANTIC_HEAD_THE_FLOW_ODE_THE_EMBEDDING_AND_THE_NEXT_BACKBONE_STEP`)
  reads the frame's hidden state `h` from a persistent buffer, runs the
  semantic head and a masked argmax (ids 0 and `>= 8194` excluded, the lowest
  index on a tie, as the host rule) into a ring slot, runs the flow ODE on the
  device (`VoxtralTts::flow_ode_device`, the same call the eager loop makes,
  so the trajectory is one kernel set for both paths,
  `THE_EAGER_AND_GRAPHED_FLOW_HEADS_SHARE_ONE_KERNEL_SET_SO_A_FRAME_DIFFERS_ONLY_BY_THE_BACKBONE_ATTENTION`),
  clamps and FSQ-rounds the final state (`tts_fsq`,
  `THE_FSQ_KERNEL_ROUNDS_AFTER_EVERY_OPERATION_LIKE_THE_HOST_BF16_PATH`), sums
  the frame's 37 codebook rows into the persistent input buffer, runs the
  backbone step at the device position and copies the new `h` back. Positions,
  the frame counter, the ring, the noise rows and an optional teacher table
  live in device buffers, so a replay reads nothing from the host.
- The bf16 backbone layer is six kernels
  (`THE_BF16_BACKBONE_LAYER_IS_SIX_KERNELS_BECAUSE_THE_NORMS_THE_SILU_AND_THE_RESIDUALS_RIDE_IN_THE_GEMV_PROLOGUES_AND_EPILOGUES`):
  `voxtral_tts_backbone_gemv` (`nv-kernels/cuda/voxtral_tts_backbone.cu`)
  stages the activation row once per block in shared memory sized to `K`,
  where a prologue applies the attention norm, the residual sum plus the ffn
  norm (writing the sum for the next residual), or the silu product of the
  gate_up halves, each with the arithmetic and reduction order of the
  `rmsnorm`, `rmsnorm_residual` and `spec_silu_mul_halves` kernels, and the
  down projection's epilogue adds the residual as candle's bf16 add does; the
  dot product keeps `gemv_bf16`'s lane order with four weight loads in
  flight, so a layer's output is bitwise the ten-kernel chain's. K/V are
  written by the STT `spec_qkv_prep` kernel and attention is
  `flash_decode_fused_bf16kv_mk`. A backbone whose linears are not bf16
  (the NVFP4 arm) keeps the generic chain through `Linear::forward`. The
  backbone's time is its four GEMVs' weight bytes over the achieved
  bandwidth; the kernels between them cost nothing measurable, so node
  count is not a lever below bf16 bytes.
- The host uploads the batch's noise rows (from the caller's noise closure,
  `SeededNoise` in serving), replays that many frames, synchronizes once and
  reads the ring; the first batch is two frames
  (`FIRST_READBACK_IS_TWO_FRAMES_SO_THE_FIRST_AUDIO_WAITS_FOR_TWO_REPLAYS_NOT_EIGHT`),
  the ring then fills to `FRAMES_PER_READBACK` and every later batch is eight,
  and the frames after `[END_AUDIO]` in the last batch are discarded. A
  teacher table (`synthesize_graphed` with `teacher`) feeds the oracle's
  frame back in place of the generated one for the suite's teacher-forced
  comparison, and the capture is the same graph.
- The flow head (`voxtral_tts.rs`, the `device` module): each of the `nfe`
  evaluations is one `voxtral_tts_flow_step` (the Euler update of the
  previous velocity, the input projection and the six token rows in one
  kernel,
  `THE_EULER_STEP_THE_INPUT_PROJECTION_AND_THE_TOKEN_ASSEMBLY_ARE_ONE_KERNEL_PER_EVALUATION`),
  three layers of `voxtral_tts_flow_gemm` (the six-row GEMM in
  `gemm_bf16_mk`'s lane order with the silu pairing and the residual add as
  epilogues,
  `THE_FLOW_GEMM_KEEPS_GEMM_BF16_MK_LANE_ORDER_WITH_FOUR_WEIGHT_LOADS_IN_FLIGHT_AND_FUSES_THE_SILU_AND_THE_RESIDUAL_INTO_ITS_EPILOGUE`)
  around `tts_flow_attn`, the three-token attention that is its own kernel
  because candle's flash-attn launches on the legacy null stream
  (`THE_FLOW_ATTENTION_IS_ITS_OWN_KERNEL_BECAUSE_CANDLE_FLASH_ATTN_LAUNCHES_ON_THE_NULL_STREAM`),
  and the nv-layers norms. The three flow layers exceed the card's L2, so
  the evaluations of one frame read the flow weights from DRAM every time:
  a frame costs the backbone's bytes once plus the flow layers' bytes `nfe`
  times, and the flow head is the larger share at the default `nfe`.
- Weight grades inside the graph, all opt-in, selected by
  `NV_VOXTRAL_TTS_GRAPH_QUANT` in the frame-loop gate and by the arm name in
  the corpus instrument: `nvfp4` (NVFP4 backbone), `nvfp4-flow` (NVFP4
  backbone and flow), `fp8-flow` (per-row e4m3 flow layers,
  `FlowQuant::E4m3`, quantized on the device at load) and `fp8` (e4m3 flow
  plus the e4m3 backbone rows the graph state builds from the bf16 linears,
  `TtsGraphState::new_with`, in serving `NV_VOXTRAL_TTS_BACKBONE=e4m3`,
  `AN_E4M3_BACKBONE_IS_AN_OPT_IN_ARM_UNTIL_THE_CORPUS_INSTRUMENT_BLESSES_IT`).
  The e4m3 backbone halves the backbone's bytes but misses the gate's
  teacher-forced bands on both fixtures (codes off by more than one level,
  off by one beyond the fraction, a dropped word in a free run), as the NVFP4
  backbone does, so bf16 stays the default and the bf16 weights stay resident
  beside the rows. The e4m3 flow head reads half the flow bytes per
  evaluation and the corpus instrument scores it inside the paired noise of
  the eager loop, but it misses the gate's off-by-one fraction on both
  fixtures (and moves a few codes by two levels on `en`), so it stays opt-in
  until the bands pass; `fp8` fails the same bands by a wider margin.
- Two capture rules the body obeys, beyond those of `07-speech-stack.md`: the
  first frame of a state runs eagerly so the step arena's slots are ordinary
  allocations rather than graph memory
  (`THE_FIRST_FRAME_RUNS_EAGERLY_SO_THE_ARENA_SLOTS_ARE_ORDINARY_ALLOCATIONS_NOT_GRAPH_MEMORY`;
  a slot allocated inside the capture is never freed in the graph and the
  graph allocator overlaps a later temporary with it), and every candle operand
  stays contiguous while the body runs under candle's
  `enable_cuda_graph_htod_cache`
  (`CANDLE_LAYOUT_PARAMS_GO_THROUGH_THE_CAPTURE_CACHE_OR_A_REPLAY_READS_A_FREED_HOST_VEC`:
  a strided candle op uploads its dims and strides from a host `Vec`, which a
  captured memcpy node re-reads on every replay after the `Vec` is gone; the
  cache serves such uploads from a content-keyed device copy and refuses an
  uncached one during capture). The graph's node census (`graph_census`) is
  the instrument for both: kernel and memcpy counts per kernel name, and
  mem-alloc nodes equal to mem-free nodes. Programmatic dependent launch is
  not used: a kernel that triggers its dependents before its writes lets the
  dependent's grid-dependency wait return before those writes are visible,
  and a trigger after the writes overlaps nothing.
- Cost: the graph removes the launch gaps that made the eager frame several
  times its weight-read floor; a graphed frame's GPU time equals its wall time
  and is set by bytes per frame over the card's bandwidth. The probe
  `frame_sections_bench` (`voxtral_tts_graph.rs`, `#[ignore]`) times the
  whole frame, the backbone alone against the ten-kernel chain (and holds
  `h` bitwise between them), and each backbone GEMV shape's achieved
  bandwidth.
- Gate: the suite covering the frame loop (`rust/tests/voxtral_tts.rs`) runs the
  graphed path after the eager one on CUDA: teacher-forced over the fixture's
  frames, the acoustic codes meet the same bands as the eager run (never off by
  more than one level, off by one in a small fraction) and a semantic id may
  differ from the eager run only at an eager knife edge (top-2 within two bf16
  ulps); the graphed free run must reach `[END_AUDIO]` and close the loop
  through the codec and the STT port within one word of the text (a free run
  is a different sample from the eager one once a knife edge flips; the corpus
  instrument below is the quality judge, the fixtures the smoke test).
- The corpus instrument is `corpus_word_errors_per_configuration` in the same
  suite (`NV_VOXTRAL_TTS_CORPUS`, default `/tmp/voxtral-corpus/rows.jsonl`,
  the 73 LibriSpeech dummy transcripts the STT instrument uses;
  `NV_VOXTRAL_TTS_ARMS` selects among `eager`, `graph`, `nvfp4`, `nvfp4-flow`,
  `fp8-flow`, `fp8`, `nfe5` and `nfe6`; `NV_VOXTRAL_TTS_SEED` seeds the
  noise): each row is synthesized with `SeededNoise` from frame 0, decoded
  by `VoxtralTtsCodec`, transcribed by `VoxtralStt`, and scored by
  `voxtral_train::word_error_rate` against the transcript; the arm's
  word-error count over the 1150 reference words, its paired per-row
  difference against the first arm with its standard error and z, its frames
  and its milliseconds per frame are the numbers a default flip cites.

## CPU path

`nv-models/src/voxtral_tts_cpu.rs` (`VoxtralTtsCpu`) is the frame loop on the
host; `VoxtralTtsModel::load_dir` routes `Device::Cpu` to it and every other
device to `VoxtralTts`. It is the STT CPU step applied to this model
(`THE_CPU_FRAME_IS_THE_STT_CPU_STEP_OVER_THE_BACKBONE_AND_SIX_ROWS_THROUGH_THE_FLOW_LAYERS`).
Its rules:

- Loading: the same `params.json`, `tekken.json`, voice `.pt` files and
  `consolidated.safetensors` as `VoxtralTts`, read by its own loader because
  the layout on the host differs: the token embedding table stays bf16 on the
  host and only the prompt's rows are gathered to f32, the codebook embedding
  is an f32 host table summed row by row (the same sequential f32 sum as the
  candle reduction), the norms are host f32 slices, and the 26 backbone layers
  and 3 flow layers are the STT `DecoderLayer` built per grade (fused qkv with
  the neox permutation and the folded `1/sqrt(128)` on the backbone's q rows,
  fused gate/up).
- The backbone step is `voxtral_cpu::CpuDecoder` over a `CpuStack` borrowing
  the layers, rope, final norm and config: the f32 loops of
  `THE_CPU_STEP_IS_PLAIN_F32_LOOPS_AROUND_THE_QUANTIZED_LINEARS` and the
  transposed key cache of
  `KEYS_ARE_STORED_TRANSPOSED_SO_THE_SCORE_LOOP_STREAMS_EIGHT_POSITIONS_PER_FMA`
  around the M-row linears. The prompt is one block of rows, so the prefill
  reads each weight once for the whole prompt like the STT streaming prefix;
  each later frame is one row at the next position.
- The flow head runs each of the seven evaluations as six rows (two CFG rows
  times three tokens) through the three layers, so every flow weight is read
  once per evaluation; its attention is a loop over the three tokens with the
  softmax scale applied to the scores, as the flow head keeps it out of q.
  `llm_projection` and the semantic head take the backbone's grade;
  `input_projection`, `time_projection` and the 36-row acoustic output stay
  dense f32. The CFG blend, the Euler update and the FSQ rounding are the host
  `half::bf16` arithmetic of `VoxtralTts::flow_frame`, so the codes depend on
  the grade only through the velocities.
- Grades (`CpuGrade`, chosen by `NV_VOXTRAL_TTS_QUANT`): `f32` is candle's gemm
  over f32 weights and reproduces the eager CPU path bitwise (the suite
  covering it, `the_f32_grade_reproduces_the_eager_cpu_path_on_the_fixture`,
  holds the hidden states, the frame-0 logits, every flow velocity and
  trajectory, the fed-back embedding and every teacher-forced frame of the `en`
  fixture bit for bit); `bf16` holds the CUDA path's bf16 weights bit for bit
  (the folded q rows round to bf16 as on CUDA) and multiplies them through
  `matmul_rows_bf16` with f32 accumulation
  (`A_DENSE_BF16_LINEAR_ON_CPU_RUNS_THE_LANE_MATVEC_OVER_ITS_HOST_BITS`);
  `q8_0` and `q4_k` are the `cpu_qmatvec` k-quant rows of the STT CPU path.
  The default is `q4_k`
  (`THE_CPU_DEFAULT_IS_Q4_K_BY_THE_73_CLIP_CORPUS_WORD_ERROR_INSTRUMENT`): a
  quantized grade reassociates against the bf16 oracle, so it holds the default
  only through the instrument below, which found its word errors within the
  paired noise of `f32` with the fixture closed loop verbatim.
- Cost structure: a frame is memory-bound on weight reads. The backbone reads
  its 26 layers once; the flow head reads its 3 layers once per evaluation,
  21 layer-reads over seven evaluations, so the two together read 47
  layer-weights per frame and the semantic head and the embeddings are noise
  beside them. On a dual-channel desktop at the plain DRAM read bandwidth the
  frame budget of 80 ms admits the 47 layer-reads only at `q4_k`, and only
  with the codec's own reads on top; `bf16` and `f32` are the fidelity grades,
  not serving ones. The flow head pays less than its 21 layer-reads on a
  machine with two L3s of unequal size
  (`THE_FLOW_HEAD_KEEPS_FOUR_FIFTHS_OF_THE_LARGEST_L3_IN_HOT_ROWS_AND_STREAMS_THE_REST`):
  the leading rows of every flow linear, sized to four fifths of the largest
  L3 by the grade's bytes per weight, are hot rows the large-L3 CCD serves
  from cache after the first evaluation of a frame, and the remaining flow
  rows, the backbone, the semantic head and `llm_projection` stream with
  non-temporal prefetch so they do not evict them. The placement changes which
  thread computes a row and nothing else, so every grade's output is bitwise
  the unplaced run's.
- The instrument for a default flip is the suite covering the corpus closed
  loop (`corpus_word_errors_per_grade_through_the_cpu_codec_and_the_stt_port`,
  `NV_VOXTRAL_TTS_GRADES`, `NV_VOXTRAL_CORPUS`, `NV_VOXTRAL_TTS_VOICE`): it
  synthesizes the 73 LibriSpeech transcripts per grade with `SeededNoise`
  seeded by row, decodes through the CPU codec, transcribes with
  `VoxtralRealtime` on CUDA and counts `voxtral_train::word_error_rate` errors,
  writing the per-row hypotheses to `/tmp/voxtral-tts-corpus-<grade>.jsonl`.
  The fastest grade whose word errors stay within the paired per-row noise of
  `f32` and whose fixture closed loop stays verbatim is the default, and a
  flip's commit names this instrument. `fixture_free_run_frames_close_the_loop_through_the_cpu_codec_and_the_stt_port`
  replays one fixture's free run at one grade through the codec and the STT
  port, dumping the frames once per grade so a codec change is heard in
  seconds.
- The gate on CPU is the frame-loop suite with `NV_VOXTRAL_TTS_DEVICE=cpu`.
  Its teacher-forced bands are a bf16-fidelity instrument: a 4- or 8-bit grade
  moves acoustic codes by more than one level and flips semantic ids at margins
  wider than two bf16 ulps while still closing the loop verbatim, so when the
  default grade is quantized the bands run on a `bf16` fidelity model and the
  free run and the closed loop on the default.

The CPU codec (`CpuCodec` in `voxtral_tts_codec.rs`,
`THE_CPU_CODEC_IS_ONE_HAND_WRITTEN_STEP_OVER_HOST_BF16_WEIGHTS`) follows the
same discipline: every causal conv is one M-row matvec over its taps stacked
per output row (the carried history is the previous `k - 1` rows, the first
call's pad is the reference's replicate, zero or reflect rows), q, k and v
share one weight read and so do w1 and w3, the windowed ALiBi attention, the
norms and the layer scales are loops over the rows, and a layer's state is its
last `window` keys and values. The transformer weights are the checkpoint's
bf16 bits through `matmul_rows_bf16`; the folded weight-norm convs keep the
f32 values the fold computes through `matmul_rows_f32` (rounding them to bf16
moves the waveform enough to change how the STT port writes the Spanish
fixture). Each weight is read once per frame whatever the frame's token count
(one token at the first stage, eight at the last), so the codec's cost per
frame is its weight bytes over the read bandwidth plus the row pool's
dispatch. The suite covering the codec holds this path to the same band as the
candle path and bitwise between the per-frame and the full decode.

`nv-layers/src/cpu_qmatvec.rs` carries the row pool and the kernels both CPU
paths share:

- The pool is one thread per physical core, at most sixteen, each bound to
  the logical cpus of its CCD with the CCDs ordered by L3 size
  (`THREADS_PIN_TO_THEIR_CCD_AND_THE_LARGEST_L3_SERVES_THE_HOT_ROWS_FIRST`),
  read from sysfs; a machine without the topology runs unpinned. A linear's
  rows go out in `ROWS_PER_TASK` chunks through two queues, hot rows to the
  large-L3 threads first and the rest to the others, and a thread drains the
  other queue when its own is empty. The `Placement` a caller scopes with
  `with_placement` names the hot share and whether cold rows prefetch
  non-temporal; the STT path scopes nothing and runs one queue.
- For more input rows than one pass holds, the pass over eight input rows is
  the outer loop and the chunk's weight rows the inner one, so the quantized
  input stays in L1/L2 across the chunk instead of streaming from L3 once per
  weight row; each output's block order is unchanged. The input quantization,
  the SiLU gate, and the attention of a multi-row step run on the same pool;
  every one of these is a per-element or per-row loop, so the prefill is
  bitwise the single-threaded one.
- The AVX-512 `q4_k` arm needs `avx512vnni` and accumulates the scaled
  pair-products with `vpdpwssd`, emitted through inline asm because this
  toolchain's `_mm512_dpwssd_epi32` carries an LLVM signature that fails to
  compile; it is the same i32 sum as `vpmaddwd` plus `vpaddd`, so the arm
  stays bitwise candle's `QMatMul` (the suite covering it,
  `q4k_arms_match_candle_bitwise_at_voxtral_shapes`, at one, three, four, six
  and thirty-nine input rows). A pass over four or more input rows reduces
  the rows' mins-by-bsums dots as one transpose and applies the block's
  `dmin` to all of them as one vector
  (`MINS_DOTS_OF_FOUR_OR_MORE_INPUT_ROWS_REDUCE_AS_ONE_TRANSPOSE`): the i32
  sums are exact in any order and the f32 steps are the per-row ones lane by
  lane, so the pass stays bitwise the one-row path. A machine with AVX-512
  but no VNNI takes the AVX2 arm.
- `matmul_rows_bf16` and `matmul_rows_f32` over the `F32Lanes` trait
  (`BF16_ROWS_EXPAND_EACH_WEIGHT_ONCE_INTO_F32_LANES_AND_KEEP_ONE_ACCUMULATOR_PER_INPUT_ROW`)
  are the lane matvec the codec and the bf16 grade use, one weight read per M
  input rows on the same pool; the suite covering it holds every arm to an
  f64 dot at the codec's shapes and the f32 rows bitwise to the bf16 rows of
  the same values.
- The probes are `#[ignore]`: `matvec_bandwidth_probe` (L3-resident shapes,
  the compute rate per arm and row count), `decoder_step_floor_probe` (the
  STT weight set as one step) and `frame_floor_probe_with_placements` (a
  backbone step plus seven flow evaluations under each placement, the frame's
  weight-read floor on the box).

## Serving: `/v1/audio/speech`

`rust/src/tts/voxtral_tts.rs` (`VoxtralTtsSpeech`) is the backend behind the
route; it implements the route's `AudioSpeech` trait, so model-id resolution,
voice errors, parameter refusals and the encoders are the ones the Qwen3 talker
uses. Its rules:

- Load: `Models::load` builds it once when `<models>/voxtral-tts`
  (`VOXTRAL_TTS_MODELS_DIR_LINK_NAME`) holds `params.json` or
  `VOXTRAL_TTS_MODEL_DIR` names a checkpoint; there is no hub-cache scan at
  boot, so a box that merely has the snapshot cached serves nothing until it is
  linked. The backbone loads on `stt::voxtral::serving_device()` (a CUDA
  stream where a device exists, else the CPU path); the codec loads on the same
  device, or on the wgpu twin under `NV_SERVE_BACKEND=wgpu`, where a missing
  adapter is an error. The backbone has no wgpu twin yet, so wgpu serving is
  codec on Vulkan with the backbone on CUDA or CPU. A warmup utterance runs on
  a thread after load; requests queue behind it on the engine gate.
- Ids: `mistralai/Voxtral-4B-TTS-2603` and the alias `voxtral-tts`;
  `is_voxtral_tts_model` accepts the alias and any prefix of the id's basename
  (`voxtral`, `voxtral-4b-tts`). `resolve_speech_route` picks Kokoro by name,
  Voxtral by id or alias (a 404 listing the served ids when it is not loaded),
  then the nv-tts talker; a request without a model id gets the talker, else
  Kokoro, else Voxtral. `GET /v1/models` lists the talker and Kokoro only
  (`models_handler.rs` does not read `models.voxtral_tts`).
- Voices: the presets of `voice_embedding/*.pt`, in `voices()`; an omitted
  voice, `default` and the OpenAI alias names map to `neutral_female`; any
  other name is a 400 (`invalid_voice`) whose message lists every preset.
- Parameters: `speed`, a `sample_rate` other than 24000 and a `stream_format`
  other than `audio` are refused, as on the Qwen3 path, because the model has
  no duration control and the route no resampler.
- Formats (`audio_response`, shared with the talker): `pcm` streams s16le;
  `wav` streams too, its header carrying the `0xFFFFFFFF` placeholder lengths
  ffmpeg writes when it streams and `decode_wav_to_16k_mono` patches;
  `mp3`, `opus`, `flac` and `aac` go through an ffmpeg pipe and answer 503
  `encoder_unavailable` without ffmpeg on PATH.
- Stream geometry: `synthesize_streaming` reports each frame as the backbone
  produces it (the CUDA graph hands them over per readback batch) and the
  synthesis thread sends it to a decoder thread owned by the sentence group
  (`decode_the_frames_waiting_as_one_chunk`), which takes every frame waiting
  in its channel, decodes them through one stateful codec call and sends the
  samples. The first bytes leave after the prefill and the first frames, a
  codec slower than the backbone widens its chunks instead of stalling it, and
  the frame sequence is the full decode's, so the audio equals the one-shot
  decode within the codec suite's chunked-vs-full band. There is no chunk-size
  knob. A codec failure closes the frame channel, which ends the synthesis and
  surfaces as the stream's final `Err`; a client that hangs up closes the
  sample channel the same way.
- Text: `tts::chunk::plan` (nv-punkt sentences) groups sentences up to
  `SEGMENT_CHARS_GROUP_SENTENCES_UNDER_ONE_PREFILL` characters; groups
  synthesize sequentially under one gate, each with a fresh codec state and
  `SeededNoise` seeded from `FIXED_SEED_UNTIL_THE_ROUTE_CARRIES_ONE` xor the
  group index, so a text renders identically across requests.
- VRAM: `vram_plan` books `aux-voxtral-tts`
  (`AUX_VOXTRAL_TTS_4B_BF16_CUDA_MIB_MEASURED_STANDALONE_PROCESS_AFTER_WARMUP`)
  when the loaded speech providers show `voxtral-tts` on cuda.
- The gate is the suite covering the route end to end
  (`rust/tests/voxtral_tts_http.rs`, `NV_VOXTRAL_TTS_TEST=1`): it boots
  `Models` on a scratch model dir with `VOXTRAL_TTS_MODEL_DIR`, posts both
  fixtures as wav and asserts 200, 24 kHz, the placeholder header and the
  closed loop through `VoxtralStt` within two word errors per fixture (the
  route seeds its own noise per sentence group, so a knife-edge clause may
  read differently from the frame-loop gate's fixture noise; the corpus
  instrument judges quality); a pcm body, a two-group text, an mp3 body,
  and the unknown-voice 400 naming every preset. Time to first audio is a
  measurement, not a gate: `first_audio_bytes_arrive_within_the_budget_on_an_idle_gpu`
  in the same file asserts
  `FIRST_BYTES_BUDGET_SECS_IS_PREFILL_PLUS_ONE_READBACK_BATCH_WITH_THREEFOLD_HEADROOM`
  and runs under `nvk.sh probe`; on a GPU shared with other work it fails by
  contention.
