# Contrastive tool decisions

`scripts/clm_pipeline.py` trains the CLM state and action projection heads on
labeled System One decisions. The frozen encoder is `Qwen/Qwen3-8B`, with
last-token pooling and L2 normalization. `clm_download.py` pins the encoder,
the released CLM head, and the upstream implementation by revision. The
pipeline imports `clm.heads.make_head` and `clm.schema.build_pairs` from that
checkout, and requires PyTorch, transformers, numpy, safetensors, datasets,
and huggingface_hub in the training Python environment.

The architecture and contrastive objective follow the
[CLM implementation](https://github.com/Contrastive-LM/CLM). The Rust backend
loads the exported projection heads directly; no Python server or embedding
HTTP service is required for inference.

## Training data

The public downloader reads only training splits from When2Call, xlam
irrelevance, ToolACE, Glaive function calling v2, and Hermes single-turn
function calling. It retains conversation history and visible tool results
before the labeled decision. Malformed records and labels outside the offered
tools are rejected. When2Call's MCQ test split remains an external holdout.
`public/manifest.json` records exact dataset revisions and accepted counts.

`clm_prepare.py` combines those records with CCCP decisions, Portal synthetic
training records, and any non-tool replay records in the supplied mix. The
pipeline reports the replay count explicitly; zero means no general decision
replay is present. It validates the labels,
canonicalizes `no_tool` to `none`, and prefixes tool descriptions with their
names because CLM embeds descriptions independently of the option keys.
States and question instructions are joined by a blank line; actions use the
same descriptions Portal sends with `PORTAL_ROUTER_PROVIDER=clm`.

Related conversation turns and repeated user questions stay in one split.
Existing external holdout questions and matching public conversations are
excluded. Conflicting duplicate labels are removed. Train, validation,
calibration, and test files are separate, with counts and SHA-256 digests in
`data/manifest.json`. Private states, caches, checkpoints and results belong
in a private work directory outside the repository.

The encoder retains the last `max_tokens - 1` tokens without adding special
tokens; the default ceiling is 8192. The CCCP context mix supplies both short
and long examples. `context_lengths.json` reports the actual length bands and
truncations for every split. Changing the encoder revision or token recipe
requires a different SQLite embedding cache; the trainer rejects an
incompatible cache.

## Run on a training host

Use a CUDA Python environment with the dependencies above. The existing
Kev environment can provide them. `WORK` is a private directory on the same
host as the CCCP training records. The pipeline creates `WORK/upstream` at
`clm_download.UPSTREAM_REVISION` and verifies the revision on subsequent runs:

```sh
python scripts/clm_pipeline.py --work "$WORK" \
  --cccp-train "$CCCP/train-balanced.jsonl" \
  --cccp-eval "$CCCP/eval-balanced.jsonl" \
  --portal "$PORTAL_SYNTHETIC" \
  --when2call-eval "$WHEN2CALL_MCQ" \
  --replay "$EXISTING_MIX/train.jsonl"
```

The pipeline downloads more public records, prepares the splits, caches the
encoder embeddings, and trains only the projection heads and logit scale.
Encoder batches contain up to 8192 padded tokens. The CUDA allocator is capped
at 80% of the memory free at startup, leaving room for other GPU processes;
reducing a batch does not shorten an individual record's context limit.
The bidirectional loss pools distinct action texts and treats repeated gold
actions as multiple positives. The selected checkpoint minimizes validation
NLL, including the original head as a candidate. Temperature is fitted on the
calibration split; final accuracy, NLL, Brier, 15-bin ECE, coverage at a 5%
error budget, and tool accuracy are computed on the untouched internal test
split. These metric definitions are recorded in code; external Kev benchmark
reports must retain their own metric definitions when comparing models.

Each completed run writes `best_head.pt`, `clm_head.safetensors`, `clm.json`,
`head_oracle.json`, `baseline.json`, `history.json`, `test.json` and
`complete.json` under `WORK/runs/clm-tooluse-8b-v1`. Embedding cache commits
survive interruption. Rerunning starts head optimization from the released
head using cached embeddings; it does not resume optimizer state.

## Native serving

Set `NV_CLM_MODEL_DIRS` to comma-separated exported run directories. The
models are listed by their `clm.json` name in `/v1/models` and accept
`choice`, `noul`, and `score` requests on `/v1/systemone`. `encoder_dir` points
to the matching Qwen3-8B snapshot; a relative path is resolved against the
export directory when moving a checkpoint to another host.

The backbone is loaded through the existing native Qwen3 implementation on
first use. The projection heads run in FP32 on CPU. Each loaded model caches
up to 8192 action projections; a repeated action avoids encoder and head
work. `usage.input_tokens` counts tokens encoded for that request, so cache
hits cost zero encoder tokens. `clm.json` stores the fitted temperature;
a request's optional `temperature` multiplies it. Cold eviction removes the
encoder, heads, and associated cache together.

The existing embedding endpoint keeps its own token policy. CLM tokenizes
without special tokens, retains the tail, and uses the exported context
limit for both states and actions. Native projection compatibility is checked
against the PyTorch head oracle with:

```sh
NV_CLM_HEAD_TEST=1 NV_CLM_HEAD_TEST_DIR="$RUN" NVK_PKG=speaches-plus \
  NVK_FEATURES=cuda NVK_SHELL=.#cuda-no-models NVK_LANE=clm rust/scripts/nvk.sh test --lib \
  checkpoint_heads_match_the_pytorch_oracle -- --ignored
```

That checks the projections on recorded vectors. Full encoder and endpoint
agreement requires evaluating real requests against both implementations;
a passing projection test alone does not establish that agreement.
