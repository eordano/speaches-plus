# 7.2 Voices -- recordings, named speakers and fitted Kokoro voices

The Rust engine owns the workspace, its API and the page at `/voice-lab`.
Whisper supplies transcripts, DiariZen supplies speaker turns, WeSpeaker supplies
identity embeddings, and Kokoro supplies speech. Style fitting uses an evolution
strategy over stock-voice blends; adapter fitting trains AdaIN projections with
candle autograd. Neither fitting tier requires Python or torch.

## Workspace and pipeline

`NV_VOICES_DATA_DIR` selects the workspace:

```
recordings/                         audio files or symlinks to mounted trees
artifacts/<sha256[:2]>/<sha256>/
  transcript.json                   segments and words when provided by STT
  diar.json                         segments and per-speaker embeddings
  clips.json                        turns, overlap flag and aligned transcript text
manifest.json                       recordings and artifact hashes/producer policies
speakers.json                       identities, names, centroids and sources
clips/                              cached 24 kHz reference WAVs
voices/<name>/                      runtime voice store
```

The scan follows symlinked trees, skips hidden directories and transcript
directories beside recordings, and keys recordings by audio content. Renames
retain artifacts. A file that cannot be read is warned about and skipped;
successful rows still reach the manifest.

`POST /v1/voices/workspace/run` queues scan, transcribe, diarize, identify and
clips. Runs are serialized inside one engine. Failed transcription or
diarization requests are logged per recording and retried by a later run.
The run does not automatically fit every speaker.

| Stage | Output and reuse rule |
|---|---|
| transcribe | Verbose JSON; reuse current artifacts. Chunk merging shifts segment, nested-word and top-level-word timestamps. |
| diarize | Segments plus speaker label, seconds, turn count and WeSpeaker embedding. Current segment-only artifacts are retried. |
| identify | Link embeddings with at least 60 seconds of speech at cosine 0.70; another label from the same recording needs 0.75. Existing recording/label sources are skipped. |
| clips | Turns of at least 4 seconds, overlap flags and text aligned from the recording transcript. Reuse the current clips producer policy. |
| fit | Explicit style or adapter job. Each accepted request runs; there is no quality-threshold skip. |

The HTTP diarization response and identify input share the same JSON contract.
Speaker durations cover all emitted turns; embedding extraction uses at most
30 seconds per speaker. Subsecond speakers carry an empty embedding and do not
enter identify.

Producer strings in `workspace::producer` are manually maintained pipeline
policy identifiers, not hashes of loaded checkpoints. Changing the served model
does not automatically invalidate artifacts. Bump the relevant policy when an
output must be regenerated. The clips producer identifies aligned transcript
text; clips are not independently re-transcribed.

Identify proposes a host name after a speaker appears in at least three
recordings of a podcast. It does not infer guest names from titles or transcripts.
Human renames and identify hold the same registry lock across read, modification
and atomic save. This lock is per engine; operate a workspace from one writer
engine.

The engine exposes manifests and artifacts for inspection. It does not implement
a sync CLI, blob uploads, conflict merging, or audio downloads from source URLs.
Mount the audio trees where the workspace symlinks resolve.

## Fitting

`POST /v1/voices/fit` accepts `name`, `tier` (`style` or `adapter`) and either
`refs` or `speaker`. The Voice Lab form sends a speaker identifier; `refs`
defaults to an empty list and is filled by speaker resolution. References must
resolve inside the workspace. The engine selects up to 12 clean turns of at
least 8 seconds and caches WAVs capped at 30 seconds. `steps` in a speaker
request overrides style generations or adapter epochs.

The request's `language` (default `en-us`; accepts the same codes as the speech
route, so `es-AR` and `es-419` both select espeak's Latin American voice) selects
the phonemizer voice for every synthesized sentence and the sentence corpus:
`TRAIN_SENTENCES`/`DEFAULT_SENTENCES` in English, `TRAIN_SENTENCES_ES`/
`DEFAULT_SENTENCES_ES` for any language starting with `es` (`corpus_for`). A
voice fitted for Spanish speech must be fitted with `language: "es"`; scoring
English synthesis against Spanish references measures the wrong thing.
The request's `sentences` are validation sentences. When omitted, direct
reference fits use the corpus defaults; speaker fits select up to four sentences
from aligned transcripts, falling back to defaults if needed. Both tiers train
on the corpus's training sentences, excluding normalized duplicates of validation sentences.
An exhausted training set is rejected. Validation selects the checkpoint and
controls early stopping; it is not an independent test set. Fitting does not
calculate Whisper WER or guarantee perceptual identity from an embedding score.

Style fitting scores candidate stock-voice blends on training sentences using
WeSpeaker cosine and an L2 penalty. Each generation evaluates the selected
candidate on validation sentences and retains the best validation checkpoint.
Adapter fitting starts with that style, then trains decoder/generator AdaIN
projections against Qwen and WeSpeaker embeddings with an anchor to base weights.
It selects its checkpoint by validation WeSpeaker cosine. See
[7.3](07.3-kokoro-candle.md) for the candle graph.

Defaults come from `tts::fit::FitRequest`:

| Parameter | Default |
|---|---|
| style generation budget | 60 |
| adapter epochs | 12 |
| patience, both tiers | 8 |
| minimum validation improvement | 0.005 |
| style population | 12 |
| style L2 coefficient | 0.02 |
| seed | 1 |

One fit runs at a time per engine. `GET /v1/voices/fit` lists in-memory jobs;
`GET /v1/voices/fit/{id}/events` replays the log and follows live events.
One cursor covers replay and live delivery, including broadcast lag.
`done` or `error` is delivered once and closes the stream.
Jobs do not survive an engine restart.

### Fitting in a browser

Both tiers also run inside a tab, on the wasm32 CPU backend of the same candle
graphs (`nv-ocr-web/src/kokoro_web.rs`,
`KOKORO_IN_A_TAB_IS_THE_CANDLE_CPU_GRAPH_COMPILED_TO_WASM32_NOT_A_WGPU_PORT`):
nv-tts has no wgpu kernels, so there is nothing for WebGPU to run, and a wgpu
port of the front end would be the prerequisite for GPU speed. The page stages
`kokoro-v1_0.safetensors`, the WeSpeaker `graph.json` and `weights.safetensors`,
the `qwen-spk` config and weights, and reference clips as raw 24 kHz f32
(`harness/kokoro_stage.py` cuts them from the workspace WAVs and extracts the
stock style rows the style tier blends); phoneme ids come from the engine's
espeak phonemizer, which cannot cross into wasm (`examples/kokoro_tokens.rs`
dumps them). `kokoro_fit_style` runs the same evolution
(`nv_tts::kokoro::style_fit::evolve`) the engine runs, scored by candle
WeSpeaker cosine; `kokoro_fit_adapter` runs `kokoro::train::adapt` with a
training window and one encoder in the loss, because a wasm32 heap holds 4 GiB.
The suites: `nv-ocr-web/tests/kokoro_web_gate.rs` (`NV_KOKORO_WEB_TEST=1`,
`NV_KOKORO_WEB_DIR`, optional `_SET`, `_WMIX`, `_WINDOW`) drives the same cores
natively from a staged directory and prints per-phase peak memory; the browser
harness's `Q38WEB_ARMS=kokoro` arm (query `set`, `stock`, `budget`,
`population`, `train`, `heldout`, `epochs`, `refs`, `wmix`, `window`) runs
Chromium and reports `KOKORO-FITS`. On the RTX PRO 6000 host, in Chromium under Xvfb: init
from bytes in 135 ms, 2.1 s of speech synthesized in 4.0 s, a style fit over
four stock voices for one generation of two candidates in 97 s, and one adapter
epoch on a one-second window with WeSpeaker out of the loss in 59 s, yielding a
19.3 MB adapter the tab renders through. Fitting quality at those budgets is a
proof of the path, not a voice: the engine's defaults (60 generations, 12
epochs, full sentences, both encoders) remain the fit to publish.

## Who is speaking

`rust/src/realtime/speaker_id.rs` identifies the speaker of every finished
utterance against the workspace registry. `SpeakerIdentifier::global` exists
when `NV_VOICES_DATA_DIR` is set and the WeSpeaker embedding model is loaded;
it embeds the utterance (at least 1 s, at most the first 30 s), takes the
cosine to every `speakers.json` centroid, and reports the best one when it
reaches `threshold_link`. The registry is re-read when `speakers.json`
changes, so a rename in the Voice Lab shows up on the next utterance. The
realtime lane puts the result on
`conversation.item.input_audio_transcription.completed` as
`speaker: {id, name, score}` (`name` is the confirmed name, else the proposed
one, else null; `speaker` is null when nothing matched). The same matcher
answers `POST /v1/voices/workspace/identify-audio` (multipart `file`) with
`{seconds, speaker}` for one clip. recgo's realtime STT client carries the
match as `State.Speaker`, and the recording TUI labels the mic and system
badges with the last speaker heard on each track.

## Qwen x-vector profiles

`POST /v1/voice-profiles` enrolls a Qwen3-TTS voice from reference audio and
`/v1/audio/speech` clones it when `voice` names the profile. Enrollment needs a
speaker encoder, and `SpeakerEncoderSource::choose` in
`nv-tts/src/speaker_encoder.rs` decides where it comes from at boot, logging
`source=checkpoint|external` or the reason it is unavailable:

1. The talker checkpoint's own `speaker_encoder.*` tensors. Only
   `Qwen/Qwen3-TTS-12Hz-*-Base` ships them; CustomVoice and VoiceDesign do not.
2. A standalone ECAPA-TDNN directory (`config.json` with top-level `enc_*`
   keys plus unprefixed `model.safetensors`) from `NV_TTS_SPEAKER_ENCODER_DIR`,
   or failing that `NV_QWEN_VOICE_ENCODER_DIR`. It is accepted only when the
   talker's `tts_model_type` is `base` and the encoder's `enc_dim` equals the
   talker `hidden_size`: the x-vector is inserted verbatim as one hidden-state
   row of the codec prefix, and a CustomVoice talker was never trained with
   anything in that slot.
3. Neither: `POST /v1/voice-profiles` answers 503 `no_speaker_encoder` and
   profile voices are refused at synthesis.

A Base talker has no built-in speakers, so an explicit `voice` is a profile
name. The OpenAI aliases, `default` and an empty `voice` resolve, in order, to
the enrolled profile named `default` and then to the engine's built-in default
voice: `rust/voices/qwen3-tts-0_6b-default.xvector.json`, a 1024-d x-vector
enrolled from a Kokoro `af_heart` sentence through the same decode, 16 kHz
gate and resample chain `POST /v1/voice-profiles` uses (`NVK_PKG=speaches-plus
rust/scripts/nvk.sh run --example enroll_xvector` regenerates it), compiled into
the binary and used whenever its width matches the talker. Enrolling `default`
overrides the timbre; deleting it falls back again. The Base prefix layout
always carries a speaker row, so there is no unconditioned fallback: a talker
width the shipped vector does not match refuses the aliases with a 400 that
names the enrollment route. Aliases never consult the store on a CustomVoice
talker, where they land on `serena`.

The profile store (`NV_VOICES_DATA_DIR/voices`, an NFS export shared across
hosts) is opened lazily through `VoiceStoreHandle` and re-checked on every
use, so an unreachable mount at boot or later does not take speech down:
aliases use the built-in voice, a named profile and every `/v1/voice-profiles`
request answer 503 `voice_store_unavailable`, and the first request after the
mount returns reopens it. The resolved default tensor is cached per source
(profile mtime or built-in), and resolution runs on the blocking pool, so a
stalled mount cannot wedge the async runtime.

The fleet serves the 0.6B Base checkpoint for cloning; the `qwen-spk` directory
on the voices mount is the 1.7B-family encoder (`enc_dim` 2048) and exists for
Kokoro adapter fitting, where only cosine similarity matters. It cannot condition
the 0.6B talker (hidden 1024), and the boot log names that mismatch. The suite
covering the decision (`speaker_encoder::tests::source_*`) runs on fabricated
directories; `real_qwen_spk_dir_enrolls_xvector_from_wav_on_cpu` and
`real_base_checkpoint_is_chosen_over_external_and_enrolls_on_cpu` are
`#[ignore]` and enroll the fixture WAV on CPU against the real weights
(`NV_TTS_BASE_TALKER_DIR` points the second at a Base checkpoint).

## Voice store and publication

The store shares an API with Qwen x-vector profiles. A Kokoro generation holds:

```
voice.json                schema, kind, producer, speaker_id, evaluation
pack.npy                  [rows,1,256] f32 style vectors
adapter.safetensors       candle adapter tensors, for the adapter tier
adapter.npz               the same tensors under ONNX initializer names
sample_0.wav ...           validation samples
```

Fitting writes an isolated staging directory first. After training, adapters,
samples and metadata succeed, it moves the generation into
`voices/<name>/.versions/<revision>/` and atomically switches
`voices/<name>/current`. Failed fits leave the published generation intact.
Older flat voice directories remain readable. Old generations remain on disk
so readers that resolved one before publication can finish safely; there is no
automatic revision pruning.

Rust store readers resolve `current`; Kokoro resolves it once per cache load,
so pack and adapter belong to one generation. Generation path and metadata
mtime invalidate the cache without a restart. The Python Kokoro pack reader
also follows `current`, but does not apply decoder adapters.

`GET /v1/voices` lists voices and evaluation metadata;
`GET/DELETE /v1/voices/{name}` reads or removes a voice;
`GET /v1/voices/{name}/files/{file}` exports allowed files.
`POST /v1/voices` imports multipart `voice.json`, `pack.npy` and optional
`adapter.npz`. The fit's publication mechanism does not make imports a transaction.

With `KOKORO_CANDLE_WEIGHTS`, adapted voices load tensors onto the candle model's
device, swap AdaIN weights for synthesis, then restore the base. Otherwise the
engine builds an ORT session per adapted voice; `KOKORO_ADAPTED_SESSIONS` bounds
that cache (default 2). Adapter fitting also requires
`NV_QWEN_VOICE_ENCODER_DIR` and `NV_WESPEAKER_CANDLE_DIR`.

## Fleet and operation

One always-on host is the engine. A storage host exports the voices tree and
the podcast tree; recordings may also link to meetings under a recordings tree.
Mount these on the engine at the same paths the storage host uses. A secondary
host retains its store mount at `/var/lib/speaches/voices-store`.

The engine's voices unit sets `NV_VOICES_DATA_DIR`, candle asset paths and
`NV_VOICES_CHUNK_MINUTES` (25). Its nightly timer posts the workspace run every
morning at 07:00. `NV_VOICES_STT_URL` and `NV_VOICES_DIAR_URL` override the
loopback endpoints. The service needs `ffmpeg` and `ffprobe` on PATH.

The page at `/voice-lab` provides recordings, speaker naming, fitting and voice
playback through same-origin API calls.

## Validation

Run the suite covering workspace and voice API contracts through the wrapper:

```sh
NVK_PKG=speaches-plus NVK_FEATURES= NVK_SHELL=.#no-models rust/scripts/nvk.sh test --lib voices --no-fail-fast
```

It covers content addressing, stale policies, identify, clips, sentence
selection, chunk timestamps, scan failure tolerance, fit form deserialization,
event delivery and publication. The adapter device-loading test has an explicit
CUDA variant; CPU tests alone do not validate GPU serving.

Synthetic tests do not establish end-to-end real-audio quality. A release gate
must additionally exercise a real recording through the engine, fit a voice,
and synthesize it without restarting. Tests that skip for missing assets are
not evidence that this gate passed. Performance claims require a run in the
measurement store under [the performance rules](the basis-tuple quoting rule).

## Realtime output voice and language

`session.update` applies `voice` and the top-level `language` to subsequent
realtime responses. The synthesis pipeline reads the current session settings,
including fitted Kokoro voice names, instead of the connection's original query.
A response keeps its initial voice and language across its sentence chunks.

Set `language: "es-AR"` for the Latin American Spanish phonemizer (`es-419`).
`session.updated` preserves the requested `es-AR` locale. This controls pronunciation;
it does not guarantee an Argentine accent from a stock voice. The accepted locales
are those validated by `espeak_voice_for` in `rust/src/tts/http.rs`.
For Spanish transcription, separately set
`input_audio_transcription: {"language": "es"}`; Whisper language codes are not
output locales. Omitted settings retain their current values. `language: null`
restores the existing realtime default, `en-us`; `voice: null` restores the default
voice. Invalid output locales reject the entire update, including any voice change.

The suite covering applied realtime voice selection, acknowledgement, locale mapping,
and rejected-update atomicity is
`realtime_synthesis_uses_updated_voice_and_output_locale` in
`rust/src/realtime/session.rs`. Parser coverage is in
`rust/src/realtime/session_update.rs`. These tests do not establish fitted voice
quality or dialect accuracy.
