# Digitizing handwritten notebooks

`rust/src/bin/notebook.rs` turns scanned notebook pages into per-page markdown and
extracted drawings, trading speed for quality on handwriting mixed with drawings —
the opposite trade-off from `/v1/ocr`. Throughput and quality figures belong in
`perf/runs.jsonl` with their basis tuple, never here. One `dots.ocr` `LayoutAll`
pass per page yields boxes, categories (`Title`, `Section-header`, `Text`,
`List-item`, `Formula`, `Table`, `Picture`, …), reading order and per-region text in
one decode — no separate detector. `Picture` boxes rescale to source coordinates and
crop the **full-resolution** image, so a drawing is usable, not a 700px thumbnail.
Output: `NNN-<stem>.md` per page plus `notebook.md`,
`images/NNN-<stem>-figNN.png`, `report.json`, `review.md`.

```sh
NVK_LANE=notebooks NVK_PKG=speaches-plus rust/scripts/nvk.sh build --release --bin notebook
. ~/.cache/cargo-tmp/devenv-__cuda.sh
LD_LIBRARY_PATH=/run/opengl-driver/lib \
  ~/.cache/cargo-tmp/tgt-notebooks/release/notebook --out ~/notebook-1994 scans/*.jpg
notebook --out ~/out --pdf-dpi 400 --cross-check scan.pdf
```

`LD_LIBRARY_PATH` covers the CUDA stub; PDF input rasterizes through `pdftoppm` when
it is on PATH. Flags: `--out`, `--reader`, `--cross-check`, `--figure-pad`,
`--figure-min-frac`, `--crop-pad`, `--crop-min-side`, `--max-new-tokens`,
`--review-threshold`, `--pdf-dpi`, `--dots-dir`, `--dsocr-dir`, `--keep-tables`,
`--quiet`; `--help` prints the list.

## Readers -- `--reader` / `NV_NOTEBOOK_READER`

| `--reader` | what it does | when |
|---|---|---|
| `layout` (default) | uses the text `dots.ocr` already emitted in the layout pass | default; one decode per page |
| `dots-crop` | re-reads every text region as its own `dots.ocr` `PlainOcr` crop, upscaled so the short side is >= `--crop-min-side` | faint or very small script that the page-level pixel budget starves |
| `dsocr-crop` | same, through DeepSeek-OCR-2 free-OCR | second opinion from a different model family |

A reader is one `RegionReader` impl plus one `ReaderKind` arm. `dots.ocr` carries the
pipeline as the only local model emitting boxes, categories, reading order *and* text
in one pass; DeepSeek-OCR-2 is text-only, the Gemma-4 VLMs have no layout boxes, and
`tesseract` is print-trained with no region typing. `layout` is the default on the only
in-repo corpus — five 1700x2200 font-rendered synthetic pages (three typefaces, ruled
paper, skew/shadow/speckle) — where it scores a low corpus CER and finds 5/5
ground-truth `Picture` regions while `dots-crop` ties on four and is catastrophic on
the fifth, a ~21-character title crop handed to `PlainOcr` making the model write a
2.5 kB essay; hence the **crop-overrun guard**: a crop read longer than
`3 x layout_chars + 40` is discarded, the layout text kept, the region flagged
`crop-overrun:N`. `dsocr-crop` agrees exactly with `layout` on the two pages smoked,
cursive included: cross-family agreement, not a better transcription. **Treat that CER
as plumbing evidence, not a quality estimate** — a rendered font has no touching
strokes, no bleed-through and self-generated ground truth, and that page crosses no
confidence threshold either, so the report below is **not calibrated**.

## Confidence report

No per-token logprobs exist, so `score` in `report.json` is a weighted penalty over observable failure modes, **not a calibrated probability**.

| signal | meaning |
|---|---|
| `layout-loop` | the loop detector fired mid-page -- output is likely truncated garbage |
| `layout-truncated` | the layout JSON did not parse to completion |
| `token-cap` | generation hit `--max-new-tokens` |
| `no-elements` / `nothing-extracted` | the layout pass returned nothing usable |
| `bad-bbox:N` | N boxes were degenerate or entirely off-page |
| `unknown-category:N` | N categories outside the dots.ocr label set |
| `empty-text-region:N` | N non-figure regions produced no text |
| `crop-loop:N` | N crop reads looped |
| `crop-overrun:N` | N crop reads produced far more text than the region held; the layout-pass text was kept |
| `two-read-disagreement:M` | `--cross-check` only: mean agreement below 0.60 |

`--cross-check` is the only signal with real discriminative power: it reads every text
region twice — page-level layout pass and independent crop read — reporting normalized
edit-distance agreement per region, at roughly double the runtime. Any page with a
non-empty flag list, or a score below `--review-threshold` (default 0.75), lands in
`review.md` with per-region notes.

## What still needs real pages

1. **The reader choice is unvalidated on real handwriting.** Run all three arms
   over ~20 real pages and pick from the measured numbers.
2. **Whether a handwriting-native model is needed at all.** If real-page
   `dots.ocr` CER is bad, add Qwen3-VL as a fourth `RegionReader`.
3. **Whether `Picture` detection survives real drawings.** Overlapping sketches and
   full-page drawings may type as `Text`; retune `--figure-min-frac`/`--figure-pad`.
4. **Whether the confidence flags correlate with real errors.** Only `--cross-check`
   sees a confidently-wrong read; its 0.60 threshold is uncalibrated.
5. **Scan geometry.** Page curl, gutter shadow, perspective; `dots.ocr` tolerates some (Real5 skew, [`06.3-ocr.md`](06.3-ocr.md)), this pipeline adds no dewarping.

A useful first batch is **20-30 pages spanning the range**: neatest and worst, heavy
crossings-out, a drawing overlapping text, pencil, photographed. Promote the synthetic
generator to the `070-ocr-*` / `071-ocr-layout-*` bands under `conformance/fixtures/`
at the real bake-off.
