# speaches-plus: session eviction and capture exclusion in Rocq

The model answers two questions. Can the cold tier free a qwen4_exp session that something
on the CPU side still uses? It covers the engine permit and idle-age selection in `evict` and
the held slots (two base sessions, the kept adapter session) `release_sessions_to_disk` may
drop. Can graph captures and device-synchronizing calls deadlock each other? It covers the
ownership protocol in `capture_exclusion.rs`, for two threads, with each blocking call
modeled as a commitment: a thread inside one does nothing else. `proof.json` lists the
scope, the claims in words, the findings and what is not covered. `PLAN.md` is the
generated plan.

| Module | Holds |
|---|---|
| `Exclusion.v` | the capture/exclusion protocol; a policy picks the shipped design (one owner) or the old one (count, then a separate lock; claim the excluder, then drain) |
| `Evict.v` | slot selection: permit, idle limit, pressure, the adapter slot; parametric in the eviction policy |
| `Shipped.v` | generated by `bind.py` from the Rust; it refuses any shape outside its grammar |
| `Findings.v` | the claims for the shipped code, and the old designs' counterexamples |

Run the gate where the speaches-plus tests run:

```sh
python3 proofgate.py -C proof check
```

On a red gate, `drift` names the code that moved. Review the model against it, then
`record --because "<what changed and what you compared>"`.
