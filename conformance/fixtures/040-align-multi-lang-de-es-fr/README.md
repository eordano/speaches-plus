# 040-align-multi-lang-de-es-fr

Smoke test that `/v1/audio/transcriptions` accepts non-English language
hints (`de`, `es`, `fr`) and returns SRT.

## Input artifacts

`audio_de.wav`, `audio_es.wav`, `audio_fr.wav` — each 1.5 s, 16 kHz mono,
single-tone synthesized sine. Regenerated by `./generate_audio.py`.

## What it asserts

Three POSTs (one per language). Each:

- Returns 200 with `Content-Type: text/plain`.
- Body is parseable SRT (`segment_numbers_monotonic`, valid `HH:MM:SS,mmm`
  timestamps).
- Segment count is in `[0, 4]` (silence-friendly so the placeholder
  audio doesn't force a particular segmentation).

## Why placeholder?

We are checking that the route does not reject the `language` hint when
it's not English — i.e. that the implementation doesn't accidentally
hard-code English-only handling. Per-language transcription correctness
moves into separate `040-align-<lang>-*` fixtures once real STT lands.
