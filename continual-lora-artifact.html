A Self-Improving Serving Harness

The Prime Agent recipe — capture trajectories in production, judge them, train a LoRA, hot-load it back into the live server — instrumented end-to-end on our own Rust inference stack, trained directly against the quantized NVFP4 base, and formally audited with machine-checked Rocq proofs that found real bugs.

01The loop

Every stage is a real, shipped component with its own endpoint or artifact — not a script taped to the side. The server improves itself while serving; a human steers with a thumb.

The 84-GiB-free OOM, killed at the root

Training initially OOM'd with 84 GiB free. Root cause: candle's generic matmul retained fp32 transposed weight copies (~16.8 GiB per allocator bucket) plus phantom rhs_grad GEMMs for frozen weights — full gradients computed and discarded. The fix is Bf16LinearOp, a custom autograd op whose backward is exactly dx = dy·W with the weight held inside the op: candle never sees it as a graph argument, so there is nothing to build a phantom gradient for and nothing to transpose. The previously-OOMing shape now trains non-checkpointed. This matches — and beats — the bitsandbytes/torchao shape (they dequantize twice per module per step; we dequantize once, backward only, since our forward is quantized-native).

Training data path is real

The fine-tuning endpoint tokenizes through the base model's actual tokenizer (byte fallback survives only for tokenizer-less test fixtures and refuses real bases), masks prompt tokens out of the loss, caps sequences at 512, drops degenerate rows, and hard-errors on out-of-vocab ids. grad_layers and LoRA+ b_lr_ratio are request hyperparameters with family-aware validation.

One wire vocabulary, four languages

The feedback/trajectory types are defined once in Rust and generated via typeshare into TypeScript (garden), Kotlin (Rock app), and Go, with drift gates in CI — a thumbs-down tapped on a phone and a label posted by a script land as the same record.

05The human in the loop

The operator workflow is three gestures, not a pipeline to babysit.

GestureWhat happens
Thumb a response 👍/👎 pills on every portal.decent.* attempt and every Rock (android) message. The tap posts to /v1/trajectory/label, joining by the x-trajectory-tag the client stamped at request time — labels survive LiteLLM rewriting response ids.
Run a round consolidate_trajectories.py --model <teacher> over the week's logs: applies labels, judge-filters, distills, submits the fine-tune, and only ships if the held-out gate passes. A losing adapter is a refusal (exit 2), not a deploy.
Forget a round /v1/unload_lora_adapter — the base is untouched underneath; the rolling adapter is the only mutable state, and it is versioned.

What is now theorem, not belief

The serving GEMM configs (bf16_matmul_row_major_bt_offs and the plain variant) provably realize y = x·Wᵀ under column-major cuBLASLt semantics, transcribed field-for-field from the MatmulConfig literals. The Bf16LinearOp backward dx = dy·W is proved to be the adjoint of that forward, the true derivative of any loss through it, and unique — the transposed-copy orientation is refuted on a concrete instance. NVFP4 nibble packing, the CUTLASS scale swizzle (including tail tiles), and per-block scale indexing round-trip and are injective; the training-side host dequant (HostDequantWeights) equals the serving reference dequant on every index. LoRA slice/cumsum machinery, the gated-q value/gate lane split, and the scaling-fold are proved against the shipped WGSL and Rust. Floating-point rounding is an explicit non-claim (exact ℝ/ℚ model); every exclusion is recorded in 08.3-rocq-proof-notes.md.

Confirmed bug · train/serve divergence

Nvfp4DequantSource::get uses weight_scale_2 raw

Every serving consumer guards this scalar (safe_recip / finiteness checks); the training-side reader in train_runner.rs does not. Machine-checked divergence witness (by vm_compute): at weight_scale_2 = 0, training dequantizes the entire base weight matrix to zeros while the CUDA serving path for the same checkpoint falls back to scale 1.0 — train and serve compute different functions. NaN/inf is the same class. The one-line guard is specified and its corrected form is proved index-identical to serving everywhere (train_runner_guarded_agrees_serve). Fix queued for the merge.

Minor · same guard class

dequantize_nvfp4_to_bf16 missing finiteness check

The small-matrix serving fallback guards the global scale against 0.0 but not NaN/inf, unlike its sibling safe_recip paths — a non-finite global scale silently diverges small matrices from large ones on the same checkpoint.

Downgraded by adversarial verify · defense-in-depth

Under-width LoRA B on a gated projection scatters onto gate lanes

Proved (zero-axiom): LoraSlotStack::set_lora's corner-padding would silently modulate the sigmoid gates of low heads and skip high heads entirely for an adapter sized for the un-gated layout. The verify pass then showed the shipped wgpu loader already rejects this exact shape (…MUST_COVER_VALUE_AND_GATE_LANES guard) — so this is a proved hazard behind one guard at one loader, not a live corruption. Residual action: push the reject down into set_lora itself.

07What's next, in order

Queued (evidence-ranked)

  1. Merge the Rocq workflow + land the weight_scale_2 guard its proof already validated.
  2. Chunked-CE port to the Qwen arm — CE peak ~9–10 GB → <1 GB at T=512; kills a phantom 1.3-TFLOP GEMM per example. Prerequisite for full-depth.
  3. Example batching B≥8 — the big full-depth throughput lever (~85 → ~600 tok/s class); fits because the quantized-resident base frees ~40 GB.
  4. W4A4 numerics A/B — our NVFP4 training forward quantizes activations; no upstream precedent. Mandatory before the loop consumes adapters trained through it.
  5. Device NVFP4 dequant kernel — unblocks QuantLinearOp (single-dequant backward fully on-device).
  6. Deploy (user-gated): internal compute hosts, Rock APK — then the first real judged consolidation round on live traffic.

Honest caveats

  • The demo adapter is degenerate — six rows overfit, as expected. It proves plumbing, not quality.
  • W4A4 training forward is unprecedented — every upstream QLoRA keeps activations ≥16-bit. The A/B gate stands between it and the loop.
  • Rocq scope is exact arithmetic — bf16/f32 rounding and split-K reduction order are declared non-claims, not proven.
  • Nothing is deployed yet — every number here is from the benchmark host; the fleet rollout is a separate, user-gated step.
  • Adapter-shipping policy: flips require landed perplexity rows — an adapter with no eval row does not ship.
